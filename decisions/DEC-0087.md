# DEC-0087 — Direct per-phase model slug override and role-based catalog presets (US-0102)

- **Date**: 2026-06-25
- **Status**: locked
- **Story**: US-0102
- **Composes on**: DEC-0086 (US-0101 tier baseline — **do not amend**), DEC-0062 (TOKEN_PROFILE orthogonality), DEC-0051 (phase→role matrix), US-0003 (subagent definitions), US-0080, US-0092/DEC-0078
- **Amends**: none (overlay extension)

## §1 — Problem and scope

Operators who already use **DEC-0086** three-tier selection need two optional overlays without migrating away from tiers:

1. **Direct per-phase vendor slug** (`MODEL_<PHASE>=<slug>`) bypassing tier indirection.
2. **Role-based catalog presets** (`MODEL_RESOLVE=role_catalog`) mapping lifecycle phases to curated role slugs in a local catalog.

The tier system remains the default/fallback layer. **US-0101** / **DEC-0086** locks are unchanged.

## §2 — Precedence (normative)

Single deterministic chain for each canonical `phase_id`:

| Step | Source | Outcome |
|------|--------|---------|
| **1** | `MODEL_<PHASE>` scratchpad key | Non-empty slug → return slug (see §4 validation) or **`MODEL_OVERRIDE_SLUG_UNKNOWN`** |
| **2** | `MODEL_TIER_<PHASE>` | Existing **DEC-0086** tier→alias/catalog chain |
| **3** | `MODEL_RESOLVE=role_catalog` only | Phase→logical role (**DEC-0051** + policy keys) → catalog `roles[<key>]` slug; miss → **`MODEL_ROLE_SLUG_UNKNOWN`** → fall through |
| **4** | `MODEL_TIER_DEFAULT` | **DEC-0086** tier chain |
| **5** | Cursor stable alias | **DEC-0086** §2 built-in mapping |

**Rejected alternative**: separate `model_overrides_lib.py` module — **rejected**; extend `scripts/model_tier_lib.py` in place to preserve v1 call sites and single validator surface (**R-simple**).

**Rejected alternative**: role presets replace tiers — **rejected**; tiers stay default; role catalog is opt-in via `MODEL_RESOLVE`.

## §3 — Scratchpad keys

| Key | Default | Role |
|-----|---------|------|
| **`MODEL_<PHASE>`** | *(absent)* | Direct vendor slug override; `<PHASE>` = same canonical ids as **DEC-0086** (includes **`ask`**) |
| **`MODEL_RESOLVE`** | **`alias_only`** | Extended enum: **`alias_only`** \| **`local_catalog`** \| **`role_catalog`** |

All **DEC-0086** keys (`MODEL_TIER_*`, `MODEL_CATALOG`, `MODEL_FALLBACK`, `MODEL_PROVIDER_MODE`) unchanged.

**Template policy**: `template/.cursor/scratchpad.md` documents `MODEL_<PHASE>` keys with placeholder comments only — **no vendor slugs**. Operator slugs live in `.cursor/scratchpad.local.md` (gitignored).

## §4 — Direct slug validation

| `MODEL_RESOLVE` | Direct slug (`MODEL_<PHASE>`) behavior |
|-----------------|----------------------------------------|
| **`alias_only`** | Accept any non-empty opaque slug string; return as resolved slug (operator responsibility) |
| **`local_catalog`** \| **`role_catalog`** | Slug must appear as a value in catalog `tiers` **or** `roles` (when present); else **`MODEL_OVERRIDE_SLUG_UNKNOWN`** |

Empty slug or unknown phase id → fail-closed with remediation text.

## §5 — Catalog schema v2

### Backward compatibility

- **`schema_version: 1`** catalogs (tiers only) — **unchanged**; validator accepts as today.
- **`schema_version: 2`** — adds optional **`roles`** object; **`tiers`** still required with all three tier keys.

### Schema v2 shape

```json
{
  "schema_version": 2,
  "tiers": {
    "cheap": "<slug>",
    "balanced": "<slug>",
    "strong": "<slug>"
  },
  "roles": {
    "po": "<slug>",
    "sa": "<slug>",
    "dev": "<slug>",
    "dev_difficult": "<slug>",
    "qa": "<slug>",
    "security": "<slug>",
    "release": "<slug>"
  },
  "notes": "optional"
}
```

- Role key recommendations follow `ai_modell_auslegung_cursor_highend.md` (non-normative operator guide).
- When `roles` present, every listed key must have a non-empty string slug.
- Malformed v2 → **`MODEL_CATALOG_SCHEMA_V2_INVALID`** (distinct from v1 **`MODEL_CATALOG_INVALID`**).

**Example artifacts** (placeholder slugs only):

- `.cursor/model-catalog.local.example.role-based-balanced.json`
- `.cursor/model-catalog.local.example.role-based-highend.json`

## §6 — Role catalog resolver

Active only when **`MODEL_RESOLVE=role_catalog`**.

### Phase → logical role (DEC-0051)

Use **DEC-0051** canonical matrix + policy keys:

- `AUTO_ROLE_RESEARCH` → `po` \| `tech-lead` (default `tech-lead`)
- `AUTO_ROLE_PLAN_VERIFY` → `qa` \| `tech-lead` (default `qa`)
- `AUTO_ROLE_REFRESH_CONTEXT` → `curator` \| `po` (default `curator`)

### Logical role → catalog role key

| Logical role | Catalog `roles` key |
|--------------|---------------------|
| `po` | `po` |
| `tech-lead` | `sa` |
| `dev` | `dev` |
| `qa` | `qa` |
| `security` | `security` |
| `release` | `release` |
| `curator` | `dev` |

Phases without a fixed **DEC-0051** row but in the **DEC-0086** cheap matrix (`ask`, `memory-audit`, `status-reconcile`, `pause`) map logical role **`dev`** (cheap worker preset per operator guide).

**`execute`** / **`quick`** map logical role **`dev`**. Operators needing **`dev_difficult`** use direct override `MODEL_EXECUTE=<slug>` or tier `strong` + catalog tier slug.

Lookup miss → **`MODEL_ROLE_SLUG_UNKNOWN`** → fall through to step 4 (not hard stop unless direct slug path).

## §7 — `/ask` phase

No change to **DEC-0086** default matrix (`ask` → **`cheap`**). **`MODEL_ASK=<slug>`** participates in step 1 precedence like any other phase.

## §8 — Fail-closed reason codes (new)

| Code | Trigger |
|------|---------|
| **`MODEL_OVERRIDE_SLUG_UNKNOWN`** | Direct slug fails validation (§4) |
| **`MODEL_ROLE_SLUG_UNKNOWN`** | Role catalog lookup miss (emit reason; fall through unless policy changes) |
| **`MODEL_CATALOG_SCHEMA_V2_INVALID`** | v2 schema validation failure |

Existing **DEC-0086** codes unchanged. **`MODEL_TIER_*`** / **`MODEL_CATALOG_*`** validators extended to accept v1 and v2 catalogs.

Eight **`test_us0102_*`** markers (AC-9). Parity scope **`--scope=model-tier-overrides`** extends **`--scope=model-tier`** family (**`MODEL_TIER_OVERRIDES_PAIRS`**).

## §10 — Risks

| Risk | Mitigation |
|------|------------|
| **R1** Precedence confusion (override vs tier vs role) | Single documented chain in architecture + runbook; contract test `test_us0102_precedence_chain` |
| **R2** Vendor slugs in committed templates | Grep gate `test_us0102_no_vendor_slugs_in_template`; placeholders only in examples |
| **R3** v1 operator catalog break on v2 validator | v1 path unchanged; v2 opt-in via `schema_version` |
| **R4** Role mapping drift vs **DEC-0051** | Import phase→role from shared constants or document locked table; regression test |
| **R5** `MODEL_RESOLVE=role_catalog` without `roles` section | **`MODEL_ROLE_SLUG_UNKNOWN`** + tier/alias fall through; document in runbook |
