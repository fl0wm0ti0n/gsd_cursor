# DEC-0052: Scratchpad-controlled `/auto` phase plan resolution with non-skippable gates

- Date: 2026-03-21
- Status: Accepted
- Story: `US-0070`
- Research refs: `R-0049`
- Related: `DEC-0051` (phase→role contract; no role substitution via skips),
  `DEC-0038` (strict runtime proof), `DEC-0029` (isolation evidence),
  `DEC-0040` (artifact ordering for breadcrumbs)

## Context

Operators need a deterministic way to narrow which canonical `/auto` phases run
per invocation while preserving fail-closed safety, evidence-chain integrity,
and compatibility with `US-0069` role preflight. Ad-hoc skipping risks silent
gate bypass, ambiguous `start-from` behavior, and stale continuation that
reintroduces omitted phases without recording why.

## Decision

Adopt a **single active phase-selection policy mode** per run, resolved from
merged scratchpad (active + `.cursor/scratchpad.local.md`; template parity on
install), materialized once into a **resolved ordered phase plan** (canonical
lifecycle order subset) **before** the first phase spawn, with mandatory
operator-visible breadcrumbs and deterministic fail-closed diagnostics.

### 1. Policy mode selector (exactly one active)

At most one of the following selectors may be materially active; if two or more
non-default selectors conflict after merge, fail closed with
`PHASE_POLICY_CONFLICT` (or equivalent) and **no** plan materialization:

- `AUTO_PHASE_PLAN=full` — default; full canonical lifecycle (including
  documented optional inserts such as `/security-review` when enabled).
- `AUTO_PHASE_EXCLUDE=<csv>` — start from full plan, remove listed phase IDs
  (validate tokens).
- `AUTO_PHASE_INCLUDE=<csv>` — listed IDs only, **re-sorted** into canonical
  order; unknown IDs and empty results fail closed.
- `AUTO_PHASE_PROFILE=<name>` — expand named profile from a documented registry;
  unknown profile fails closed.

Unset `AUTO_PHASE_PLAN` implies `full` when no other selector is set.

### 2. Plan materialization pipeline (evaluation order)

1. Parse merged scratchpad inputs.
2. Detect active policy mode; on conflict → stop (§1).
3. Expand mode to a **candidate** ordered phase list per `R-0049`.
4. Apply **non-skippable reinstatement** for the **default profile**: reinsert
   phases in the **default non-skippable set** that were removed, recording
   `non_skippable_gate` (and related codes) in breadcrumbs. **Named high-risk
   profiles** may define alternate reinstatement/exception rules only when they
   include explicit operator acknowledgment fields and versioned profile spec
   references (illustrative sketch: `profile_high_risk_dev_fast` in `R-0049`).
5. Intersect with `start-from=<phase>`: retain phases from the requested anchor
   forward that remain in the plan; **empty intersection** fails closed with
   diagnostics listing resolved plan vs requested start.
6. Persist **selected phases**, **skipped phases + reasons**, and policy
   metadata to continuation breadcrumbs (`docs/engineering/state.md` and related
   surfaces per implementation) **before** first spawn.

### 3. Default non-skippable phase set (baseline)

Unless a named high-risk profile explicitly documents a narrower exception with
acknowledgment:

- **Safety gates**: `qa`, `verify-work`, `release` — always reinstate in default
  profile (aligns with backlog AC-4 and existing sync/release contracts).
- **Evidence-chain integrity**: any phase whose omission would leave a later
  planned phase without valid prior isolation + strict-proof checkpoints for the
  same story/run must be treated as non-skippable in default profile (typically
  the upstream chain required by active implementation-loop and gate semantics).

Architecture may tighten the **minimal mandatory subgraph** in implementation,
but **must not** silently drop required isolation or strict-proof tuples.

### 4. Compatibility with `US-0069` (DEC-0051)

- Role resolution runs **only for phases present** in the resolved plan;
  skipping `research` does **not** reassign `architecture` to `po`.
- Preflight capability gate applies before each spawn for **planned** phases
  only; skipped phases produce **no** spawn and **no** alternate-role fallback
  for a different phase.
- Resume, backlog-drain, bulk execute, and team-mode paths must reload
  phase-policy inputs and **recompute** the plan; stale plans cannot revive
  skipped phases silently.
- **US-0120 additive**: `closure | qe` (with `AUTO_ROLE_CLOSURE` scratchpad override
  to `curator` allowed) is a valid phase→role mapping. §3 preflight capability gate
  for closure: `capability: role:qe or override`; fail-closed: `PHASE_CAPABILITY_MISSING`.

### 5. Failure taxonomy (operator-actionable)

Reserve deterministic codes including (non-exhaustive; align with backlog):

- Unknown phase token / invalid identifier
- Empty plan after include
- `PHASE_POLICY_CONFLICT`
- Invalid or unknown profile
- `start-from` empty intersection vs resolved plan
- Reinstatement / non-skippable diagnostics

### 6. Documentation and parity

Active install and `template/` must document scratchpad keys, precedence,
non-skippable defaults, profile rules, `start-from` intersection, and reason
codes (`AC-8`, `AC-9` planning hooks).

## Consequences

- **Positive**: Predictable operator control, auditable skip reasons, preserved
  safety gates and role contract.
- **Negative**: More scratchpad surface area; profiles require careful
  governance to avoid silent bypass.
- **Neutral**: Implementation lives in `/auto` and tests (`US-0070` execute/QA
  tranche); this decision fixes the architecture contract only.

## Compliance

- Satisfies `US-0070` AC-1–AC-7 at architecture level; AC-8–AC-10 require
  implementation and regression artifacts.
