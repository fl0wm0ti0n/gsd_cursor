# DEC-0061: First-class bug issues (`BUG-xxxx`) with `OPEN`/`DONE` lifecycle (US-0079)

- Date: 2026-03-29
- Status: Accepted
- Story: `US-0079`
- Supersedes: none
- Extends: `US-0045` (canonical status — adds a **second status family** for bugs, parallel rules, no change to story authority for `US-xxxx`)

## Context

Defects were indistinguishable from feature stories at intake/backlog level. Research **`R-0056`** recommends a lightweight **`BUG-####`** identity, minimal reproducibility fields, explicit routing (no silent **`US-xxxx`** conversion), and traceability through sprint, QA, verify-work, and release artifacts without mandatory triage/SLA machinery.

## Decision

### 1. Identifier and allocator

- **Format**: `BUG-` + **four decimal digits** (`BUG-0001` …), zero-padded.
- **Assignment**: **next id = one greater than the highest existing `BUG-####` already present** in the canonical bug surface (same deterministic policy as **`US-xxxx`** per **`DEC-0034`** / backlog convention). No gaps repair requirement; duplicates are invalid.

### 2. Canonical storage (default)

- **Primary home**: markdown section **`## Bug issues (canonical)`** in **`docs/product/backlog.md`**, **append-new** for new bugs, **stable sort by id** within the section.
- **Optional split** to **`docs/product/bugs.md`** only when **(a)** an explicit future amendment or operator policy documents the split and **(b)** **`US-0045`** reconciliation text and **`/ask`** retrieval lists are updated to name **both** surfaces. Until then, **single-file** is normative.

### 3. Status literals

- **Only** **`OPEN`** and **`DONE`** (same header discipline as stories). Optional free-text **severity/narrative** may appear as non-canonical bullets; no required triage states.

### 4. Minimum bug schema (per issue block)

Each **`BUG-xxxx`** entry **MUST** include labeled substructure (bullets or fixed labels — execute chooses rendering; validators key off labels):

| Field | Requirement |
|-------|----------------|
| `environment` | Non-empty context (product area, OS/tooling, branch/commit when known) |
| `steps_to_reproduce` | Ordered, deterministic steps |
| `expected` | Expected behavior |
| `actual` | Observed behavior |
| `evidence_refs` | Non-empty list of paths, logs, screenshot refs, or opaque evidence ids |

**Optional** link fields (for anti-duplication and planning): `related_us`, `blocks_us`, `duplicate_of`, `supersedes` — each, when present, lists **ids only** with framework id shapes.

### 5. Intake routing (no silent US conversion)

- **Canonical signal**: merged scratchpad **`INTAKE_WORK_ITEM_KIND`** ∈ **`story`** (default) | **`bug`** per **`DEC-0055`** merge order.
- **Command signal**: documented **`/intake bug`** (or equivalent explicit argv) **when** intake implementation adds it; either scratchpad **or** command bug mode MUST be true to allocate **`BUG-xxxx`**.
- **Fail closed**: if operator describes a **defect** but **neither** signal is set, intake **MUST NOT** persist a new **`US-xxxx`** for that defect class — emit deterministic **`INTAKE_BUG_ROUTING_REQUIRED`** (or reuse/amend **`INTAKE_WORK_ITEM_KIND_MISMATCH`** consistently in runbook) and **abort backlog mutation**.
- **Conflict**: if signals contradict (e.g. bug kind + feature-only pack without override), **fail closed** with the same family of codes — no write.

### 6. `US-0045` reconciliation extension

- **`docs/product/backlog.md`** remains **authoritative** for **both** `Status: OPEN|DONE` **story** lines and **`BUG-xxxx`** status lines in the bug section.
- **`docs/product/acceptance.md`** gains a dedicated portfolio subsection **`## Bug acceptance (canonical)`** (see §8): checkbox rows **`BUG-xxxx`**, derived/reconciled from backlog bug status — **never** the inverse.
- Drift scripts / guards **MUST** treat **`BUG-`** as a **first-class** id family alongside **`US-`** (detection + reason codes), without weakening existing US-only rules.

### 7. Sprint, QA, verify-work, release

- **`sprints/S*/tasks.md`**, **`summary.md`**, **`qa-findings.md`**, **`uat.*`**, **`release-findings.md`** **MAY** reference **`BUG-xxxx`** in titles or traceability rows using the same “id + evidence pointer” style as **`US-0042`** post-QA issues.
- Bugs **do not** require conversion to **`US-xxxx`** for linkage; optional **`related_us`** ties cross-family work.

### 8. Acceptance.md layout

- New top-level section **`## Bug acceptance (canonical)`** after **`## Remaining Items`** (or as documented in **`architecture.md`**): rows **`- [ ]` / `- [x]`** per **`BUG-xxxx`**, **sorted by id**, mirroring backlog bug **`DONE`**/**`OPEN`** checks. Empty stub allowed until the first bug exists.

### 9. `/ask` and context packs

- Narrow-read allowlists / regex id families **MUST** include **`BUG-####`** alongside **`US-xxxx`** where backlog-derived ids are surfaced; **no** semantic merge of families in retrieval output.

### 10. Validators and tests

- **Execute** provides deterministic validator(s) (or extends an existing doc validator) for minimum field presence and status literals on the canonical bug surface; reason codes are **stable strings** (prefix suggestion **`BUG_VALIDATION_*`** — final literals in runbook + **`R-0056`** Tier A vectors).
- **Regression tiers** follow **`R-0056`** Tier A–D mapping to **US-0079 AC-1..AC-10**.

### 11. Migration / grandfathering

- Historical defects recorded only as **`US-xxxx`** remain **valid legacy**; **no** mass porting required. Operators **MAY** open a new **`BUG-xxxx`** and **`duplicate_of`/`supersedes`** link to old prose. New defects **SHOULD** use **`BUG-xxxx`** once **`US-0079`** is delivered.

### 12. AC-10 (backlog) — boundaries, migration, open/closed-only policy (**this decision**)

This **`DEC-0061`** is the **authoritative** record for **US-0079 AC-10**:

- **Bug vs story**: defects use **`BUG-xxxx`** + §5 routing; features use **`US-xxxx`**; cross-links via **`related_us`** / **`blocks_us`**.
- **Migration**: §11 grandfather rule; optional manual port with duplicate hints.
- **Lifecycle**: §3 — **`OPEN`/`DONE` only**; no SLA/triage/severity state machine.

### 13. Phase boundary operator visibility (**US-0070** / **AC-10** alignment)

When **`docs/engineering/state.md`** records **phase boundary status** for a run that includes **bug-tracked** work, writers **SHOULD** add optional tuple **`bug_ids=<csv>`** (may be empty) **when** the completed phase created/updated/closed **`BUG-xxxx`** records, so operator snapshots remain **inspectable** without parsing full backlog. Omit the tuple when no bug mutations occurred (backward compatible).

## Alternatives considered

1. **US-only defects** — rejected (weak traceability; discovery).
2. **Heavy triage / SLA states** — rejected (out of scope).
3. **External issue tracker as canonical** — rejected (**US-0045** backlog authority).

## Consequences

- Execute implements schema, routing, validators, command/runbook/README + **`template/`** parity (**US-0079 AC-9**).
- **`US-0045`** tooling extended for bug family; acceptance subsection populated/maintained.
- Sprint-planning may map **AC-1..AC-10** to tasks referencing **`DEC-0061`** and **`architecture.md`** **`# US-0079`**.
