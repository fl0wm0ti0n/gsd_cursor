# DEC-0028: Optional Component-Scoped Execution Mode

- Date: 2026-03-01
- Status: Accepted
- Related story: US-0035
- Research refs: R-0017

## Context

Teams need to focus workflow execution on selected components without risking
unintended changes in non-target components. The mode must remain optional to
avoid overhead in simpler repos.

## Decision

1. Add optional controls in `.cursor/scratchpad.md`:
   - `COMPONENT_SCOPE_MODE=0|1` (default `0`)
   - `TARGET_COMPONENTS=` (comma-separated IDs)
2. Define scope declaration/report artifacts:
   - `docs/engineering/component-scope.md`
   - `docs/engineering/component-scope-report.md`
3. Enabled-mode behavior:
   - intake/architecture declare in-scope and out-of-scope components
   - sprint planning includes scoped task metadata
   - execute enforces scope-first behavior
   - QA verifies unaffected-component checks
4. If unapproved out-of-scope impact remains open, release stops at decision
   gate with reason code `COMPONENT_SCOPE_VIOLATION_UNAPPROVED`.

## Consequences

- Scoped work becomes explicit and auditable.
- Default workflows remain unchanged when mode is disabled.
- Release safety improves for concurrent multi-component work.
