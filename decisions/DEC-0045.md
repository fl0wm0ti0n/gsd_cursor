# DEC-0045: Installer-owned `its_magic/` metadata boundary

- Date: 2026-03-15
- Status: Accepted
- Story: `US-0062`

## Context

Installer-owned framework metadata was previously mixed at repository root (for
example `.its-magic-version`) and could be confused with project-owned content.
The workflow already had ownership manifests and clean/upgrade policies, but the
metadata placement contract was not explicit enough for operator clarity.

## Decision

Adopt a canonical installer-owned metadata home at `its_magic/` and treat it as
framework scope in install/upgrade/clean flows.

Decision details:

1. Canonical installed version marker is `its_magic/.its-magic-version`.
2. Installer-owned metadata README surface is `its_magic/README.md`.
3. Ownership manifests include `its_magic` for install + clean operations.
4. Upgrade path is backward-compatible:
   - read legacy `.its-magic-version` when present,
   - write canonical `its_magic/.its-magic-version`,
   - remove legacy root version marker after successful write.
5. Clean-repo removes `its_magic/` and legacy root marker (if present), while
   preserving non-owned project content.

## Consequences

- Framework metadata is clearly separated from project artifacts.
- Existing repositories migrate without destructive project moves.
- Install/upgrade/clean documentation and regression tests must remain aligned to
  the `its_magic/` boundary contract.
