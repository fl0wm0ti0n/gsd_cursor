# DEC-0035: Tiered Token Profile and Compact Active-Context Policy

- Date: 2026-03-12
- Status: Accepted
- Related story: US-0053
- Research refs: R-0027, R-0028

## Context

High-traffic workflow artifacts have grown large, increasing repeated read cost
for routine phases and `/ask` interactions. Teams need lower default token usage
without weakening release reliability gates or losing auditability.

## Decision

1. Introduce `TOKEN_PROFILE=lean|balanced|full` as deterministic policy control
   for token-overhead intensity (default `balanced`).
2. Implement explicit profile-to-flag mapping and override precedence:
   - mandatory gate invariants remain non-overridable by profile,
   - documented manual flag overrides can supersede profile defaults.
3. Define compact active-context policy:
   - bounded active context in `docs/engineering/state.md`,
   - non-destructive historical archive packs with canonical references.
4. Define compact decisions index policy:
   - `docs/engineering/decisions.md` remains a bounded current index,
   - full decision detail remains in `decisions/DEC-xxxx.md`.
5. Adopt narrow-read `/ask` retrieval order:
   targeted sections first, bounded expansion when unresolved, explicit
   "not found in artifacts" when evidence is absent.

## Consequences

- Lower recurring token usage for routine interactions and phase runs.
- More predictable operator UX through profile-based controls.
- Additional implementation and regression work is required to lock precedence,
  compaction behavior, and guardrail invariants.
