# DEC-0075 — Downstream-safe template CI, kit-internal active CI, and drift guard (BUG-0009)

## Status

Accepted — 2026-06-06

## Context

**Composes on `US-0017`** (template drift guard — **negative-parity exceptions** for
intentional active ≠ template surfaces), **`US-0008`** (installer copy model),
**`US-0018`** (upgrade/clean re-copy heals stale downstream repos), and **`DEC-0056`**
/ **`US-0063`** (blank-until-bootstrap `TEST_COMMAND` policy).

Research anchor **`R-0075`** (`orchestrator_run_id=auto-20260606-02`) confirmed root
cause: `template/.github/workflows/ci.yml` is byte-identical to active
`.github/workflows/ci.yml` and copies five jobs — including kit-only self-packaging
jobs (`npm-test`, `brew-test`, `choco-test`) — into every downstream repo via the
**US-0008** installer manifest.

Operator scope (intake): fix **new installs/upgrades** only; existing broken repos heal
on next **US-0018** upgrade; also harden generic `checks` for fresh projects with no
real tests configured.

## Decision

Adopt the architecture below. Acceptance-criteria traceability is published in
§AC-Traceability at the end.

### 1. CI split shape — in-place job subtraction (Option A)

| Surface | Job inventory | Rationale |
|---------|---------------|-----------|
| `template/.github/workflows/ci.yml` | `checks`, `auto-fix` **only** | Downstream-safe generic CI |
| `.github/workflows/ci.yml` (active kit) | `checks`, `auto-fix`, `npm-test`, `brew-test`, `choco-test` | Kit self-distribution (**US-0007** / **US-0009**) |

**Normative constraints**:

- Keep filename **`ci.yml`** on both surfaces; **do not** rename to `ci-downstream.yml`.
- **Do not** change `docs/engineering/context/installer-owned-paths.manifest`
  `[install_include_paths]` / `[clean_paths]` entries for `.github/workflows`.
- **`template/.github/workflows/deploy.yml`** — **no change** (already downstream-safe).

**Alternatives rejected**:

- **Option B** — separate downstream filename: requires installer mapping complexity with
  no benefit over in-place subtraction (**R-0075** Q1).
- **Option C** — cross-repo reusable workflow (`uses:` kit repo): breaks offline install
  and pins consumers to kit network (**R-0075** Q1).

### 2. US-0017 negative-parity exception table

These paths are **intentionally not byte-identical** between active and `template/`.
`check_intake_template_parity.py` MUST **NOT** gain a `--scope=ci-downstream` byte-parity
mode — that would contradict this policy.

| Path | Parity rule | Guard |
|------|-------------|-------|
| `template/.github/workflows/ci.yml` | Downstream-safe; **must not** byte-match active | `check_downstream_ci_guard.py` forbidden scan + contract test SHA-256 differ |
| `.github/workflows/ci.yml` (active) | Kit-internal; retains packaging jobs | Guard positive five-job inventory |
| `template/docs/engineering/runbook.md` | `TEST_COMMAND:` header **empty on ship** (likely ≠ active harness line) | Documented exception; other runbook edits still mirror per row below |
| `scripts/check_downstream_ci_guard.py` | **Byte-identical** active + `template/` | **US-0017** script parity |
| `scripts/downstream_ci_guard_lib.py` | **Byte-identical** active + `template/` | **US-0017** script parity |

**Amendment policy**: new negative-parity rows require a subsequent DEC revision; sprint
work MUST NOT add further intentional mismatches without DEC.

### 3. Drift guard — script + lib split + harness §28B

**Entrypoint**: `scripts/check_downstream_ci_guard.py` (stdlib-only).

**Library**: `scripts/downstream_ci_guard_lib.py` — YAML job-key extraction (regex
`^\s{2}(\w[\w-]*):`, no PyYAML dep), forbidden-pattern scan, active positive inventory,
reason-code emitter (mirrors `readme_feature_coverage_lib` / `bug_issue_lib` split).

| Flag | Purpose |
|------|---------|
| `--repo PATH` | Target repo root (default: parent of `scripts/`) |
| `--self-test` | Stable marker subtests → `[DOWNSTREAM_CI_GUARD_SELF_TEST_OK]` |
| `--report` | Emit JSON inventory (template job keys, active job keys, forbidden hits) |

**Exit codes**: `0` = pass; `1` = guard violation (reason code on stderr); `2` = invocation/self-test failure.

**Harness**: new section **`§28B`** in `tests/run-tests.ps1` + `tests/run-tests.sh`.

**Contract tests**: extend `tests/auto_command_contract_test.py` in place with
`test_bug0009_*` prefix (forbidden-pattern markers, negative SHA-256 parity, active
five-job inventory).

**`check_intake_template_parity.py`**: extend with `--scope=downstream-ci-guard` for
**guard script byte-identity only** — NOT for `ci.yml` byte parity.

### 4. Forbidden pattern list and reason codes

**Template `ci.yml` must NOT contain** (case-sensitive substring / job-id scan):

| Category | Patterns |
|----------|----------|
| Job ids | `npm-test`, `brew-test`, `choco-test` |
| Paths/commands | `npm pack`, `its-magic-*.tgz`, `installer.sh`, `packaging/chocolatey`, `packaging/homebrew`, `choco pack`, `brew style` |

**Active kit `ci.yml` must contain** all five job ids: `checks`, `auto-fix`, `npm-test`,
`brew-test`, `choco-test`.

**Reason codes** (normative; no proliferation without DEC):

| Code | When |
|------|------|
| `DOWNSTREAM_CI_FORBIDDEN_PATTERN` | Template `ci.yml` matches a forbidden pattern |
| `DOWNSTREAM_CI_JOB_LEAK` | Template job inventory ⊄ `{checks, auto-fix}` |
| `KIT_CI_PACKAGING_JOBS_MISSING` | Active `ci.yml` missing any required packaging job id |

### 5. checks workflow semantics (both surfaces)

Apply to **`checks` job in both** active and template `ci.yml`:

1. When all runbook command keys (`TEST_COMMAND`, `LINT_COMMAND`, `TYPECHECK_COMMAND`)
   are empty or steps skipped → job **PASS** with explicit summary **`no tests configured yet`**.
2. `Fail if tests or lint failed` fires **only** when a **configured** test/lint step
   returns `failure` (skipped steps do not fail the job).
3. Typecheck failures remain hard-fail when `TYPECHECK_COMMAND` is configured.

**R4 mitigation**: once **US-0063** bootstrap sets `TEST_COMMAND`, real configured-command
failures MUST still fail `checks` — no weakening of fail-step semantics post-bootstrap.

### 6. Template runbook `TEST_COMMAND` bootstrap (DEC-0056 alignment)

| Surface | `TEST_COMMAND` default on ship |
|---------|-------------------------------|
| `template/docs/engineering/runbook.md` | **Empty** (`TEST_COMMAND:` with no value) |
| Active `docs/engineering/runbook.md` | Keep powershell harness (`tests/run-tests.ps1`) |

**US-0063 interaction preserved**: installer stack-aware bootstrap writes `TEST_COMMAND`
only when missing/unset in materialized runbook. Pre-bootstrap downstream repos stay
green; post-bootstrap repos run real tests.

**R5 mitigation**: sprint MUST re-run `validate_doc_profile.py` after template runbook
header change.

### 7. Install/upgrade smoke (BUG-0003 class)

Extend `tests/installer_completeness_bug0003_test.py`:

- `test_downstream_ci_yml_job_inventory_missing_mode` — `--mode missing --create` →
  installed `.github/workflows/ci.yml` job keys ⊆ `{checks, auto-fix}`; forbidden jobs absent.
- `test_downstream_ci_yml_job_inventory_upgrade_mode` — same after `--mode upgrade`.

**Manifest**: add `scripts/check_downstream_ci_guard.py` and
`scripts/downstream_ci_guard_lib.py` under `[install_include_paths]` (active + `template/`).

No change to `.github/workflows` manifest entries.

### 8. Template parity inventory

**Positive parity (active + `template/` byte-identical)**:

1. `scripts/check_downstream_ci_guard.py` ↔ `template/scripts/check_downstream_ci_guard.py`
2. `scripts/downstream_ci_guard_lib.py` ↔ `template/scripts/downstream_ci_guard_lib.py`
3. `docs/engineering/runbook.md` — remediation subsection only (see §9); **except**
   `TEST_COMMAND:` header line per §2
4. `docs/engineering/context/installer-owned-paths.manifest` — guard script entries
5. `scripts/check_intake_template_parity.py` — `--scope=downstream-ci-guard` extension

**Active-only (no mirror)**:

6. `docs/engineering/architecture.md` `# BUG-0009`
7. `tests/auto_command_contract_test.py` extensions
8. `tests/installer_completeness_bug0003_test.py` extensions
9. `.github/workflows/ci.yml` edits (template vs active differ by design)

**NEGATIVE parity (MUST NOT violate)**:

- Do **not** byte-match template and active `ci.yml` after fix.
- Do **not** add `check_intake_template_parity.py --scope=ci-downstream`.
- Do **not** strip packaging jobs from **active** CI.

### 9. Operator documentation — upgrade remediation

Ship verbatim blurb in README troubleshooting + runbook + release-notes template:

> **CI still runs its-magic packaging jobs?** Your project received a pre-fix workflow.
> Run **`its-magic --target <repo> --mode upgrade`** (or **`--mode clean`** then reinstall)
> to refresh `.github/workflows/ci.yml` from the corrected template. After upgrade, GitHub
> Actions should show only **`checks`** and **`auto-fix`** jobs — not `npm-test`,
> `brew-test`, or `choco-test`.

Scope reminder: fix applies to **new installs/upgrades**; stale repos heal on next upgrade
(**US-0018**).

### 10. Non-goals

- No cross-repo reusable GitHub Actions workflow.
- No rename of downstream `ci.yml`.
- No change to `deploy.yml`.
- No change to kit packaging job semantics in **active** CI.
- No new npm/pip runtime dependencies (stdlib-only Python guard).
- No retroactive auto-fix of operator repos outside upgrade/clean copy path.

## Consequences

- Downstream repos receive green-by-default CI without kit-only packaging failures.
- Kit repo retains full self-distribution CI confidence.
- Drift guard prevents re-leak of forbidden patterns into template CI.
- **US-0017** gains a documented, test-enforced negative-parity exception for `ci.yml`.

## Risks

| ID | Risk | Mitigation |
|----|------|------------|
| R1 | Strip packaging jobs from active CI | Guard active positive inventory; template-only forbidden scan |
| R2 | Stale broken repos until upgrade | Accepted scope; §9 remediation copy |
| R3 | Installer copies wrong workflow | Install-completeness job-inventory tests (§7) |
| R4 | False green after bootstrap | Fail-step only on configured command failure (§5) |
| R5 | Runbook validator side-effects | Re-run `validate_doc_profile.py` in sprint QA |
