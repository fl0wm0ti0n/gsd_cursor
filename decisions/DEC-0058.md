# DEC-0058: Executable merged-scratchpad wiring for validate-and-push (US-0076)

- **Date**: 2026-03-27
- **Status**: Accepted
- **Story**: `US-0076`
- **Research refs**: `R-0053`
- **Related**: **`DEC-0018`** (sync policy and reason-code vocabulary — **authoritative** for semantics),
  **`DEC-0055`** (merged scratchpad precedence: local → materialized baseline → example),
  **`US-0038`** (acceptance / gate chain), **`US-0071`** (operator-visible string hygiene)

## Context

**`DEC-0018`** and **`US-0038`** define **what** must hold before an auto-push and the
canonical **reason codes**. **`scripts/validate-and-push.ps1`** / **`.sh`** today read
**`docs/engineering/runbook.md`** for **commands** only and do **not** evaluate merged
scratchpad for **`SYNC_POLICY_MODE`**, **`ALLOW_AUTO_PUSH`**, **`AUTO_PUSH_BRANCH_ALLOWLIST`**,
or **`SYNC_CUSTOM_PHASES`**. Operators therefore experience **policy-only** configuration:
scratchpad flags document intent for **`/auto`** but do not **gate** the push scripts
(**`R-0053`** gap).

## Decision

### 1. Relationship to **`DEC-0018`**

- **`DEC-0018`** remains the **policy authority** (modes, gate order, reason-code meanings).
- **`DEC-0058`** records the **executable wiring** contract: how local scripts **read**
  merged scratchpad and **apply** that policy **without** duplicating a second informal
  policy source.
- Operator docs must **not** claim “scratchpad alone pushes”; they must say **run**
  **`validate-and-push`** (or documented alias) after an **eligible** boundary (**`US-0076`**
  **`AC-7`**).

### 2. Single policy source in the executable path

For **`SYNC_POLICY_MODE`**, **`SYNC_CUSTOM_PHASES`** (when mode is **`custom_phase_list`**),
**`ALLOW_AUTO_PUSH`**, and **`AUTO_PUSH_BRANCH_ALLOWLIST`**:

- The **only** source in the push script path is **merged scratchpad** per **`DEC-0055`**
  (same merge as **`installer.py`** / shared helper — **no** parallel shell re-implementation
  of precedence).
- **`runbook.md`** remains the source for **`TEST_COMMAND`** and optional lint/typecheck
  commands (**`R-0053`** mitigation: no dual policy for sync flags vs runbook commands).

### 3. Parse / merge failure behavior

- On missing layers, parse errors, or **`[SCRATCHPAD_MERGE_ERROR]`**-class failures:
  **fail closed**, **no push**, operator-visible remediation (reuse **`installer.py`**
  diagnostics where practical).

### 4. Phase / boundary signal (**`by_phase`**, **`by_milestone`**, **`custom_phase_list`**)

- **Default**: **Script invocation** (operator or CI) **is** the phase-completion boundary
  for eligibility evaluation when the configured mode requires a boundary. **`Cursor`** does
  not invoke this script automatically unless a **separate** documented hook is added
  (**backlog boundaries**).
- **Optional override** (single deterministic escape hatch): environment variable
  **`SYNC_PHASE_BOUNDARY=<canonical_phase_id>`** so CI can assert which phase completed.
  If unset, scripts **do not** parse **`state.md`** for phase (avoids ambiguous/stale reads
  unless a future story adds a strict contract).

### 5. Pre-push check chain

Order and failure codes align with **`US-0038`** / **`.cursor/commands/auto.md`** baseline:

1. Scratchpad merge + policy parse (**`SYNC_DISABLED`**, **`MANUAL_MODE_NO_AUTO`**,
   **`AUTO_PUSH_NOT_ENABLED`**, **`SYNC_TRIGGER_NOT_ELIGIBLE`**, **`[SCRATCHPAD_MERGE_ERROR]`**
   family as applicable).
2. **`TEST_COMMAND`** from runbook (required): **`TEST_COMMAND_MISSING`**, **`TEST_FAILED`**,
   **`TEST_TIMEOUT`**.
3. Optional lint/typecheck when set: **`OPTIONAL_CHECK_FAILED`**.
4. Branch allowlist: **`BRANCH_NOT_ALLOWLISTED`**.
5. QA / blocking posture (**§6**): **`BLOCKING_QA_FINDINGS`**, **`PRE_QA_AUTOPUSH_FORBIDDEN`**
   when applicable per bounded rules below.

### 6. QA / blocking scan (**`US-0076` AC-5**)

- **Glob**: all files matching **`sprints/S*/qa-findings.md`** (one sprint directory segment;
  pattern **`S` + four digits** / existing repo convention).
- **Blocking markers** (any match in **any** scanned file → **`BLOCKING_QA_FINDINGS`**, no push):
  - Literal substring **`BLOCKING_QA_FINDINGS`** (reason-code echo in artifact), or
  - A markdown task line **`- [ ]`** where the same line contains **`BLOCKING`** or
    **`FAIL`** (case-insensitive), or
  - A line **`- [ ]`** that is immediately under a heading **`## Blocking`** (case-insensitive)
    before the next **`##`** heading.
- **`PRE_QA_AUTOPUSH_FORBIDDEN`**: Emit when **`US-0038`** QA-first rule applies for the
  bounded policy implemented in the script (e.g. feature-branch heuristic or sprint-state
  signal **documented in runbook**) and the repo has not satisfied the documented “QA cleared”
  signal **without** weakening **`BLOCKING_QA_FINDINGS`** semantics above.

### 7. Cross-platform and observability

- **`validate-and-push.ps1`** and **`validate-and-push.sh`** stay **behaviorally aligned**
  for scratchpad-driven gates (**`US-0076` AC-6**).
- Logs / stdout: **reason codes** and **branch** identifiers only; no secret or **US-0071**-forbidden
  tokens.
- Optional **`--dry-run`** (or equivalent flag) prints **would-push / would-skip** with reason
  codes **without** **`git push`** (**`R-0053`**).

### 8. Deprecation note

The interpretation that **`SYNC_*` / `ALLOW_AUTO_PUSH`** are **documentation-only** for push
scripts is **deprecated** as of this decision for repos using **`US-0076`**-updated scripts;
**`DEC-0018`** semantics are unchanged — only **enforcement surface** is extended.

## Consequences

- **Positive**: One merge truth (**`DEC-0055`**), deterministic failures, **`US-0038`** alignment.
- **Negative**: Scripts gain a **Python** dependency for merge (or shared module invocation) on
  paths that use **`installer.py`** merge — acceptable vs duplicated precedence logic.
- **Risks**: Mis-tuned QA regex → false block or false allow; mitigate with **`AC-8`** fixtures
  and documented examples in runbook.
