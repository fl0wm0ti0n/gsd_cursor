# Decision DEC-0004

Status: Accepted

## Context

Two template files don't fit cleanly into "framework" or "user-data" categories:

1. `.cursor/scratchpad.md` — ships with default flag values, but users customize these (AUTO_FLOW_MODE, PHASE_MODE, etc.).
2. `README.md` — ships as its-magic documentation, but users may replace it with project-specific content.

How should upgrade mode handle these "mixed" files?

## Options

1. **Option A: Preserve (treat as user-data)** — never overwrite on upgrade. Safe, but users miss new flags or docs.
2. **Option B: Replace (treat as framework)** — always overwrite on upgrade. Dangerous: destroys user customizations.
3. **Option C: Merge** — parse and merge new keys into existing files. Complex, error-prone, hard to implement across 3 languages.
4. **Option D: Preserve + notify** — keep the user's file, but check for new content in the template version and print a notice listing what's new. The updated `scratchpad.local.example.md` (framework file, always updated) serves as reference for new flags.

## Recommendation

**Option D** (preserve + notify) for `.cursor/scratchpad.md`:
- Preserve the user's customized flags.
- Print a notice if the template version has new lines not present in the user's copy.
- The always-updated `scratchpad.local.example.md` shows all available flags.

**Option A** (preserve) for `README.md`:
- Never overwrite. Users can check the npm package or GitHub for updated its-magic docs.

## Impact

- Scratchpad handling requires a simple "diff check" in the upgrade flow: count lines in template vs. installed, or check for specific new keys. If mismatch, print a notice.
- README is simply skipped. No additional logic needed.
- Low complexity overall.
