## Context

US-0123 is the third slice of the six-story OpenCode adapter epic (US-0121..US-0126). US-0121 shipped the empty-but-valid `template/.opencode/` pack + the `--host` installer switch. US-0122 populated the pack with eight markdown role agents and locked the Layer-1 permission matrix (with `model:` omitted from every template agent per AC-7). US-0123 owns the per-role `provider/slug` resolution chain for the OpenCode host: each of the eight roles can resolve to a real `provider/model-id` slug (DeepSeek, Moonshot, Z.AI/GLM, Anthropic, OpenAI, OpenAI-compatible DashScope/Qwen, …) without leaking vendor IDs into `template/`, without the kit proxying provider traffic, and without amending Cursor's US-0101/US-0102 runtime.

R-0109 DQ1..DQ10 deepened the ten discovery questions. This DEC locks the answers as the cross-cutting model-slug contract that US-0124 (plugin spawn loop) and US-0126 (runbook) inherit without re-deriving. Two sovereign-critic non-blocking carry-forwards from the research phase are closed here: (1) `ik_us0123_dq7_catalog_optional_vs_failclosed` — absent catalog = no-op (no fail-closed); present + unknown slug = `OPENCODE_MODEL_SLUG_UNKNOWN` (fail-closed); (2) `ik_us0123_t002_t003_installer_hook_contract` — T-002 materializer + T-003 installer hook interface locked: trigger = `--host opencode|both` AND catalog present; absent = skip; fail = surface reason code + exit non-zero; triple-installer parity.

Research basis: **`R-0109`** US-0123 deepened findings (DQ1..DQ10 LOCKED for `/architecture`; US-0121 Q1..Q12 + US-0122 DQ1..DQ8 locks preserved, not wiped).

## Decision

### 1. Source of truth = local-only catalog (DQ1 LOCKED — AC-1)

SOT = `.opencode/model-catalog.local.json` (gitignored, operator-filled) + example `template/.opencode/model-catalog.local.example.json` (committed, placeholders only). The kit does NOT share one catalog across hosts. Forbidden surfaces for real OpenCode slugs: (a) `template/.opencode/agents/*.md` `model:` frontmatter (must be omitted in template — DQ2); (b) `template/.opencode/opencode.json{,c}` (must not exist in template — R-0109 Q6 US-0121 lock preserved); (c) `.cursor/model-catalog.local.json` (Cursor-side, separate host + schema — DQ4); (d) `.cursor/scratchpad.local.md` `MODEL_*` keys (Cursor-side compose only — DQ1). Different hosts, different schemas, different files.

**Rejected alternatives**: (a) scratchpad `MODEL_*` keys as OpenCode SOT + bridge materializer — rejected as coupling two hosts through one file with schema drift risk (per-phase Cursor keys vs per-role OpenCode); (b) `model:` placeholder in template agent frontmatter — rejected as violating US-0102 volatile-ID rule + US-0122 AC-7 and false-failing the D3 grep; (c) shared `.cursor/model-catalog.local.json` across hosts — rejected as union-schema coupling.

### 2. Template agents omit `model:` (DQ2 LOCKED — inherits US-0122 AC-7)

`template/.opencode/agents/*.md` frontmatter MUST NOT contain a `model:` key. US-0122 already ships these files with `model:` omitted (verified: `grep ^model: template/.opencode/agents/*.md` → zero matches). US-0123 inherits this and does NOT add `model:` to template. The materializer injects `model: <provider/slug>` into INSTALLED agent files only. Placeholder strings live in the example catalog file (`template/.opencode/model-catalog.local.example.json`), not in agent files.

### 3. Single fail-closed reason code (DQ3 LOCKED — AC-4)

Introduce ONE namespaced code `OPENCODE_MODEL_SLUG_UNKNOWN` for the OpenCode path (unknown/empty slug in `.opencode/model-catalog.local.json` at materialize time). Reuse existing `MODEL_CATALOG_INVALID` for malformed OpenCode catalog JSON (same semantics, different file — emit with an `opencode-catalog` scope tag rather than a new code). Do NOT introduce `OPENCODE_MODEL_CATALOG_INVALID`, `OPENCODE_MODEL_ROLE_SLUG_UNKNOWN`, etc. — one namespaced code is enough; the rest reuse the existing family with scope tags. Existing Cursor-side codes (`MODEL_SLUG_UNKNOWN`, `MODEL_OVERRIDE_SLUG_UNKNOWN`, `MODEL_ROLE_SLUG_UNKNOWN`, `MODEL_TIER_INVALID`, `MODEL_RESOLVE_FALLBACK`, `MODEL_CATALOG_SCHEMA_V2_INVALID`) remain Cursor-side only — not emitted on the OpenCode path.

### 4. Catalog path separate from Cursor (DQ4 LOCKED — AC-1)

Path = `.opencode/model-catalog.local.json` (gitignored) + `template/.opencode/model-catalog.local.example.json` (committed, placeholders). Separate from `.cursor/model-catalog.local.json` (Cursor-side). `.opencode/.gitignore` (US-0121 Q10) already ignores `*.local.json` — `model-catalog.local.json` is covered by the glob; no new gitignore entry needed (T-006 verifies; add explicit entry only if glob is narrower).

### 5. Per-role catalog schema, US-0069 bridges phase→role (DQ5 LOCKED — AC-7)

OpenCode catalog schema is per-role: `{schema_version, providers, roles}` where `roles` maps each of the 8 role names (`po`, `tech-lead`, `dev`, `qa`, `release`, `curator`, `security`, `auto`) to a `provider/slug` string. No per-phase keys on OpenCode. US-0069 / DEC-0051 phase→role matrix bridges `phase_id → role` on the orchestrator (unchanged); the catalog bridges `role → provider/slug` on OpenCode (new). Per-role divergence (AC-7) is expressed by assigning different `provider/slug` values to different roles — e.g. `po: "anthropic/claude-sonnet-4"`, `dev: "deepseek/deepseek-chat"`. Tests assert ≥2 roles have different providers in the example catalog.

### 6. Single example surface, placeholders only (DQ6 LOCKED — AC-2, AC-3, AC-9)

Single example surface = `template/.opencode/model-catalog.local.example.json`. Provider names (DeepSeek, Moonshot, Z.AI, Anthropic, OpenAI, DashScope) are allowed in the example — informational, not vendor IDs. Real model-id slugs are FORBIDDEN in `template/` — operators fill `<your-deepseek-slug>`, `<your-kimi-slug>`, `<your-glm-slug>`, `<your-claude-slug>`, `<your-gpt-slug>` placeholders in the local `.opencode/model-catalog.local.json`. Custom OpenAI-compatible providers (DashScope/Qwen) use a `providers` block with `npm: "@ai-sdk/openai-compatible"` + `options.baseURL` placeholder. D3 grep scope = `template/.opencode/agents/**/*.md` + `template/.opencode/opencode.json{,c}` (if present), **excluding** `*.example.json` / `*.local.json` — provider names in the example do NOT false-fail the D3 grep. Example covers ≥ DeepSeek, Moonshot, Z.AI, and one Western provider (Anthropic) — satisfies AC-2. No vendor IDs in `template/` — satisfies AC-3. Per-role assignment demonstrates AC-9 (Chinese APIs as capability, no kit proxy).

### 7. Additive integration — materializer injects into installed agents only (DQ7 LOCKED — AC-1, AC-5, AC-6 — critic NBs closed)

Additive integration — US-0122 template agents unchanged. US-0123 adds: (a) example catalog `template/.opencode/model-catalog.local.example.json`; (b) materializer `scripts/opencode_model_catalog_apply.py`; (c) validator extension on `scripts/model_tier_validate.py` (DQ9); (d) gitignore entries (already in US-0121 Q10 — `*.local.json` under `.opencode/`). At install time (`--host opencode|both`), the materializer reads `.opencode/model-catalog.local.json` (if present) and injects `model: <provider/slug>` into the INSTALLED `.opencode/agents/<role>.md` (not template). If catalog absent, installed agents keep `model:` omitted and OpenCode uses its default model — **no fail-closed** (catalog is optional; fail-closed applies only when catalog present but slug unknown/empty → `OPENCODE_MODEL_SLUG_UNKNOWN`). Auth keys live in OpenCode `/connect` (`~/.local/share/opencode/auth.json`), never in catalog, template, or git (AC-5). Cursor DEC-0086/0087 behavior unchanged (AC-6) — OpenCode path is additive, no Cursor alias as OpenCode runtime.

**Critic NB `ik_us0123_dq7_catalog_optional_vs_failclosed` closed**: absent catalog = no-op (no fail-closed); present + unknown = `OPENCODE_MODEL_SLUG_UNKNOWN` (fail-closed). The materializer does NOT fail when the catalog is missing — it only fails when the catalog is present but invalid.

**Critic NB `ik_us0123_t002_t003_installer_hook_contract` closed**: T-002 materializer + T-003 installer hook interface locked:
- Materializer input: `.opencode/model-catalog.local.json` + installed `.opencode/agents/<role>.md` files.
- Materializer output: installed agent files with `model:` injected (or reason code + non-zero exit).
- Installer trigger: `--host opencode|both` AND `.opencode/model-catalog.local.json` exists at install target.
- Installer behavior on absent catalog: skip materializer (no-op; no fail-closed).
- Installer behavior on materializer failure: surface reason code + exit non-zero.
- Triple-installer parity: `installer.py` / `installer.ps1` / `installer.sh` use the same trigger condition and error surface.
- The installer does NOT generate the catalog for the operator — operators create it themselves (or copy from the example and fill in real slugs).

### 8. OpenCode host = always `api` mode, kit does not proxy (DQ8 LOCKED — AC-2, AC-6)

OpenCode host = always `api` mode (BYOK via `/connect`). The kit does NOT proxy provider traffic. `MODEL_PROVIDER_MODE=cursor|api` (US-0101 / DEC-0086 §5) is a Cursor-side scratchpad key; on OpenCode it is irrelevant (always `api`). `MODEL_RESOLVE=role_catalog` (US-0102 / DEC-0087) is Cursor-side; on OpenCode the catalog is `.opencode/model-catalog.local.json` (DQ1), not the Cursor role catalog. The two hosts have independent resolution chains. Documented in the runbook stub (US-0123 ships one line; US-0126 owns full text).

### 9. Validator extension — extend `model_tier_validate.py` (DQ9 LOCKED — AC-8)

Extend `scripts/model_tier_validate.py` with a new `--scope opencode-catalog` mode (preferred over a new script). The extension adds:
- `check_template_opencode_agents`: grep `template/.opencode/agents/**/*.md` for `model:` field (must be absent) + forbidden vendor slugs (D3 grep, excluding `*.example.json` / `*.local.json`). Also grep `template/.opencode/opencode.json{,c}` if present (must not exist in template).
- `validate_opencode_catalog`: load `.opencode/model-catalog.local.json` (if present) → validate schema (`schema_version`, `providers`, `roles` with 8 role keys) → unknown/empty slug → `OPENCODE_MODEL_SLUG_UNKNOWN` (DQ3) → malformed JSON → `MODEL_CATALOG_INVALID` (scope-tagged `opencode-catalog`).
- `check_opencode_example_catalog`: load `template/.opencode/model-catalog.local.example.json` → assert placeholder values only (no real model-id slugs) → assert ≥2 roles have different providers (AC-7 per-role divergence).
- Reuse existing `check_forbidden_slugs_in_file` helper (extend the forbidden-slug list to cover OpenCode agent files + example catalog).

Only if the extension proves too coupled (e.g. schema divergence forces a separate validator class) does architecture fall back to a new `scripts/opencode_model_catalog_validate.py`. Default: extend.

### 10. Runbook stub + h2 anchor (DQ10 LOCKED — AC-10)

The kit does not endorse a single vendor." US-0126 expands this into a full "OpenCode model slug routing" runbook section. US-0123 does NOT author a full runbook section (YAGNI — US-0126 owns it).

### 11. Contract tests + parity (AC-8)

- **Neutral**: US-0121 pack path consumed (additive); US-0122 template agents unchanged; US-0102 volatile-ID rule respected; Cursor `MODEL_*` keys unchanged.
