# DEC-0077 — Caveman voice-compression rule append, contract markers, and SHA baseline bump (BUG-0011)

## Status

Accepted — 2026-06-06

## Context

**Composes on `DEC-0072`** (Caveman scratchpad contract, rule-only composition, 9-zone literal
invariant, default-off invariant) — **forward-link only; no rewrite** of `DEC-0072` body or
§6 pinned `test_caveman_default_off_*` subtests.

Research anchor **`R-0077`** (`orchestrator_run_id=auto-20260606-02`) confirmed root cause:
**US-0089** shipped Caveman **scaffolding** in `.cursor/rules/caveman.mdc` (gates, literals,
toggles) but **zero** actionable voice-compression directives — so `CAVEMAN_MODE=1` does not
change reply prose. **US-0090** input-side compression is **orthogonal** and must not be
modified.

Operator scope: rule-body append only — no new skill, no scratchpad key changes, no Wenyan
modes, no vendor token-percent claims.

## Decision

Adopt the architecture below. Acceptance-criteria traceability is published in
§AC-Traceability at the end.

### 1. Delivery surface — rule append only (DEC-0072 §2 preserved)

Append to **`.cursor/rules/caveman.mdc`** (active) and **`template/.cursor/rules/caveman.mdc`**
(mirror) — **byte-identical pair** after delivery.

**Do not** modify pre-voice scaffolding blocks verbatim (scratchpad gate, 9-zone literal
invariant, non-suppressible gate vocabulary, toggle phrase catalog, TOKEN_PROFILE
non-substitution, attribution line).

**Alternatives rejected**:

- **Skill-only voice** — rejected; literals must stay in always-on rule (**R-0077** Q6).
- **Amend `# US-0089` only** (no `# BUG-0011`) — rejected; breaks bug-section traceability
  pattern (**R-0077** Q6).

### 2. Voice section verbatim outline (normative for execute)

New top-level section in `caveman.mdc` (append after existing scaffolding):

```text
## Voice compression (when CAVEMAN_MODE=1)
```

**Subsection order** (headings architecture-locks; dev phase MUST NOT rename):

| Order | Heading | Content |
|-------|---------|---------|
| 1 | `### Precedence` | When `CAVEMAN_MODE=1`, voice-compression directives in **this rule** override conflicting **user-rule** prose-style guidance (e.g. "write complete sentences", "blog-post quality") for **assistant reply voice only**; does **not** override user rules for tool usage, git safety, security, or commit policy. Footnote (architecture only): Cursor merges Team → Project → User rules; project rule precedence cited here for operator clarity — normative agent text lives in this subsection. |
| 2 | `### Intensity levels` | Markdown table with columns **Level** / **Semantics** / **Example pattern** for **`lite`**, **`full`**, **`ultra`** only (no Wenyan rows). Kit-native before/after pairs: (1) orchestration gate explanation, (2) auth-middleware bug from intake repro. Pattern line: `` `[thing] [action] [reason]. [next step].` `` Goal: **token-saving terse/imperative prose** — **not** stereotypical caveman roleplay. |
| 3 | `### Drop rules` | Drop articles/filler/hedging/pleasantries where level permits; technical terms exact; fragments OK at `full`/`ultra`. |
| 4 | `### Auto-Clarity` | Pause compression for security warnings, destructive ops, ambiguous compression — resume Caveman after clear part. |
| 5 | `### Persistence` | Voice compression active every response while `CAVEMAN_MODE=1`; off only via scratchpad or documented toggle phrases. |
| 6 | `### Ultra and literal regions` | **Pointer stub only** — defer to existing `## Literal-region invariant (9-zone hard MUST)`; state reason codes / IDs / paths / proof tuples remain byte-literal; `ultra` abbreviates ordinary prose words only — **never** abbreviate reason codes or gate tokens. **No duplicate** 9-zone list. |

### 3. Level table semantics — kit-native examples (Option B)

Upstream React-centric examples **rejected** — kit-native examples required (**R-0077** Q2).
