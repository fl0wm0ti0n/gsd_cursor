# DEC-0063: Intake gate script ship path for packaged installs (BUG-0001)

- Date: 2026-03-30
- Status: Accepted
- Bug: `BUG-0001`
- Related stories: `US-0008`, `US-0018`
- Research: `R-0058`
- Supersedes: none

## Context

Packaged **`its-magic`** installs hydrate consumer repos from **`template/`** (see **`installer.ps1`** / **`installer.sh`** **`SOURCE_ROOT`**). **`template/scripts/`** lacked the three mandatory **`intake_*`** modules present in repo **`scripts/`**, so **`/intake`** pre-persistence gates cannot run in target repos. Scope remains **intake-mandatory script completeness only** — not full active/**`template/scripts/`** mirroring (**`DEC-0061`** / bug acceptance).

## Options considered

1. **Enumerate only in `package.json` `files`** (ship from repo **`scripts/`** root without **`template/scripts/`** copies) — **Rejected** for **triple-installer parity**: PS1/SH installers copy from **`template/`** only; Choco/Brew archives rely on the same tree.
2. **Mirror entire `scripts/` into `template/scripts/`** — **Rejected** — overshoots agreed completeness bar and increases drift surface.
3. **Minimal mirror + parity enforcement (chosen)** — Copy exactly the three intake modules into **`template/scripts/`**, keep repo **`scripts/`** canonical for development, add deterministic parity checks and **`US-0018`** alignment.

## Decision

### 1. Canonical intake payload (normative)

These files **MUST** exist under **`template/scripts/`** and **MUST** match the corresponding files under **`scripts/`** (byte-for-byte or policy-approved normalization documented in sprint tasks):

- `intake_evidence_validate.py`
- `intake_evidence_lib.py`
- `intake_bug_routing_guard.py`

**Transitive imports**: Only **`intake_evidence_lib`** is required by **`intake_evidence_validate`**; **`intake_bug_routing_guard`** is stdlib-only (**`R-0058`**). No additional repo-local modules are in scope for **BUG-0001**.

### 2. `package.json` `files` policy

- **Primary delivery**: Inclusion of **`template/`** in **`files`** **MUST** subsume the three paths above once present under **`template/scripts/`**.
- **Optional hardening**: Explicitly listing **`scripts/intake_evidence_validate.py`**, **`scripts/intake_evidence_lib.py`**, **`scripts/intake_bug_routing_guard.py`** in **`files`** is **allowed** for npm audit clarity **if** implementers keep **active** and **`template/`** copies in lockstep (same parity rules). It is **not** a substitute for **`template/scripts/`** copies.

### 3. Parity and regression tests

- Add a **deterministic** check (CI-friendly) that **`template/scripts/`** contains the three intake modules and that they match **`scripts/`** (extend existing parity patterns — e.g. intake-focused fixture or script alongside **`check_token_cost_parity.py`** / installer tests as sprint chooses).
- **`template/`** tree under packaging mirrors **MUST** stay aligned with **active** repo policy for these paths (**`US-0030`** family).

### 4. Upgrade / new-file delivery (`US-0018`)

- New or updated intake files under **`template/scripts/`** **MUST** be classified and delivered on **`--mode upgrade`** per existing upgrade semantics (framework-owned template files); **BUG-0001** closure **requires** green lifecycle evidence for **fresh install** and **upgrade** paths in sprint **AC**/**tasks**.

## Consequences

- Installers and npm consumers converge on one **`template/`**-based truth for intake tooling.
- Duplication between **`scripts/`** and **`template/scripts/`** requires discipline; parity tests mitigate drift.
- Explicit **`files`** entries without template copies would **not** satisfy **BUG-0001** acceptance.

## Risks

| Risk | Mitigation |
|------|------------|
| Drift between **`scripts/`** and **`template/scripts/`** | Parity test + single change-set expectation in review |
| Upgrade skips new intake files | **`US-0018`** classification + QA matrix row in sprint |

## Decision outcome

- Approved option: **3** (minimal mirror + parity + upgrade alignment)
