# DEC-0027: Optional Cross-Repo Compatibility Observability

- Date: 2026-03-01
- Status: Accepted
- Related story: US-0034
- Research refs: R-0016

## Context

Teams need compatibility visibility across repos/modules/contracts, but many
projects should not incur extra workflow overhead by default.

## Decision

1. Add optional mode controls in `.cursor/scratchpad.md`:
   - `CROSS_REPO_OBSERVABILITY=0|1` (default `0`)
   - `COMPATIBILITY_GATE_ON_CRITICAL=0|1` (default `1`)
   - `COMPATIBILITY_SOURCES=` explicit monitored source declarations
2. Define canonical artifacts:
   - `docs/engineering/compatibility-signals.md`
   - `docs/engineering/compatibility-report.md`
   - `docs/engineering/manifests/registry.manifest.yaml`
   - `docs/engineering/manifests/repo.manifest.yaml`
3. Preserve zero-overhead behavior when mode is disabled for
   `/intake`, `/architecture`, `/execute`, and `/qa`.
4. When mode is enabled and unresolved critical findings exist with gate policy
   enabled, block release progression via decision gate with reason code
   `COMPATIBILITY_CRITICAL_OPEN`.

## Consequences

- Compatibility observability becomes explicit, traceable, and optional.
- Default workflows remain lightweight.
- Release safety can be strengthened in compatibility-sensitive projects.
