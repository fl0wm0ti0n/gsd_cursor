# DEC-0039: Upgrade-Safe Scratchpad Example Refresh and Installer Parity

- Date: 2026-03-14
- Status: Accepted
- Related story: US-0057
- Research refs: R-0032

## Context

Users reported drift where `.cursor/scratchpad.local.example.md` did not reliably
reflect newer framework flags after upgrade, while user-owned local overrides
must remain untouched.

## Decision

1. Treat `.cursor/scratchpad.local.example.md` as framework-owned and always
   refresh it in `--mode upgrade`.
2. Keep `.cursor/scratchpad.local.md` user-owned and never overwrite it in
   upgrade mode.
3. Enforce parity across `installer.ps1`, `installer.sh`, and `installer.py`
   for scratchpad example refresh behavior and diagnostics.
4. Add deterministic upgrade diagnostics that report example refresh status and
   explicit user-local preservation signal.
5. Add lifecycle regression coverage for installer and CLI upgrade paths.

## Consequences

- New flags remain discoverable in refreshed example surfaces after upgrades.
- User local overrides remain safe from accidental overwrite.
- Upgrade behavior becomes observable and deterministic across all installer
  implementations.
