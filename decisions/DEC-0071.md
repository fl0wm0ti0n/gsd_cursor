# DEC-0071 — 4-layer defense-in-depth `.env` exclusion contract

## Status

Accepted — 2026-04-13

## Context

US-0085 introduces a repo-root `.env` (gitignored) holding values for 20 `*Env`
environment variables referenced by `.cursor/remote.json` and
`docs/engineering/release-targets.json` (US-0064). Agents must not read `.env`.

`.gitignore` alone is insufficient because Cursor agents have developer-level
filesystem access beyond git tracking (R-0072 confirmed). A single exclusion
layer leaves residual risk of secret ingestion.

## Decision

Adopt a **4-layer defense-in-depth** contract for `.env` exclusion:

| Layer | Mechanism | What it blocks |
|-------|-----------|----------------|
| 1 | `.gitignore` — `.env`, `.env.local` patterns | Git commit/push of secret files |
| 2 | `.cursorignore` — `.env`, `.env.local`, `.env.*` | Agent file tools (`read_file`, `grep`, `@` mentions) |
| 3 | `.cursor/rules/coding-standards.mdc` — behavioral rule | Agent intent to open/search `.env` |
| 4 | Operator discipline — runbook guidance | Opening `.env` in editor (context leak) |

Each layer mitigates a distinct attack surface. No single layer is sufficient.

### AC-8 helper: `scripts/print_remote_env_hint.py`

- Reads `.env.example` names and validates parity with `*Env` fields in
  `template/.cursor/remote.json` and `docs/engineering/release-targets.json`.
- Never opens, reads, or prints from `.env`.
- Exit 0 = parity ok; exit 1 = `ENV_EXAMPLE_PARITY_MISMATCH`.

Alternative considered: documented shell recipe (`source .env && env | grep`).
Rejected — POSIX-only, leaks values to stdout, no parity enforcement.

### Template parity

Active and `template/` both receive `.gitignore` updates, `.cursorignore`,
`.env.example`, and rule text. Scripts and tests are active-only.

## Consequences

- All 4 layers must be maintained in sync; adding a new `*Env` field requires
  updating `.env.example` (enforced by `print_remote_env_hint.py` parity check).
- Terminal bypass remains a residual risk — agents can run shell commands that
  read `.env`; mitigated by rules and operator awareness, not by tooling.
- Open-tab leak (operator opens `.env` in editor) is mitigated by runbook warning
  and `.cursorignore` blocking proactive agent reads.
- US-0086 (automation profile) must inherit this contract — automation may use
  env already set but must not read `.env`.
