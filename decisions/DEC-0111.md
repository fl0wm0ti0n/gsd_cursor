# DEC-0111: Release Trigger Derivation Architecture

**Status**: Accepted

**Companion**: R-0098 (research delivered)  
**Orchestrator Run**: auto-20260628-04  

## Decision

Extend current release flow (`/release` command, `trigger_release.sh`) with four trigger adapters (GitHub webhook, npm publish, git tag push, manual /release) that produce standardized `TriggerContext` structures. Version comparison logic, CHANGELOG `[Unreleased]` promotion, and release notes generation reuse US-0100 functions unchanged. Compose layer sits before existing `/release` path without altering it.

## Rationale

- **Q1-Q5 (Technical)**: `TriggerContext` abstraction enables adapter-agnostic downstream processing. GitHub/npm/git tag/manual triggers all converge on same `{version, previous_version, source, metadata}` structure. `release_changelog_lib.compare_versions()` and `promote_unreleased()` remain unchanged — US-0111 calls them, doesn't modify them. Backward compat: `RELEASE_TRIGGER_SOURCE=manual` (default) → byte-identical to pre-US-0111 `/release` behavior.

- **Q6-Q10 (Process)**: Compose layer dispatch before `/release` ensures no existing code paths altered. Ledger integration via `append_entry()` (read-only API). Parity scope `release-trigger-adapter` added to `check_intake_template_parity.py`. 9 fail-closed reason codes in `reason_codes.md` § US-0111.

## Risk Analysis

- **R1**: GitHub API rate limiting — mitigate with `GITHUB_TOKEN` env var + fallback to `git ls-remote`
- **R2**: npm private registry auth — `npm view` inherits `.npmrc`; offline detection short-circuits
- **R3**: Annotated vs lightweight tag ordering — use `git for-each-ref --sort=-version:refname` with semver sort
- **R4**: Windows atomic rename — document as best-effort; test fallback path explicitly
- **R5**: Auto-detection ambiguity in CI — document priority order; recommend explicit `RELEASE_TRIGGER_SOURCE=github`
- **R6**: Ledger bloat — one ledger row per trigger event; orthogonal to sovereign loop cadence

## Consequences

- **Positive**: Trigger-agnostic release flow; manual override preserved; no breaking changes to `/release` command
- **Negative**: Increased complexity in release dispatch layer; 9 new fail-closed error codes to document
- **Neutral**: Ledger gains `decision_type=version_derivation` entries; US-0110 convergence predicate unchanged
