# DEC-0069: Bug-intake boundary refresh of `resume_brief` for post-intake `/auto` resume (`BUG-0005`)

- Date: 2026-04-03
- Status: Accepted
- Bug: `BUG-0005`
- Research: `R-0064`
- Supersedes: none

## Context

**`BUG-0005`** reports that after canonical **`/intake bug`** persistence, running **`/auto`** without explicit **`start-from`** can fail fast with **`RESUME_BRIEF_STALE`** because **`handoffs/resume_brief.md`** still encodes a pre-intake cycle (for example **`intended_resume_phase=intake`**) that no longer matches the newly persisted bug context.

Deterministic resume-source precedence (**`.cursor/commands/auto.md`**, **`docs/engineering/auto-orchestration-reference.md`**) remains:

1. Explicit **`/auto start-from=<phase>`**
2. Parseable **`handoffs/resume_brief.md`**
3. Conservative **`docs/engineering/state.md`** fallback
4. Fail fast on stale/unparseable/ambiguous brief (no silent downgrade to state when the brief is present-but-stale)

**`R-0064`** concludes the defect is a **handoff gap** at the bug-intake boundary, not a reason to weaken fail-fast. The architecture must lock **when** and **how** the brief is refreshed or reconciled so normal **`/intake bug` → `/auto`** continuity works without manual override, while preserving precedence and **`US-0045`** backlog authority.

## Options considered

1. **Intake-time deterministic `resume_brief` rewrite (chosen)** — On successful canonical bug intake persistence, the intake phase writer atomically updates **`handoffs/resume_brief.md`** with fields aligned to the new bug context and the **next valid lifecycle phase** for that context (default **`discovery`** for OPEN bug rows unless a narrower documented exception applies). Minimal complexity; no change to precedence order.
2. **Narrow `/auto` self-heal** — Orchestrator rewrites the brief when machine-verifiable predicates hold. **Deferred** as non-primary: higher complexity and risk of masking operator intent; if introduced later, requires strict predicates, idempotency, **`state.md` audit breadcrumbs**, and dedicated reason codes (separate decision).
3. **Operator-only remediation** — Manual **`start-from`** or hand edit. **Rejected** as sole solution for **`BUG-0005`** acceptance (“no manual override for normal continuation”).

## Decision

### 1. Primary contract: intake boundary refresh (normative)

When **`/intake bug`** (or equivalent canonical bug-intake path) **successfully persists** an OPEN bug row per **`US-0045`**:

- The intake completion writer **must** refresh **`handoffs/resume_brief.md`** in a single deterministic write (full replace or prepend of the normative “latest pointer” block per repo template — implementation chooses one pattern but must be **idempotent** and **documented** in sprint scope).
- The refreshed brief **must** include at minimum:
  - **`bug_id`** matching the persisted bug
  - **`intended_resume_phase`** (or equivalent canonical field) set to **`discovery`** for the default OPEN-bug continuation (not **`intake`** for a completed intake)
  - **`resolution_source`** seed consistent with “brief is authoritative until overridden by explicit **`start-from`**”
  - Boundary metadata: **`orchestrator_run_id`** when known, intake/boundary **timestamp**, and pointer to intake evidence when present (**`handoffs/intake_evidence/...`**)
- The refresh **must** be consistent with **`docs/product/backlog.md`** for that **`bug_id`** (no brief claiming a phase that contradicts OPEN/DONE facts).

### 2. Precedence and fail-fast boundaries (unchanged, normative)

- Explicit **`start-from`** remains **highest** precedence.
- If **`resume_brief.md`** is **present and parseable**, orchestrator **must** evaluate it **before** **`state.md`** fallback.
- **`RESUME_BRIEF_STALE`**, **`RESUME_BRIEF_UNPARSEABLE`**, and conflict codes **remain** valid when the brief contradicts authoritative backlog (**`US-0045`**) or freshness rules — **no silent continue**.
- Intake refresh **does not** exempt corrupt or manually edited briefs from fail-fast.

### 3. Reconciliation vs “refresh”

- **Refresh** = deterministic rewrite triggered by **successful** bug intake persistence (primary fix).
- **Reconciliation** = reserved for future **bounded self-heal** only under **DEC-0069 §4** gate; not required for **`BUG-0005`** closure.

### 4. Optional future self-heal (non-normative gate)

Any orchestrator-side self-heal **must** satisfy all of:

- Single unambiguous OPEN bug row + matching **`state.md`** checkpoint + completed intake marker
- Idempotent rewrite + append-only **`state.md`** audit record with reason code
- Default deny unless explicitly specified in a future decision

Until then, **§1** is the only normative automation path.

### 5. Writer ownership

- **Canonical writer** for post-bug-intake **`resume_brief`** refresh: **bug intake completion** path (PO role in phase matrix for **`intake`**).
- **`/auto`**, **curator `/refresh-context`**, and other phases **must not** silently overwrite intake-refreshed briefs except through documented, deterministic contracts (e.g. explicit portfolio close-out) — avoid dual-writer races; conflicts are resolved by fail-fast or explicit operator **`start-from`**.

### 6. Regression matrix (normative minimum)

Executable or documented parity checks **must** cover **`R-0064`** scenarios:

| # | Scenario | Expected |
|---|----------|----------|
| 1 | Intake persists OPEN bug; brief updated at boundary | **`/auto`** resolves **`discovery`** (or policy-defined next) without false **`RESUME_BRIEF_STALE`** |
| 2 | Intake persists bug; brief absent | **`/auto`** uses **`state.md`** fallback per precedence |
| 3 | Operator sets explicit **`start-from`** | Argument wins; valid phase proceeds |
| 4 | Brief parseable but contradicts backlog | Fail-fast (**`RESUME_BRIEF_STALE`** or dedicated conflict code); no silent continue |
| 5 | Portfolio switch: prior bug DONE, new bug OPEN | Brief targets new **`bug_id`** and phase; no stale **`intake`** carryover |

### 7. Affected surfaces (implementation scope hint)

- **`.cursor/commands/intake.md`** (and **`template/`** mirror if required by parity policy)
- **`handoffs/resume_brief.md`** structure / examples in runbook or PO guidance as needed
- Optional validators or tests that assert brief freshness vs backlog after bug intake

## Consequences

- **`/intake bug` → `/auto`** normal continuation no longer depends on stale pre-intake resume metadata.
- Fail-fast safety and deterministic precedence remain intact.
- Sprint work can focus on intake writer + tests without broad orchestrator refactors.

## Risks

| Risk | Mitigation |
|------|------------|
| Dual-writer conflict (intake vs curator) | Single canonical writer list in **§5**; document exceptions; fail-fast on ambiguity. |
| Wrong default phase for niche bug workflows | Keep default **`discovery`**; document exceptions in architecture if product adds variants. |
| Template/active parity drift | Apply same refresh contract to **`template/`** command surfaces per repo parity rules. |

## Decision outcome

- Approved option: **1** (intake-time deterministic **`resume_brief`** refresh)
- Approval source: architecture phase (**tech-lead**), **`orchestrator_run_id=auto-20260403-02`**
