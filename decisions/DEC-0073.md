### 1. Three-axis non-substitution — Option A (three parallel sentences; forward-link `DEC-0072` §1)

`TOKEN_PROFILE` (US-0080 / DEC-0062), `CAVEMAN_MODE` (DEC-0072 §1 — response-
side voice), and `CAVEMAN_COMPRESS_INPUT` (this DEC — input-side file
mutation) are **three independent axes**. None substitutes for another.

**Normative paragraph** (published verbatim in both
`docs/engineering/auto-orchestration-reference.md` and
`docs/engineering/runbook.md`, **active + `template/` mirrors**; replaces the
two-sentence DEC-0072 §1 paragraph by extending it in place — not rewriting
DEC-0072):

> `TOKEN_PROFILE` controls context breadth. `CAVEMAN_MODE` controls reply
> voice. `CAVEMAN_COMPRESS_INPUT` controls input-side file mutation. None
> substitutes for another; setting one does not change the others. Combine
> freely.

**Rules**:

- Setting `CAVEMAN_COMPRESS_INPUT=1` NEVER changes `TOKEN_PROFILE` or
  `CAVEMAN_MODE` semantics.
- `CAVEMAN_MODE=1` NEVER activates input compression; input compression is
  **script-invoked**, not voice-toggled. Operator phrases from `DEC-0072` §5
  (`caveman on` / `caveman: lite`…) do **not** extend to compression.
- `TOKEN_PROFILE=lean` NEVER implies input compression.

**Option B** (add a 2×2×2 matrix alongside the paragraph) and **Option C**
(collapse into `TOKEN_PROFILE` / `CAVEMAN_MODE` as a sub-mode) are rejected —
see "Alternatives considered". Rationale: the two-D paragraph form
already exists in `DEC-0072` §1 for `TOKEN_PROFILE × CAVEMAN_MODE`; mirroring
the same form for the third axis is symmetric, easy to scan, and adds zero
auditability cost. A table adds doc surface for no semantic gain.

**Relation to `DEC-0072` §1**: `DEC-0072` §1 remains binding for the two-axis
table. This DEC **does not edit** `DEC-0072`; the published runbook /
reference paragraph is extended in-place (a single paragraph supersedes the
prior two-sentence paragraph; the `TOKEN_PROFILE × CAVEMAN_MODE` 2D table in
`DEC-0072` §1 is unchanged).

### 2. Activation gate — opt-in, empty-scope fail closed

**All** of the following MUST be true at tool entry to activate any mutation:

1. `CAVEMAN_COMPRESS_INPUT=1` in `.cursor/scratchpad.md` (default `0` / absent
   = off per DEC-0072 §3).
2. `CAVEMAN_FILE_SCOPE=` has a **non-empty** resolved value after §5 grammar
   parsing. Empty-scope default is a **pure opt-in** invariant — there is no
   implicit scope.
3. A mutation mode flag is explicitly supplied on the CLI (`--write`) OR the
   caller is `--verify-originals` (non-mutation).

**Fail-closed behavior** (pre-write, no file touched):

| Condition | Reason code | Exit |
|-----------|-------------|------|
| `CAVEMAN_COMPRESS_INPUT=0` or unset | `CAVEMAN_COMPRESS_MODE_DISABLED` | non-zero |
| `CAVEMAN_FILE_SCOPE=` empty / whitespace / comment-only | `CAVEMAN_COMPRESS_SCOPE_EMPTY` | non-zero |
| Unknown named profile in `CAVEMAN_FILE_SCOPE` | `CAVEMAN_COMPRESS_SCOPE_UNKNOWN_PROFILE` | non-zero |
| Conflicting CLI flags (e.g. `--dry-run --write`; `--write --verify-originals`) | `CAVEMAN_COMPRESS_FLAG_CONFLICT` | non-zero |

`--purge-orphans` is **deferred** (not in v1). If supplied, the script fails
closed with `CAVEMAN_COMPRESS_FLAG_CONFLICT` (unknown flag class — v1 exposes
only the four flags listed in §8).

**Scratchpad keys** (reserved no-ops in DEC-0072 §3 — activated here):

- `CAVEMAN_COMPRESS_INPUT=0|1` — default `0`.
- `CAVEMAN_FILE_SCOPE=` — default empty.

No new scratchpad keys are added; no existing key is renamed. Exact byte
strings (DEC-0072 §3 test contract) preserved.

### 3. Sidecar original policy — Option B parallel tree, single `.gitignore` anchor

**Locked path pattern**:

```
docs/.caveman-originals/<relative/path-from-repo-root>/<file>
```

Rules:

- Every `--write` run MUST create (or refresh) the sidecar **before** any
  target-file mutation. Atomic write order: write sidecar (temp + replace) →
  scan literal regions on proposed output → write target (temp + replace).
  Any step fails closed → no partial state.
- Relative path reconstruction preserves directory structure verbatim (e.g.
  `docs/user-guides/foo.md` → `docs/.caveman-originals/docs/user-guides/foo.md`).
- A `.gitkeep` MUST exist at `docs/.caveman-originals/.gitkeep` (active only)
  to materialize the directory on install / clone; content is empty.
- **`.gitignore` anchor**: single repo-root entry `docs/.caveman-originals/`
  (active only; not installer-owned — operators may commit sidecars in their
  own repos if desired; the kit's `.gitignore` defaults to ignoring them).
- **`.cursorignore`**: left **operator-owned** per `DEC-0071` / US-0085. No
  kit-level parity entry for sidecars. Runbook documents this explicitly.

**Option A** (sibling dotfile per folder) and **Option C** (hash-suffix) are
rejected: Option A scatters sidecars and requires per-folder `.gitignore`
hygiene; Option C hurts human readability and complicates
`--verify-originals`. Option B matches the US-0085 philosophy ("one place,
one `.gitignore` anchor, no per-folder drift").

### 4. Deny-list source of truth — Option C hybrid; deny always wins

**Layered source of truth** (deterministic evaluation order — any violation
at any stage fails closed with the corresponding §7 reason code, **before**
any file mutation):

1. **Hard-coded baseline** (Python constant in
   `scripts/caveman_compress_input.py`) — verbatim list from §4.1 below.
2. **`.gitignore` secret-pattern merge** — patterns starting with `.env*`,
   `*secret*`, `*credential*`, `*token*`, `*private*` merged as additional
   denies. Adds denies; never removes.
3. **Optional `.cursorignore` overlay** — only when operator opts in via
   `CAVEMAN_COMPRESS_INGEST_CURSORIGNORE=1` (reserved flag; default off).
   Adds denies; never removes.
4. **Allow-list evaluation** (§5) — only files surviving steps 1–3 are
   eligible.
5. **Literal-region pre-write scan** (DEC-0072 §4 9-zone invariant).
6. **Write** (sidecar + target; §3).

**Deny always wins over allow.** Any file in steps 1–3 is unreachable by any
allow-list glob.

### 5. Allow-list grammar — Option C hybrid; frozen `docs-prose-only` v1 profile

**`CAVEMAN_FILE_SCOPE`** grammar (evaluated left-to-right; empty = pure
opt-in = `CAVEMAN_COMPRESS_SCOPE_EMPTY`):

| Form | Example | Semantics |
|------|---------|-----------|
| Named profile | `CAVEMAN_FILE_SCOPE=docs-prose-only` | Expands to the frozen glob set below. |
| Raw CSV globs | `CAVEMAN_FILE_SCOPE=docs/user-guides/**/*.md,docs/engineering/runbook.md` | Each glob evaluated literally; path-separator `/` required (forward-slash) regardless of host OS. |
| Hybrid | `CAVEMAN_FILE_SCOPE=profile:docs-prose-only;globs:handoffs/archive/*.md` | Profile expanded + additional raw globs unioned. |

**Unknown profile** (any token not in the locked table below and not matching
the grammar rules) → fail closed with `CAVEMAN_COMPRESS_SCOPE_UNKNOWN_PROFILE`.
**Empty** value (after trimming / comment strip) → `CAVEMAN_COMPRESS_SCOPE_EMPTY`.

#### 5.1 v1 profile table (frozen; DEC-revision required to amend)

| Profile | Glob set |
|---------|----------|
| `docs-prose-only` | `docs/user-guides/**/*.md`, `docs/engineering/runbook.md`, `docs/engineering/state-archive/**/*.md`, `handoffs/archive/*.md` |

Only one profile ships in v1. Additional profiles require a DEC.

**Precedence when profile and raw globs are both supplied** (hybrid form):
union (both expanded; deduplicated at glob-match time; deny-list still wins
over the union).

**Out-of-scope in v1**: profile composition (`profile:A;profile:B`) —
restricted to one profile per scope string; detecting a second `profile:`
token fails closed with `CAVEMAN_COMPRESS_SCOPE_UNKNOWN_PROFILE`.

### 6. Compression algorithm — Option B only (safe-mode minifier); aggressive deferred

**v1 ships a single, strictly-idempotent algorithm** (Option B from Q9):

1. Collapse runs of ≥2 consecutive blank lines to exactly one blank line.
2. Trim trailing whitespace on every line.
3. Normalize line endings to `\n` (LF).
4. Preserve final-newline-at-EOF status (do not add / remove trailing
   newline).

This algorithm is **deterministic and byte-idempotent by construction**:
running it a second time on its own output produces a byte-equal result.
Zero filler-word drift risk (R8 neutralized in v1).

**Option A (aggressive — filler-word strip + prose rewrite) is deferred** to
a future story under a new DEC (no `--mode` flag in v1 to reserve future
grammar freedom). **Option C (LLM-assisted) remains rejected** for US-0090
and future stories — non-determinism violates AC-6; vendor coupling
prohibited.

**Literal-region pre-write scan** (DEC-0072 §4 9-zone invariant) applies:
even the safe-mode algorithm MUST NOT alter any byte inside a literal region.
The script computes the 9-zone region map on the **input** and the **output**;
byte-for-byte equality of literal regions is a hard precondition for `--write`
commit. If the scan fails, the script fails closed with
`CAVEMAN_COMPRESS_LITERAL_REGION_DAMAGED` — no sidecar update, no target
mutation (sidecar write happens in the same atomic phase per §3, so roll back
the temp file before rename).

**Idempotency contract** (AC-6): for any file `f` in allow-list and not in
deny-list, `compress(compress(f)) == compress(f)` byte-for-byte. Violating
this is `CAVEMAN_COMPRESS_NOT_IDEMPOTENT`.

### 7. Reason-code vocabulary — nine codes, three families, no post-write codes

Locked vocabulary (architecture ratifies verbatim; `ALL_CAPS_WITH_UNDERSCORES`
per DEC-0038 / US-0088 style; all fit zone 4 of the DEC-0072 §4 literal-region
invariant automatically):

| Family | Reason code | Stage | Trigger |
|--------|-------------|-------|---------|
| **Gating** | `CAVEMAN_COMPRESS_MODE_DISABLED` | pre-write | `CAVEMAN_COMPRESS_INPUT≠1`. |
| **Gating** | `CAVEMAN_COMPRESS_FLAG_CONFLICT` | pre-write | Conflicting CLI flags (e.g. `--dry-run --write`). |
| **Scope** | `CAVEMAN_COMPRESS_SCOPE_EMPTY` | pre-write | `CAVEMAN_FILE_SCOPE=` empty (default). |
| **Scope** | `CAVEMAN_COMPRESS_SCOPE_UNKNOWN_PROFILE` | pre-write | Named profile not in §5.1. |
| **Scope** | `CAVEMAN_COMPRESS_SCOPE_VIOLATION` | pre-write | Resolved target path outside resolved allow-list. |
| **Integrity** | `CAVEMAN_COMPRESS_DENY_HIT` | pre-write | Target path matches §4 deny baseline / ignore merges / overlay. |
| **Integrity** | `CAVEMAN_COMPRESS_NOT_IDEMPOTENT` | during-write | Second-run byte comparison differs. |
| **Integrity** | `CAVEMAN_COMPRESS_LITERAL_REGION_DAMAGED` | during-write | 9-zone region differs between input and proposed output. |
| **Integrity** | `CAVEMAN_COMPRESS_ORIGINAL_MISSING` | pre-write (`--verify-originals`) | Compressed file has no sidecar. |

**Invariants**:

- Every code is **pre-write** or **during-write** (pre-commit). **No
  post-write codes** — a post-write failure means a write committed before
  validation, which is architecturally forbidden.
- **No new codes** may be added outside a follow-on DEC revising this §7.
  Rule (R9 mitigation): family membership (Scope / Integrity / Gating) is
  the only axis along which the vocabulary may grow.
- All codes appear in `--report` JSON output (§8) under a `violations[]`
  array; each entry has `{code, path, stage, detail}`.

### 8. CLI contract — four flags, orthogonal, fail-closed on conflict

**Entrypoint**: `scripts/caveman_compress_input.py` (active) +
`template/scripts/caveman_compress_input.py` (byte-identical per US-0017 and
§9 row 1).

**Flags** (all stdlib `argparse`, no third-party dep):

| Flag | Semantics |
|------|-----------|
| `--dry-run` (default when no mutation mode supplied) | Inventory + diff summary + deny hits + literal-region sanity to stdout. No mutation. |
| `--write` | Perform mutation (sidecar + target) on every file surviving deny + allow + literal scan. Fails closed on any violation. |
| `--verify-originals` | No mutation. Walks `docs/.caveman-originals/` and asserts every sidecar maps to an existing target and vice versa. Fails closed with `CAVEMAN_COMPRESS_ORIGINAL_MISSING` on any orphan. |
| `--report` | Emits a single JSON document to stdout: `{deny_list_version, scope_resolved, files_considered[], files_eligible[], files_would_write[], violations[], idempotency_check}`. May be combined with `--dry-run` or `--verify-originals`; incompatible with `--write`. |

**Conflict precedence** (deterministic; fail closed with
`CAVEMAN_COMPRESS_FLAG_CONFLICT`):

- `--dry-run --write` → conflict.
- `--write --verify-originals` → conflict.
- `--write --report` → conflict (`--report` is read-only).
- Any unknown flag (including `--purge-orphans`, `--mode=...`) → conflict.

**Exit-code contract**: `0` iff zero violations and zero unresolved parity
asserts; non-zero otherwise. Non-zero exit carries a single
`REASON_CODE=CAVEMAN_COMPRESS_*` line on stderr (first code encountered wins;
remaining codes are in `--report` JSON when requested).

**`CAVEMAN_COMPRESS_INGEST_CURSORIGNORE`** (reserved env var from §4) is
read at tool entry; any value other than `0|1` is treated as `0` (default
off; no fail-closed to preserve forward compatibility).

## Risk resolutions (R8–R11)

- **R8 (filler-word drift)** — Neutralized in v1 by **deferring aggressive
  mode entirely** (§6 Option B only). Future aggressive-mode DEC MUST
  specify a frozen filler-word list and `--report` hash emission.
- **R9 (reason-code proliferation)** — Mitigated by §7 three-family
  grouping (Scope / Integrity / Gating) and the invariant "no new codes
  without a subsequent DEC revising §7". Nine codes total — architecture
  explicitly forbids growth beyond this set absent DEC.
- **R10 (rule-subsection byte-identity)** — Mitigated by **not adding a
  subsection to `.cursor/rules/caveman.mdc` in v1** (§9 negative parity).
  Pre-US-0090 SHA-256 `E10EFC32C628E790E69E2393F381108FE0B1F16E0BCDCFFFC162EFF6F91E47DE`
  is preserved end-to-end; a contract subtest re-asserts byte-identity post-
  ship. Runbook subsection (row 2) provides the discoverability surface
  without touching the rule file.
- **R11 (publish-smoke omission / BUG-0003 class)** — Mitigated by **hard
  requirement** §10: the install-completeness fixture is **non-negotiable**;
  `/sprint-plan` MUST seed a task for it, and `/release` MUST not ship
  without it.

  one runbook subsection + mirror, one reference paragraph extended +

## Alternatives considered

- **§1 Option B — 2×2×2 matrix published alongside paragraph.** Rejected: 8
  cells, visually dense, no semantic gain over three parallel sentences.
  Operator readability wins over audit-table symmetry here; 2D table in
  `DEC-0072` §1 already exists for the only pairing that benefits from a
  matrix (`TOKEN_PROFILE × CAVEMAN_MODE`).
- **§1 Option C — matrix only (drop paragraph).** Rejected: adds doc
  surface for no semantic gain; harder to quote; worse for index-search.
- **§3 Option A — sibling dotfile sidecars.** Rejected: scatters sidecars,
  requires per-folder `.gitignore` hygiene, drifts over time.
- **§3 Option C — hash-suffix sidecars.** Rejected: hurts human readability,
  complicates `--verify-originals`, adds collision-resolution logic without
  benefit.
- **§4 Option A — hard-coded constants only.** Rejected: silent drift risk
  when new secret paths enter `.gitignore` without DEC update.
- **§4 Option B — `.cursorignore` / `.gitignore` alone.** Rejected:
  `.cursorignore` targets agent file-context exclusion, not script mutation
  (R-0072 semantics); `.gitignore` will not list canonical product /
  engineering docs (they are committed).
- **§5 Option A — CSV globs only.** Rejected: no curated opinion; every
  operator writes their own glob set; auditability suffers.
- **§5 Option B — named profiles only.** Rejected: inflexible for one-off
  operator scope.
- **§6 Option A in v1 — aggressive safe+aggressive with filler-word list.**
  Rejected for v1: filler-word list becomes a release-over-release
  byte-identity liability (R8), adds fixture surface (one class per filler
  category), and the line-level minifier already achieves meaningful token
  reduction on prose-heavy files with zero drift risk.
- **§6 Option C — LLM-assisted compression.** Rejected (non-determinism,
  vendor coupling; violates AC-6 by construction).
- **§7 add `CAVEMAN_COMPRESS_PARTIAL_WRITE` post-write code.** Rejected: a
  post-write failure means we committed before validating, which §3 atomic
  order forbids. If the atomic write fails, the sidecar / target temp files
  are discarded before rename — no post-write state to name.
- **§8 add `--mode=safe|aggressive`.** Rejected in v1 (§6 Option B only). A
  future DEC can introduce the flag.
- **§8 add `--purge-orphans` in v1.** Rejected per research (R-0073
  recommendation); defer to a follow-on story to avoid hidden destructive
  operations in v1.
- **§9 add subsection to `.cursor/rules/caveman.mdc` (Q17 option).**
  Rejected for v1: R10 byte-identity risk outweighs marginal discoverability
  benefit. Runbook subsection (row 2) and non-substitution paragraph (row 3)
  cover operator UX. A future DEC may add the subsection if evidence
  justifies.
- **§10 Option B — new `scripts/check_caveman_template_parity.py`.**
  Rejected: script proliferation. Extending the existing intake-parity
  script matches the BUG-0001 / BUG-0003 install-completeness convention.
- **§10 Option B — new `tests/installer_caveman_completeness_test.py`.**
  Rejected: test-file proliferation. Extending
  `tests/installer_completeness_bug0003_test.py` keeps the install-
  completeness contract under one test surface.
