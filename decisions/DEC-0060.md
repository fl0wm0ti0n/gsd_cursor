# DEC-0060: Intake question-pack interactive evidence and persistence gate (US-0078)

- Date: 2026-03-28
- Status: Accepted
- Story: `US-0078`
- Supersedes: none
- Extends: `DEC-0050` (`US-0068`) — pack taxonomy, topic IDs, and baseline reason codes remain authoritative; this decision **adds** machine-verifiable **interaction evidence** and normative **`ref`** binding.

## Context

`DEC-0050` requires deterministic packs and persisted fields (`asked_topics`, `missing_topics`, `assumptions_confirmed`) with a fail-closed gate, but does not fully specify how implementations prove that required topics were **actually asked** or that assumptions were **explicitly user-confirmed** in-session. Research **`R-0055`** defines a concrete evidence schema, parser rules, and test matrix for closing that gap without reopening pack semantics.

## Decision

1. **Evidence artifact**: Every intake run that mutates backlog/acceptance MUST persist an **`intake_evidence`** bundle (markdown section, structured sidecar, or equivalent) that includes at minimum:
   - `selected_pack` — `first-intake-pack` | `small-intake-pack` per **`DEC-0050`**.
   - `asked_topics` — ordered list of **required** topic keys for which the run **emitted** a user-visible question or a deterministic assumption-proposal prompt.
   - `missing_topics` — subset still unsatisfied at gate time (empty when passing).
   - `topic_coverage` — **one row per required topic key** at persistence time: `{ topic_key, satisfied_by, ref }`.
   - `satisfied_by` — `answer_ref` | `assumption_confirmation_ref` (literal enums).
   - `ref` — canonical pointer per **§ Ref binding** below (non-empty for every row).
   - `assumptions_confirmed` — unchanged literal contract from **`DEC-0050`**.
   - `assumption_confirmation_ref` — required whenever `assumptions_confirmed` is affirmative/non-placeholder per **`R-0055`**; MUST reference the **user** affirmative turn, not model inference.

2. **Validation rules** (normative; align **`R-0055`** § “Validation / parser rules”):
   - Pack resolution → required keys; unknown pack → `INTAKE_REQUIRED_PACK_INCOMPLETE`.
   - ∀ required key, ∃ `topic_coverage` row with non-empty `ref` → else `INTAKE_REQUIRED_TOPIC_MISSING` / aggregate `INTAKE_REQUIRED_PACK_INCOMPLETE`.
   - **Asked-vs-covered**: every `topic_coverage` key MUST appear in `asked_topics` unless a **documented bundle exception** is added in a future DEC amendment; default = **fail closed** (`INTAKE_REQUIRED_TOPIC_MISSING` or dedicated drift code if implementation allocates one, still blocking).
   - Affirmative `assumptions_confirmed` without `assumption_confirmation_ref` → `INTAKE_ASSUMPTION_CONFIRMATION_REQUIRED`.
   - Literal allowlist rejection for false confirmations (`yes`/`true`/`confirmed` without ref) per **`R-0055`**.
   - Any rule failure → **`INTAKE_PERSISTENCE_BLOCKED`** with primary sub-codes preserved in diagnostics; **no** backlog/acceptance mutation (**`US-0078` AC-3**).

3. **Mode parity**: `INTAKE_GUIDED_MODE=0` (low-touch) MUST still run rules 1–2; it may shorten **follow-ups** but MUST NOT skip the evidence gate for required pack coverage.

4. **Ref binding (locked format)**:
   - **`ref`** = opaque string `ie:<intake_run_id>:<turn_index>:<sha256_16>` where:
     - `intake_run_id` — UUID v4 or monotonic run id issued at intake start (implementation-chosen; MUST be unique per run).
     - `turn_index` — non-negative integer, strictly increasing per user-visible exchange in the intake session (implementation-defined step counter).
     - `sha256_16` — first 16 hex chars of SHA-256 over UTF-8 **canonical JSON** of `{ "intake_run_id", "turn_index", "topic_key", "satisfied_by", "quoted_user_text" }` with **sorted keys** and `quoted_user_text` = trimmed user message body for that turn (empty string allowed only for assumption bundle edge cases explicitly tested).
   - **`assumption_confirmation_ref`** uses the **same** `ie:` scheme but `satisfied_by` in the hashed payload MUST be `assumption_confirmation_ref` and `quoted_user_text` MUST be the user’s **affirmative** reply.
   - Validators MUST reject malformed `ref` prefixes, wrong length, or mismatch between row fields and parsed `ref` payload where detectable.

5. **Migration**:
   - **New persistence**: full **`topic_coverage`** + **`ref`** rules apply; incomplete evidence → fail closed.
   - **Legacy rows** in backlog/vision created before this decision: **grandfathered** for **read/display** only; the **next** intake-driven mutation for that story MUST supply full **`US-0078`** evidence or the write is blocked (no silent partial upgrade).
   - Optional operator backfill scripts are **out of band**; framework default is not automatic backfill.

## Alternatives considered

1. **Amend `DEC-0050` in place** — rejected for traceability; **`DEC-0050`** remains the pack/coverage authority; **`DEC-0060`** layers evidence enforcement.
2. **Policy-only enforcement (no `ref`)** — rejected; fails **`US-0078`** AC-1/AC-4.
3. **Transcript-external secret refs** — rejected as default; `ie:` keeps binding self-contained and testable without external transcript stores (stores may still exist for debugging).

## Consequences

- Execute phase implements validator + persistence hook ordering before any backlog/acceptance write.
- Active + `template/` parity for intake command/runbook/README references.
- **`R-0055`** test tiers (**Tier A–C**) remain the **`AC-8`** baseline; fixtures MUST use literal reason codes in this decision and **`DEC-0050`**.
