# DEC-0037: Deterministic Status Reconciliation Command Contract

- Date: 2026-03-13
- Status: Accepted
- Related story: US-0055
- Research refs: R-0031

## Context

Status drift can persist across artifact surfaces after long-running automation
or historical updates (for example DONE stories with unchecked ACs in backlog or
acceptance, stale resume intent metadata). Existing commands provide partial
coverage (`/memory-audit`, `/release` target-sprint reconciliation,
`/refresh-context` compaction), but no dedicated deterministic normalization pass.

## Decision

1. Introduce a dedicated status reconciliation command (for example
   `/status-reconcile`) with deterministic detection and bounded repair.
2. Preserve canonical ownership: backlog story status remains source-of-truth;
   derived surfaces reconcile to canonical unless conflict with release evidence
   requires fail-closed handling.
3. Enforce target-scoped mutation boundaries:
   - update only mismatched stories and linked derived rows,
   - never rewrite unrelated historical narrative content.
4. Require auditable normalization evidence in
   `docs/engineering/status-normalization-report.md` plus state checkpoint.
5. Require deterministic reason codes and remediation on blocked/conflict paths.
6. Update continuation metadata (`handoffs/resume_brief.md`) deterministically to
   next OPEN story and intended phase after reconciliation.

## Consequences

- Improves reliability of `/auto` continuation and artifact consistency.
- Adds implementation and regression workload for reconciliation logic and
  reason-code handling.
- Reduces ad-hoc manual status cleanup operations.
