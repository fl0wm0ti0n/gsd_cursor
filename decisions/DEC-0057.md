# DEC-0057: Scratchpad example-first upgrade ordering and paired catalog parity (AC-11)

- Date: 2026-03-26
- Status: Accepted
- Story: `US-0075`
- Research refs: `R-0052` (including post-discovery US-0075 extension)
- Related: **`DEC-0039`** (framework-owned example refresh; user-local preservation;
  installer parity diagnostics), **`DEC-0055`** (Model B merge precedence; example as
  default catalog; upgrade preserves local + refreshes example), **`US-0057`** /
  **`US-0073`** (prior contracts this story closes drift against)

## Context

Under **Model B** (**`DEC-0055`**), operators rely on **`.cursor/scratchpad.local.example.md`**
as the discoverable framework key catalog, while materialized **`.cursor/scratchpad.md`**
may refresh from **`template/.cursor/scratchpad.md`**. A failure mode reported in discovery
is **example lag**: the materialized baseline moves while the **example** surface stays
stale, or the two paired files diverge in **documented sections / `KEY=` vocabulary**
(e.g. Team mode, `/auto` role/phase keys, triad caps). That breaks the operator contract
to **copy-from-example** and undermines merge diagnostics that name layers consistently
(**`DEC-0039`**).

**`DEC-0039`** already requires upgrade to refresh the example and never overwrite user
**`.cursor/scratchpad.local.md`**. It does not, by itself, spell out **pipeline ordering**
relative to materialized baseline refresh or **machine-enforced structural parity** between
the paired committed/template files.

## Decision

### 1. Example-first ordering invariant (upgrade / install refresh)

Any operation that refreshes **materialized** **`.cursor/scratchpad.md`** (active or under
`template/`) from template **must not** complete in a state where **`.cursor/scratchpad.local.example.md`**
is older than the shipped **`template/.cursor/scratchpad.local.example.md`** catalog while
the baseline was updated. Concretely:

1. **Refresh example from template first**, or **bundle** example refresh with baseline
   refresh in one deterministic transaction, so the **example never lags** the template
   catalog when the baseline moves (**`US-0075`** **`AC-1`**, **`AC-3`**).
2. **`--mode upgrade`** and applicable fresh-install paths **always** refresh framework-owned
   **`scratchpad.local.example`** surfaces to match shipped template bytes unless a
   **documented exception** exists with a **reason code** (**`AC-2`**).
3. Parity of behavior and diagnostics across **`installer.ps1`**, **`installer.sh`**,
   **`installer.py`**, **`bin/its-magic.js`**, and **`docs/engineering/context/installer-owned-paths.manifest`**
   (+ `template/` mirror) is mandatory (**`AC-4`**, **`AC-8`**).

This **amends** the operational reading of **`DEC-0039`** §1–3: example refresh is not only
“on upgrade” but **ordered relative to** baseline refresh so drift cannot recur; it **does not**
change **`DEC-0039`** user-local non-overwrite or cross-installer parity intent.

### 2. Alignment with **`DEC-0055`** merge model

Canonical merge **precedence** (**local → materialized baseline → example**) is unchanged.
This decision adds **delivery / refresh ordering** and **structural parity** so the **example**
layer always reflects the **full** shipped framework vocabulary visible in the paired baseline
file, consistent with **`DEC-0055`** §2–3 (example supplies defaults; upgrade preserves user
local; example refreshed on upgrade per **`DEC-0039`**).

### 3. Paired-file catalog parity (**`AC-11`**)

Enforce **deterministic structural parity** between:

- **`.cursor/scratchpad.md`** ↔ **`.cursor/scratchpad.local.example.md`**
- **`template/.cursor/scratchpad.md`** ↔ **`template/.cursor/scratchpad.local.example.md`**

**Equality** is required on:

- the set of framework **`##` section headers** (per research **`R-0052`** parity gate), and
- the set of **`KEY=`** lines (automation keys),

with **values** allowed to differ only where the story explicitly allows conservative
example defaults. **No key or section may exist in only one** of a pair unless a **deterministic
manifest exception** documents it as *local-only*; default is **full mirror** (**`US-0075`**
**`AC-11`**).

Verification is **machine-enforced** (test or script invoked from **`tests/run-tests.*`**),
not manual-only review.

### 4. Operator diagnostics

Upgrade/install output must distinguish **example refresh**, **materialized baseline** actions,
and **user local** preservation, with reason-coded paths aligned with **`DEC-0039`** /
**`US-0057`** regression posture (**`AC-5`**, **`AC-10`**).

## Consequences

- Execute/sprint work implements ordering fixes, parity checks, tests, README/runbook, and
  manifest alignment per **`US-0075`** acceptance criteria.
- **`DEC-0055`** and **`DEC-0039`** remain authoritative for merge precedence and ownership;
  **`DEC-0057`** is the **US-0075** architecture decision for **ordering + AC-11**.

## Options considered

1. **Documentation-only ordering guidance** — Rejected; does not prevent recurrence without
   CI-enforced parity and tests.
2. **Example refresh without paired parity gate** — Rejected; leaves one-sided keys/sections.
3. **Example-first ordering + paired parity gate + diagnostics (chosen)** — Matches discovery,
  research, and backlog **`AC-11`**.
