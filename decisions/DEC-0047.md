# DEC-0047: Mandatory runtime QA autopilot contract for generated projects

- Date: 2026-03-16
- Status: Accepted
- Story: `US-0065`

## Context

Generated-project QA could pass without proving the target app/service actually
started, became reachable, or produced acceptable runtime signals. Research
(`R-0042`) confirms startup/readiness proof, bounded retries, and log-severity
evidence are needed for deterministic runtime truth.

## Decision

Adopt a mandatory runtime-validation contract for execute/qa with explicit
reason-code boundaries and bounded retry behavior.

Decision details:

1. Runtime stage chain is mandatory:
   `startup -> readiness/connectivity -> log scan -> bounded retry -> verdict`.
2. PASS requires successful completion of mandatory runtime stages (or explicit,
   deterministic skip semantics when policy allows).
3. Runtime failures must emit deterministic reason codes:
   - `RUNTIME_STARTUP_FAILED`
   - `RUNTIME_ENDPOINT_UNREACHABLE`
   - `RUNTIME_LOG_CRITICAL_DETECTED`
   - `RUNTIME_RETRY_BUDGET_EXHAUSTED`
   - `RUNTIME_STACK_PROFILE_UNRESOLVED`
4. Retry behavior is bounded and selective:
   - applies to transient startup/connectivity failures only,
   - capped by configured attempt/time limits,
   - non-transient critical log signals fail closed.
5. Evidence schema is mandatory and reproducible:
   - startup command/profile,
   - runtime mode (`local|remote`) and endpoint/health result,
   - retry ledger (attempts/delays/outcomes),
   - runtime log severity summary,
   - final verdict + reason code + evidence refs.
6. Stack-aware profile resolution is required for Node/Python/Go/Java/.NET, with
   deterministic fail-safe on unresolved profiles.
7. Webapp contexts include browser-surface runtime verification and
   console/network error evidence when applicable.

## Alternatives considered

1. Optional best-effort runtime checks:
   - rejected because it preserves false-PASS risk and fails AC intent.
2. Stack-specific retry algorithms from day one:
   - deferred due to complexity; unified bounded retry policy is simpler and
     sufficient for first contract.
3. Permissive generic unknown-stack fallback:
   - rejected to keep outcomes deterministic; unresolved profiles fail closed.

## Consequences

- QA/execute PASS semantics become stricter and more trustworthy for generated
  projects.
- Runtime evidence quality improves reproducibility and remediation speed.
- Some projects may initially fail faster until stack-profile mapping or startup
  commands are clarified; this is expected and explicit.
