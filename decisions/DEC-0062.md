# DEC-0062: Token-cost metrics, comparable-run class, and evidence channel (US-0080)

- Date: 2026-03-29
- Status: Accepted
- Story: `US-0080`
- Supersedes: none
- Extends: `US-0053` (token profile / compaction — this decision adds **normative measurement + comparison** only)
- Related: `DEC-0052` (materialized phase plan in run class), `R-0057` (research basis)

## Context

Long orchestrated runs can accumulate very large **cache-read-equivalent** token volume versus fresh input/output. **`US-0080`** requires measurable baselines, a **50% cache-read reduction** target on **comparable** `/auto` runs, auditable evidence, and explicit **trade-offs** without weakening isolation, strict-proof, role, or release gates (**`US-0048`**, **`US-0056`**, **`US-0069`**, **`US-0039`**).

## Decision

### 1. Canonical metric fields (AC-1 / AC-6)

Per-run and per-phase rollups **MUST** record these **literal keys** (integer counts unless noted):

| Field | Meaning |
|-------|---------|
| `cache_read_tokens` | Tokens served from prompt/context cache for the counted scope (vendor **`cache_read_input_tokens`** semantics or product-mapped equivalent). |
| `cache_creation_tokens` | Tokens written into cache for the counted scope (vendor **`cache_creation_input_tokens`** semantics or equivalent), when available; **`0` or omitted** only when the host cannot report — document `metric_source` in the row. |
| `input_tokens` | Ordinary input tokens **excluding** the cache-read breakdown when the API separates them (align to vendor **`input_tokens`** definition for the same usage object). |
| `output_tokens` | Completion/output tokens for the counted scope. |
| `phase_call_count` | Non-negative integer: number of **phase-spawned model calls** attributed to each canonical **`phase_id`** in the resolved schedule for that run. |
| `orchestrator_call_estimate` | Optional: bounded estimate of top-level orchestration/tool turns if implementers split “orchestration hops” from phase calls — **not** a substitute for **`phase_call_count`**. |

**UI label mapping**: Any IDE or host label **MUST** be mapped to these semantics in committed evidence; if mapping is unknown, record **`metric_source=unmapped_host`** and **do not** claim AC-2 satisfaction for that row.

### 2. Comparable run class (AC-1 / AC-2)

Two runs are **comparable** for baseline/target and **50% `cache_read_tokens` reduction** claims **only** when their **run-class canonical object** matches **byte-for-byte** after canonical serialization (sorted keys, UTF-8, no insignificant whitespace).

**Run-class object** (required keys — values from merged scratchpad + **`docs/engineering/state.md`** plan breadcrumbs for that run):

- `story_id` (e.g. `US-0080`)
- `TOKEN_PROFILE` (merged scratchpad)
- `SECURITY_REVIEW` (`0` or `1`)
- `phase_policy_mode` (`full` \| `exclude` \| `include` \| `profile`)
- `resolved_phase_plan` (ordered array of canonical phase id strings **after** reinstatement, as materialized pre-spawn per **`DEC-0052`**)
- `requested_start_from` (canonical phase id or empty string if none)
- `resolution_source` (`argument` \| `resume_brief` \| `state_fallback`)
- `resolved_start_phase` (canonical phase id)

**`run_class_hash`**: SHA-256 hex (lowercase) of `json.dumps(run_class_object, sort_keys=True, separators=(',', ':'))`.

**Rule**: AC-2 comparisons **MUST** use the **same `run_class_hash`**. Cross-hash comparisons are **invalid** for the 50% claim (emit reason code **`TOKEN_COST_RUN_CLASS_MISMATCH`** in tooling/docs).

### 3. Evidence channel (AC-6)

- **Canonical store**: **append-only** files under **`handoffs/token_cost_runs/`**, one primary artifact per **`orchestrator_run_id`**:
  - Preferred: **`handoffs/token_cost_runs/<orchestrator_run_id>.md`** (human-auditable tables) **or** **`.jsonl`** (machine-first), as implemented in execute.
- Each file **MUST** include: `orchestrator_run_id`, `run_class_hash`, `metric_source`, UTC timestamp, per-phase rows (the §1 fields), and **run totals**.
- **`docs/engineering/state.md`**: auto continuation / phase checkpoints **MUST** include a pointer: **`token_cost_evidence_ref=<path>`** when metrics are recorded for that run (may be empty until first row exists).

### 4. Bounded phase-context (AC-4) — architecture contract

Phase subagents **MUST** receive **only** inputs allowed by phase handoff contracts; slimming **MUST NOT** remove **`US-0048`** isolation fields, **`US-0056`** strict-proof tuples, **`US-0069`** role evidence, or **`US-0039`** release-chain requirements from the **canonical artifact surfaces** those stories govern. Redundancy removal is allowed **only** when a **DEC-0062 §6** parity manifest proves active + **`template/`** policy equivalence.

### 5. Parity manifest (AC-3 / AC-9)

Execute **MUST** maintain a **versioned manifest** (path chosen in sprint, e.g. **`docs/engineering/token-cost-parity-manifest.md`** or scripted list) enumerating every **active** path under **`.cursor/commands/`**, **`.cursor/rules/`**, and required **`template/`** mirrors touched by token-cost slimming. CI parity checks **MUST** extend beyond scratchpad pairs where this manifest lists command/rule deltas.

### 6. Accepted trade-offs (AC-10)

| Trade | Benefit | Cost / risk | Mitigation |
|-------|---------|-------------|------------|
| Shorter command/policy text in repeated surfaces | Lower cache-read volume | Operators may miss edge-case policy | Keep gates + runbook deep links; parity manifest + AC-8 regressions |
| Dedicated metric files vs only state.md | Auditable time series; smaller state growth | Extra files to curate | Append-only discipline; pointer from state |
| Strict run-class equality | Prevents baseline gaming | Stricter rebaseline when phase plan changes | Document intentional rebaseline in sprint notes |
| Optional `cache_creation_tokens` | Works across hosts with partial usage | Incomplete cross-host strictness | `metric_source` + docs |

**Non-goals (explicit)**: disabling cache, removing mandatory gates, weakening **`DEC-0029`** / **`DEC-0038`** / **`DEC-0051`** / **`US-0039`**.

### 7. Phase boundary operator visibility (AC-10 alignment)

When a phase completion records **token-cost** evidence for an orchestrated run, writers **SHOULD** add **`token_cost_evidence_ref=<path>`** to the compact **phase boundary status** block (may be empty when no metrics file exists yet). Optional **`run_class_hash=<hex>`** **SHOULD** be copied when known for inspectability.

## Alternatives considered

1. **Profile-only (`TOKEN_PROFILE=lean`)** — rejected (insufficient per **`R-0057`**).
2. **Compare across different `resolved_phase_plan` values** — rejected (invalidates AC-2).
3. **IDE-only metrics** — rejected as canonical (supplementary only; committed artifacts are SOT for AC-6).

## Consequences

- **`/execute`** implements slimming, manifest, validators, and **`handoffs/token_cost_runs/*`** population per sprint tasks.
- **`README.md`** / **`docs/engineering/runbook.md`** document operator patterns (AC-7) consistent with §2–§3.
- **`R-0057`** research findings are **normatively narrowed** by this decision’s literals and hashes.
