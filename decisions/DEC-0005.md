# DEC-0005: /ask Command Design

## Status: Accepted

## Context

Users need a way to ask questions about project state, stories, architecture, and decisions without triggering the full workflow pipeline (intake -> architecture -> sprint -> execute). The current system forces all interaction through artifact-producing commands.

## Options

### Option A: New /ask command (read-only, no subagent)
A lightweight command that reads context files and answers questions. No artifacts created, no state modified. Uses the default agent.

### Option B: Modify existing commands to detect "question mode"
Add heuristics to /intake and other commands to detect when the user is asking a question vs. making a request. Skip artifact creation for questions.

### Option C: Separate /status and /explain commands
Multiple specialized read-only commands for different question types.

## Decision

**Option A.** A single `/ask` command is simplest. It's explicit (user chooses to use it), requires no heuristics, and doesn't risk accidentally skipping artifacts when they should be created. One command covers all question types because the AI naturally adapts to the question content.

## Consequences

- Adds 1 command file (active + template).
- README needs a documentation update.
- No structural changes to existing commands or agents.
