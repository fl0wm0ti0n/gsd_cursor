# DEC-0008: Dedicated Memory Drift Audit Command

## Status: Accepted

## Context

US-0024 requires a read-only way to detect when project memory artifacts
(`state`, `decisions`, `backlog`, `acceptance`, handoffs, sprint status) no
longer match repository/code reality, especially when coding happened outside
the normal workflow loop.

The solution must remain minimal, non-blocking, and clearly separate this
problem from US-0017 (template drift between active files and `template/`).

## Options

### Option A: Extend `/verify-work`

Add memory drift checks inside `/verify-work`.

- Pros: reuses an existing QA-oriented phase.
- Cons: ties drift checking to UAT timing, conflates acceptance verification with
  memory hygiene, and makes early/pre-handoff audits less natural.

### Option B: Extend `/map-codebase`

Add memory drift checks to `/map-codebase`.

- Pros: command already inspects repository structure.
- Cons: `/map-codebase` is baseline/discovery oriented, not recurring operational
  hygiene. Scope expansion would blur command intent.

### Option C: Add dedicated `/memory-audit` command

Create a focused read-only command that emits a drift report artifact and
guidance.

- Pros: clear semantics, simplest operational model, run-anytime behavior,
  strongest fit to acceptance criteria.
- Cons: introduces one additional command to maintain.

## Decision

**Option C is accepted.** Implement a dedicated `/memory-audit` command that:

1. Runs read-only checks against repository signals and memory artifacts.
2. Writes `docs/engineering/memory-drift-report.md`.
3. Separates findings into:
   - **Memory drift** (US-0024 scope)
   - **Template drift** (reference-only, routed to US-0017)
4. Provides non-blocking guidance and returns success unless invocation fails.

## Consequences

- Command boundaries stay clean:
  - `/map-codebase` remains architecture/dependency mapping.
  - `/verify-work` remains UAT/acceptance verification.
- Teams gain a lightweight hygiene checkpoint before handoff, QA, and release.
- Heuristics may produce false positives/negatives initially; severity tiers and
  clear evidence in the report are required to preserve trust.
