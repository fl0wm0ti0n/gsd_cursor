# DEC-0032: Installer Ownership Manifest and Complete Clean-Repo Coverage

- Date: 2026-03-11
- Status: Accepted
- Related story: US-0050
- Research refs: R-0024, R-0025

## Context

Real-world installs reported partial cleanup after `--clean-repo` and starter
artifacts that looked like inherited project memory. Current per-installer path
lists are drift-prone and do not provide one deterministic ownership contract
across installer implementations.

## Decision

1. Define one canonical installer-ownership manifest (single source of truth)
   for managed paths/files.
2. Make all installer entry points (`installer.ps1`, `installer.sh`,
   `installer.py`) consume this same ownership contract for install and clean
   operations.
3. Expand clean-repo behavior to remove all installer-owned workflow artifacts
   in scope, while remaining explicitly non-destructive for non-owned project
   files.
4. Enforce starter-template neutrality for engineering artifact placeholders:
   remove seeded historical operational rows from starter files.
5. Add install/clean regression tests for fresh install, complete cleanup, and
   reinstall-baseline parity.

## Consequences

- Cleanup behavior becomes deterministic and parity-safe across installers.
- Template hygiene improves first-time trust in new repos.
- Ownership manifest introduces one additional artifact to maintain, but reduces
  long-term drift and defects.
