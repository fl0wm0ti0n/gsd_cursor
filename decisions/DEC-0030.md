# DEC-0030: Optional Per-Feature User Guide Mode

- Date: 2026-03-02
- Status: Accepted
- Related story: US-0032
- Research refs: R-0021, R-0022

## Context

Teams want end-user-facing how-to guides for each feature, but not every repo
should be forced to maintain them by default. US-0032 must provide a
docs-as-code path for these guides that is optional, structurally testable, and
zero-overhead when disabled.

## Decision

1. Add a single global mode flag in `.cursor/scratchpad.md`:
   - `USER_GUIDE_MODE=0|1` (default `0`).
2. Define a canonical user-guide location and naming scheme:
   - Root directory: `docs/user-guides/`
   - One file per feature story: `docs/user-guides/US-xxxx.md`.
3. Standardize a minimal, structurally testable schema for each guide:
   - Sections: Purpose, Prerequisites, Usage steps, Example, Limitations,
     Troubleshooting.
4. When `USER_GUIDE_MODE=0`, intake/architecture/sprint/execute/qa/release add
   no required user-guide steps or gates; existing workflows remain unchanged.
5. When `USER_GUIDE_MODE=1`, each in-scope feature story must have a
   corresponding guide file; `/sprint-plan` includes guide tasks, and `/execute`
   updates guides in the same change as feature code.
6. Wire an optional, mode-conditioned release gate:
   - `/release` performs structural validation for in-scope stories when
     `USER_GUIDE_MODE=1`.
   - On missing or structurally incomplete guides, block release with reason
     code `USER_GUIDE_INCOMPLETE` and remediation pointing to the missing file
     or sections.
7. Keep user guides strictly end-user facing and separate from spec-pack
   artifacts (Design Concept, CRS, Technical Spec); the two optional modes
   (`SPEC_PACK_MODE`, `USER_GUIDE_MODE`) can be enabled independently.

## Consequences

- Provides a simple, optional docs-as-code pathway for per-feature user guides
  with deterministic structure and validation.
- Keeps default workflows lightweight in repos that do not want user-guide
  enforcement.
- Aligns with existing optional-mode patterns (`SPEC_PACK_MODE`,
  `CROSS_REPO_OBSERVABILITY`, `COMPONENT_SCOPE_MODE`) by using a single
  scratchpad flag and canonical artifact locations.
- Introduces a new optional release gate that implementation must wire into
  `/release` behavior when `USER_GUIDE_MODE=1`.
