# DEC-0021: Deterministic Backlog Reconciliation at Release Boundary

## Status

Accepted

## Context

Recent workflow runs produced a contradiction: sprint release artifacts showed a
completed/released state while `docs/product/backlog.md` still reported related
story status/ACs as incomplete. This creates audit ambiguity and weakens
artifact-first memory.

US-0043 requires this mismatch to be prevented by workflow contract, not manual
cleanup.

## Decision Drivers

- Keep backlog status and AC state consistent with canonical release evidence.
- Prevent silent drift recurrence after sprint release finalization.
- Preserve safe defaults (fail closed on contradictory evidence).
- Limit mutation scope to target sprint stories only.
- Keep behavior deterministic and testable.

## Options Considered

### Option A: Manual curator reconciliation only

- **Pros**: minimal implementation work.
- **Cons**: drift can recur; non-deterministic; weak auditability.

### Option B: Read-only drift detection only

- **Pros**: low risk, no automatic mutation.
- **Cons**: still relies on manual fixes; contradiction can persist.

### Option C: Deterministic release-boundary reconciliation (chosen)

- **Pros**:
  - closes the loop automatically when release evidence is complete
  - provides fail-safe blocking on contradictions
  - supports deterministic reason-code-based remediation
- **Cons**:
  - adds release-boundary logic and regression requirements
  - requires precise target-story scoping to avoid overreach

## Decision

Adopt Option C:

1. At release finalization boundary, reconcile target sprint-linked backlog
   stories using canonical evidence precedence.
2. When evidence is PASS, transition target story status to `DONE` and reconcile
   AC checkboxes to checked.
3. When contradictory evidence is detected, fail safe with reason code
   `BACKLOG_STATUS_DRIFT` and do not mutate unrelated backlog entries.

## Consequences

### Positive

- Backlog and release artifacts remain synchronized after release.
- Reduced manual correction overhead and reduced memory drift risk.
- Deterministic remediation path via reason codes and evidence links.

### Negative

- Release flow contract and tests become more strict.
- Parsing/scope logic for backlog story blocks must be precise.

### Neutral / Follow-up

- This does not replace broader traceability governance (`US-0025`); it enforces
  consistency at release boundary for target sprint stories.

## Evidence precedence

1. `handoffs/release_queue.md` target sprint row
2. `handoffs/releases/Sxxxx-release-notes.md`
3. `sprints/Sxxxx/qa-findings.md`
4. `sprints/Sxxxx/uat.json` and `sprints/Sxxxx/uat.md`
5. `sprints/Sxxxx/release-findings.md` (if present)

## Failure-safe policy

- Fail closed on contradictory/incomplete evidence.
- Emit deterministic reason code `BACKLOG_STATUS_DRIFT`.
- Include remediation guidance and evidence references.
- Do not mutate unrelated stories.
