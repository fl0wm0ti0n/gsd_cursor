# DEC-0009: Artifact Lifecycle Taxonomy and Phase Ownership

## Status: Accepted

## Context

US-0025 (traceability), US-0026 (milestone lifecycle), and US-0027 (UAT
lifecycle) all address the same underlying gap: artifact files exist as
placeholders but have no documented lifecycle governing when they must be
populated, who owns each transition, and what minimum content qualifies as
"done."

The PO recommended a shared taxonomy to avoid three separate, potentially
inconsistent lifecycle models. This decision establishes that shared foundation.

## Options

### Option A: Per-story lifecycle rules (three separate models)

Each story defines its own states, ownership, and evidence rules independently.

- Pros: each story is self-contained.
- Cons: likely inconsistencies across artifact types, harder to teach and
  maintain, redundant concepts.

### Option B: Shared artifact lifecycle taxonomy (one model, three applications)

Define a common set of artifact states, a phase-ownership matrix, and minimum
evidence rules. Each story applies the taxonomy to its specific artifacts.

- Pros: consistent mental model, single reference point, reduced documentation.
- Cons: shared model must be general enough to cover all artifact types.

## Decision

**Option B is accepted.** A single artifact lifecycle taxonomy governs all
project artifacts. Story-specific rules reference the taxonomy rather than
inventing independent models.

## Taxonomy

### Artifact states

| State | Meaning |
|-------|---------|
| **placeholder** | Artifact file exists with valid structure but minimal/no real content. Created during planning phases. Acceptable during early lifecycle. |
| **populated** | Artifact contains real content meeting minimum field requirements for its type. Filled during execution or verification phases. |
| **verified** | Artifact content has been reviewed and confirmed accurate by a downstream role. Checked during QA, verify-work, or release phases. |

### Phase-ownership matrix

| Artifact | Placeholder owner | Population owner | Verification owner |
|----------|------------------|------------------|--------------------|
| sprint tasks (`tasks.md`) | Tech Lead (`/sprint-plan`) | Dev (`/execute`) | QA (`/qa`) |
| UAT (`uat.json`, `uat.md`) | Tech Lead (`/sprint-plan`) | QA (`/verify-work`) | Release (`/release`) |
| milestone (`milestone.json`, `phases.json`) | Tech Lead (`/milestone-start`) | Tech Lead (during `/sprint-plan`) | Release (`/milestone-complete`) |
| milestone progress (`progress.md`) | Tech Lead (`/milestone-start`) | Tech Lead + Curator (ongoing) | Release (`/milestone-complete`) |
| milestone summary (`summary.md`) | — (not created until completion) | Release (`/milestone-complete`) | — |
| traceability index (`state.md` section) | Tech Lead (`/sprint-plan`) | QA (`/verify-work`) | Curator (`/refresh-context`) |
| handoffs (`handoffs/*.md`) | Phase sender | — | Phase receiver |

### Minimum evidence rules

- **Before sprint completion**: all sprint artifacts must be at least
  **populated** (tasks done, UAT steps recorded with results).
- **Before milestone completion**: all milestone artifacts must be
  **populated**, and downstream verification must confirm **verified** state
  for UAT and traceability.
- **Placeholder artifacts are acceptable** only during planning phases. Once
  execution begins, placeholders must be populated before the phase that owns
  population completes.

### Milestone lifecycle states (US-0026 application)

| State | Entry condition | Required artifact content | Exit condition |
|-------|----------------|--------------------------|----------------|
| **created** | `/milestone-start` run | `milestone.json`: id + status. Name/goal may be draft. `phases.json`: at least intake phase. `progress.md`: initialized. | Sprint planning begins. |
| **active** | First sprint under milestone starts | `milestone.json`: name, goal, scope all populated. `phases.json`: phases reflect actual work. `progress.md`: updated per sprint. | All planned sprints complete. |
| **in-review** | All sprints done, UAT passing | `progress.md`: all sprints show done. UAT artifacts verified. | `/milestone-complete` run. |
| **completed** | `/milestone-complete` run | `summary.md`: finalized with outcomes. `state.md`: updated. | — |
| **cancelled** | Milestone abandoned | `summary.md`: records cancellation reason. | — |

### UAT lifecycle (US-0027 application)

| Phase | Owner | UAT artifact state | Content |
|-------|-------|--------------------|---------|
| `/sprint-plan` | Tech Lead | placeholder | `uat.json`: sprint ID, empty steps. `uat.md`: header + target stories/ACs listed, no results. |
| `/verify-work` | QA | populated | `uat.json`: steps derived from acceptance criteria, pass/fail counts. `uat.md`: each step with result, summary. |
| `/release` | Release | verified | Release agent confirms UAT is populated and passing as gate. |

## Consequences

- All artifact lifecycle conversations share common vocabulary (placeholder →
  populated → verified).
- Phase ownership is explicit and auditable via the matrix.
- Minimum evidence rules prevent "placeholder forever" drift without requiring
  hard enforcement logic — the AI reads and follows the taxonomy.
- Stories US-0025, US-0026, US-0027 reference this taxonomy rather than
  defining ad-hoc rules.
