# DEC-0050: Mandatory intake question packs and fail-closed coverage gate

- Date: 2026-03-17
- Status: Accepted
- Story: `US-0068`

## Context

`US-0068` addresses a deterministic intake-quality gap: adaptive questioning
exists, but there is no enforced minimum required topic coverage before
persisting backlog/acceptance artifacts. Research (`R-0045`) and discovery
handoff evidence confirm two distinct intake contexts must be supported without
allowing coverage bypass: first-intake (comprehensive) and small-intake
(compact follow-up).

## Decision

Adopt mandatory deterministic intake question packs with an explicit fail-closed
persistence gate and structured coverage evidence.

Decision details:

1. Two canonical packs are mandatory:
   - `first-intake-pack` (comprehensive required coverage):
     - users/problem
     - runtime target/environment
     - language/framework/runtime
     - architecture preference
     - UI/design expectations
     - security/compliance
     - non-functional priorities
     - scope/timeline
   - `small-intake-pack` (compact required coverage):
     - outcome/success criteria
     - impacted components
     - constraints/compatibility risks
     - required tests/acceptance checks
     - done definition
2. Each pack must use deterministic topic IDs plus required/optional
   classification so coverage checks are machine-verifiable.
3. Intake persistence is blocked by default unless required coverage is complete
   or bounded assumptions are explicitly user-confirmed.
4. Low-touch mode remains available but cannot bypass critical required safety
   coverage.
5. Intake outputs must persist deterministic evidence:
   - `asked_topics`
   - `missing_topics`
   - `assumptions_confirmed`
6. Missing required coverage must fail closed with deterministic diagnostics:
   - `INTAKE_REQUIRED_TOPIC_MISSING`
   - `INTAKE_REQUIRED_PACK_INCOMPLETE`
   - `INTAKE_ASSUMPTION_CONFIRMATION_REQUIRED`
   - `INTAKE_PERSISTENCE_BLOCKED`

## Alternatives considered

1. Keep adaptive-only questioning with no fixed minimum coverage:
   - rejected because missing critical details can still be persisted silently.
2. Single unified questionnaire for all intake sizes:
   - rejected because it adds unnecessary friction for small follow-up scopes.
3. Warning-only persistence behavior for missing required topics:
   - rejected because it breaks deterministic intake quality and downstream trust.

## Consequences

- Intake quality and downstream planning trust become deterministic and auditable.
- Some intakes will require additional clarification before artifact persistence.
- Scope remains intake-policy-only for `US-0068`; runtime autopilot, generated
  test scaffolding, and release operator hints remain governed by
  `US-0065`/`US-0066`/`US-0067`.
