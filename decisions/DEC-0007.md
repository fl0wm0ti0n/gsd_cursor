# DEC-0007: Fresh Subagent Context Per Phase

## Status: Accepted

## Context

The workflow relies on role-based phases (PO, Tech Lead, Dev, QA, Release,
Curator). Running multiple phases in one long conversation can blur role
independence, especially in execute/qa loops where unbiased review is critical.
Instruction-only guidance like "ignore prior chat" is not a hard isolation
boundary.

## Options

### Option A: Keep role switching in one conversation

Continue current behavior and rely on prompts/rules to ask each role to behave
independently.

### Option B: Enforce fresh subagent context for every phase

Each phase starts in a new subagent/chat context. Memory transfer occurs only
via handoff and artifact files.

## Decision

**Option B** is accepted. Every phase handoff requires a fresh subagent
boundary. `/auto` becomes orchestration-only and must spawn a new subagent for
each phase, including each execute/qa loop iteration.

## Consequences

- Better independence between producer/reviewer roles.
- Handoffs become the explicit, auditable memory channel.
- Slightly more orchestration overhead, but improved reliability for long-lived
  projects and pause/resume flows.
