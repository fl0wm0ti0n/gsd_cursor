## §1 — Tier semantics

Three operator-facing tiers for LLM model strength per lifecycle phase:

| Tier | Intent | Examples |
|------|--------|----------|
| **`cheap`** | Minimum viable model — context pruning, archival, light ceremony | `curator`, `refresh-context`, `memory-audit` |
| **`balanced`** | Moderate strength — intake, discovery, release ceremony | `po`, `release`, `plan-verify` |
| **`strong`** | Full strength — architecture, implementation, verification | `tech-lead`, `dev`, `qa`, `security` |

**Rationale**: Three tiers map to operator intuition ("light/medium/heavy") without requiring knowledge of vendor model IDs. Tiers are stable across Cursor model renames.

## §2 — Tier→alias resolution

| Tier | Cursor alias | Implementation |
|------|-------------|----------------|
| **`cheap`** | **`fast`** | `model: fast` in agent frontmatter |
| **`balanced`** | **`inherit`** | `model: inherit` in agent frontmatter |
| **`strong`** | *(omit)* | No `model:` field — Cursor default resolution (parent or strongest) |

**Rationale (R-0088 Q1)**: Cursor's public API offers only `inherit` and `fast` as stable non-vendor aliases. No stable middle-tier alias exists as of 2026-06. `inherit` is the only stable non-vendor alias; introducing a framework-specific middle alias would require materializer translation and add no value. `strong` omits the field so Cursor's default resolution applies.

**`auto`** orchestrator phase always inherits parent model (no tier override).

## §3 — Local catalog schema + resolver contract

### Schema v1

```json
{
  "schema_version": 1,
  "tiers": {
    "cheap": "<slug>",
    "balanced": "<slug>",
    "strong": "<slug>"
  },
  "notes": "optional free-text"
}
```

- Path: **`.cursor/model-catalog.local.json`** (gitignored)
- Example: **`.cursor/model-catalog.local.example.json`** (committed, placeholder values)
- All three tier keys required; values are opaque vendor slug strings

### Resolver algorithm

1. Read `MODEL_TIER_<PHASE>` from merged scratchpad → tier value (`cheap`|`balanced`|`strong`)
2. If `MODEL_RESOLVE=alias_only` (default): use built-in mapping (§2)
3. If `MODEL_RESOLVE=local_catalog`: load catalog JSON → lookup tier key → slug
4. If key missing in catalog → `MODEL_SLUG_UNKNOWN` fail-closed
5. If `MODEL_FALLBACK=inherit` and catalog lookup fails → emit `MODEL_RESOLVE_FALLBACK` reason + use `inherit`
6. Unknown tier value → `MODEL_TIER_INVALID` fail-closed
7. Malformed catalog JSON → `MODEL_CATALOG_INVALID` fail-closed + remediation text

## §4 — Template agent defaults

| Agent role | Tier | `model:` field |
|-----------|------|----------------|
| `curator` | cheap | `model: fast` |
| `po` | balanced | `model: inherit` |
| `release` | balanced | `model: inherit` |
| `tech-lead` | strong | *(omit)* |
| `dev` | strong | *(omit)* |
| `qa` | strong | *(omit)* |
| `security` | strong | *(omit)* |

**Forbidden in `template/.cursor/agents/`**: hardcoded vendor slugs (`composer-*`, `claude-*`, `gpt-*`, `opus-*`). Template files use aliases only (`fast`/`inherit`/omit).

Materializer applies scratchpad overrides only when `MODEL_RESOLVE=local_catalog`.

## §5 — Provider mode semantics

`MODEL_PROVIDER_MODE=cursor|api` documented in `docs/engineering/runbook.md` + `auto-orchestration-reference.md`:

| Mode | Description |
|------|-------------|
| **`cursor`** (default) | All subagents route through Cursor-managed infrastructure; tier aliases work as designed |
| **`api`** | Operator uses BYOK via Cursor Settings → Models → API Key |

**Known limitation (confirmed 2026-06)**: Subagents do NOT inherit custom API keys or base URLs — they always bill against Cursor plan. Workaround: use parent model + `inherit`, or run phases manually in separate chats.

## §6 — Orthogonality vs TOKEN_PROFILE (DEC-0062)

**`MODEL_TIER`** selects LLM model strength (which model runs). **`TOKEN_PROFILE`** selects context-pack breadth / token cost (how much context the model sees). These are **independent axes** — a `strong` tier with `lean` profile is valid; a `cheap` tier with `full` profile is valid. Neither substitutes for the other. Documentation must state non-substitution explicitly.

## §7 — Fail-closed reason codes

| Code | Trigger |
|------|---------|
| **`MODEL_TIER_INVALID`** | Unknown tier value (not `cheap`/`balanced`/`strong`) |
| **`MODEL_CATALOG_INVALID`** | Malformed catalog JSON (parse error, missing `schema_version`) |
| **`MODEL_SLUG_UNKNOWN`** | Tier key missing from catalog when `MODEL_RESOLVE=local_catalog` |
| **`MODEL_RESOLVE_FALLBACK`** | Catalog lookup failed but `MODEL_FALLBACK=inherit` → emit reason + fallback |

| Risk | Mitigation |
|------|------------|
| **R1** Cursor subagent BYOK limitation limits api-only mode value | Document limitation; provide workaround recipes |

## §10 — Scratchpad keys

| Key | Default | Role |
|-----|---------|------|
| `MODEL_TIER_DEFAULT` | `balanced` | Fallback when phase-specific key absent |
| `MODEL_TIER_<PHASE>` | *(per matrix)* | Per-phase tier override |
| `MODEL_CATALOG` | `.cursor/model-catalog.local.json` | Path to local catalog |
| `MODEL_RESOLVE` | `alias_only` | Resolution strategy (`alias_only` \| `local_catalog`) |
| `MODEL_FALLBACK` | `inherit` | Fallback when catalog lookup fails |
| `MODEL_PROVIDER_MODE` | `cursor` | Provider routing (`cursor` \| `api`) |
