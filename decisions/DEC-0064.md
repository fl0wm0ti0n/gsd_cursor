# DEC-0064: Deterministic first-intake full-plan coverage gate (US-0081)

- Date: 2026-03-31
- Status: Accepted
- Story: `US-0081`
- Research: `R-0059`
- Supersedes: none

## Context

First/new/broad intake can currently decompose into a narrow story set without explicit evidence that all major plan areas were accounted for. This creates silent omission risk and weakens operator trust. `US-0081` requires deterministic complete-plan accounting before persistence while preserving bounded decomposition and backlog status authority (`US-0045`).

## Options considered

1. **Guidance-only decomposition checks** - Rejected: non-enforceable and non-deterministic.
2. **Auto-expand every plan area into immediate stories** - Rejected: over-complex and can generate low-quality backlog noise.
3. **Mandatory coverage map gate (chosen)** - Require normalized plan-area inventory and total mapping to `story_ids[]` or `deferred_ref` before persistence.

## Decision

### 1. Gate trigger

For first/new/broad intake, persistence MUST pass a complete-plan coverage validator before any backlog mutation.

### 2. Data contract (normative additions)

Intake evidence MUST include:

- `plan_area_inventory[]` with stable `plan_area_id`
- `plan_area_coverage[]` where each `plan_area_id` maps to exactly one of:
  - non-empty `story_ids[]`, or
  - `deferred_ref` (+ bounded `deferred_reason`)
- derived `coverage_complete=true` to allow persistence

Invariant rules:

- `plan_area_id` uniqueness in both arrays
- one-to-one coverage row per inventory row
- xor rule: `story_ids` xor `deferred_ref`
- referenced `story_ids` must exist in the candidate intake write set

### 3. Fail-closed diagnostics

All coverage failures MUST raise umbrella `INTAKE_PERSISTENCE_BLOCKED` with deterministic subcodes:

- `INTAKE_PLAN_COVERAGE_MISSING`
- `INTAKE_PLAN_AREA_ID_INVALID`
- `INTAKE_PLAN_COVERAGE_CONTRACT_INVALID`
- `INTAKE_PLAN_DEFERRED_REF_MISSING`

### 4. Verification policy

Implementation MUST include regression coverage for:

- pass: complete mapping
- pass: justified defer mapping
- fail: uncovered plan area
- fail: malformed ids/contract xor violation
- guided and low-touch parity enforcement
- active/template parity for intake command, PO guidance, validator fixtures

## Consequences

- Intake persistence becomes deterministic and auditable for broad scope.
- Additional schema/validator strictness may surface more actionable intake blocks early.
- Bounded decomposition remains allowed, but silent omission paths are removed.

## Risks

| Risk | Mitigation |
|------|------------|
| False-positive blocking from noisy area extraction | Stable normalization and bounded major-area policy in architecture/tests |
| Contract complexity increases maintenance cost | Keep minimal schema and single validator path |
| Template drift | Add parity fixtures and run in standard test runners |

## Decision outcome

- Approved option: **3** (mandatory deterministic coverage-map gate)
