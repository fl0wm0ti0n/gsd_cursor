# DEC-0048: Deterministic generated-test scaffolding and auto-run contract for app projects

- Date: 2026-03-16
- Status: Accepted
- Story: `US-0066`

## Context

Generated-repo workflows can reach QA/release gates without baseline runnable
tests when a project starts from an app scaffold that has no tests yet.
Research (`R-0043`) confirms a minimal cross-stack baseline scaffold contract is
needed so test evidence is reproducible, non-destructive, and auto-executed in
`/qa`.

## Decision

Adopt a deterministic baseline test-scaffolding contract with mandatory auto-run
evidence for generated app projects.

Decision details:

1. Stack/project detection is mandatory for Node, Python, Go, Java, and .NET.
2. `/execute` generates only missing baseline test assets and records generated
   paths in execution evidence.
3. `docs/engineering/runbook.md` `TEST_COMMAND` is updated only when a runnable
   baseline command is missing/unset for the resolved stack profile.
4. `/qa` must execute baseline tests automatically and record:
   - command executed,
   - pass/fail result,
   - output/evidence reference.
5. Unresolved or unsupported stack generation fails closed with deterministic
   diagnostics:
   - `TEST_SCAFFOLD_STACK_UNRESOLVED`
   - `TEST_SCAFFOLD_UNSUPPORTED_STACK`
   - `TEST_SCAFFOLD_GENERATION_FAILED`
6. Non-destructive precedence is explicit:
   - existing user-authored tests/config/commands are preserved,
   - generated baseline fills missing assets only.
7. Reruns are idempotent:
   - stable scaffold paths/conventions,
   - no duplicate file churn or oscillating command rewrites.
8. Runtime truth remains governed by `US-0065`:
   - passing static baseline tests does not bypass runtime-autopilot verdicts.

## Alternatives considered

1. Optional best-effort scaffold generation:
   - rejected because it allows silent no-test paths and weakens QA evidence.
2. Single generic scaffold template for all stacks:
   - rejected because conventions differ and would produce fragile baselines.
3. Full plugin-based extensibility in first iteration:
   - deferred as over-complex for current acceptance scope; deterministic built-in
     stack profiles are the simpler viable baseline.

## Consequences

- New app projects gain immediate runnable baseline tests and clearer QA evidence.
- Some polyglot/atypical repos may fail faster on unresolved stack detection.
- First iteration remains intentionally minimal (baseline scaffolds) and avoids
  advanced framework-specific architecture.
