# DEC-0034: Optional Fresh-Project ID Namespace Bootstrap

- Date: 2026-03-11
- Status: Accepted
- Related story: US-0052
- Research refs: R-0024, R-0025

## Context

Fresh-project teams may expect first generated IDs to start at `0001`, while
existing repositories require stable highest-existing-ID continuation to avoid
collisions. A single global behavior does not satisfy both needs.

## Decision

1. Introduce an explicit optional bootstrap mode for ID namespaces (default off).
2. Bootstrap eligibility is determined by deterministic freshness checks across
   canonical artifacts (no existing US/DEC/R IDs).
3. If eligible and bootstrap is enabled, ID generation starts at `US-0001`,
   `DEC-0001`, and `R-0001`.
4. If repository is non-fresh, continue from highest existing ID and do not
   rewrite or renumber historical artifacts.
5. Emit clear diagnostics when bootstrap is requested but freshness criteria fail.

## Consequences

- Fresh-project UX becomes explicit and controllable.
- Backward compatibility is preserved for existing repositories.
- Additional eligibility checks and tests are required to ensure collision safety.
