# DEC-0044: Remote Runtime Connectivity Contract for QA/Release/Publish

- Status: Accepted
- Date: 2026-03-15
- Story: US-0064
- Related: DEC-0036, DEC-0039, DEC-0043

## Context

Release targets already support configurable publish types (`npm|choco|brew|git|
docker|cloud|custom|ssh`), but operator-safe runtime connection metadata and
remote phase consumption rules are incomplete. Users need deterministic
domain/ip/port/ingress context, Docker-over-SSH options, and canonical
connectivity reporting for release/QA/debug workflows.

## Decision

1. Extend `docs/engineering/release-targets.json` with deterministic runtime
   connectivity metadata:
   - `runtime.mode` (`local|remote`)
   - endpoint fields (`domainEnv|ipEnv|hostEnv`, `port`, `protocol`)
   - optional Traefik/ingress fields
   - optional `dockerOverSsh` contract for ssh targets.
2. Enforce phase-level validation and fail-safe diagnostics:
   - `REMOTE_CONNECTIVITY_CONFIG_INVALID`
   - `RUNTIME_CONNECTIVITY_DOC_WRITE_FAILED`
3. Require release/QA/execute remote-aware context handling when configured.
4. Persist canonical operator-safe endpoint guidance in
   `docs/engineering/runtime-connectivity.md`.
5. Preserve secret safety: env-reference-only sensitive fields and redacted
   operator outputs.

## Consequences

- Operators get deterministic host/connect guidance for local and remote targets.
- Remote QA/debug and release guidance become reproducible and auditable.
- Existing mandatory release and quality gates remain unchanged.
