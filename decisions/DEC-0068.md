# DEC-0068: POSIX-safe installer shell startup contract for CLI `sh` invocation (BUG-0004)

- Date: 2026-04-03
- Status: Accepted
- Bug: `BUG-0004`
- Research: `R-0063`
- Supersedes: none

## Context

`BUG-0004` reports immediate installer failure in Linux shell environments:

`/usr/lib/node_modules/its-magic/installer.sh: 2: set: Illegal option -`

Research (`R-0063`) confirms that Unix CLI flow in `bin/its-magic.js` invokes the installer as `sh installer.sh ...`, so `installer.sh` must remain valid for POSIX `sh` implementations (such as `dash`) and cannot rely on bash-only shell option semantics.

## Options considered

1. **Force bash invocation in CLI (`bash installer.sh`)** - Rejected: adds runtime dependency and weakens portability in minimal environments.
2. **Hybrid shell detection with dynamic launcher branching** - Rejected: more complexity than needed for this defect scope.
3. **Keep `sh` invocation and enforce POSIX-safe installer startup semantics (chosen)** - Minimal, deterministic, and aligned with current CLI/test contract.

## Decision

### 1. Invocation contract remains `sh` on Unix (normative)

- `bin/its-magic.js` keeps Unix installer execution path via `spawnSync("sh", [installer.sh, ...])`.
- We do not introduce a bash dependency for baseline install flows.

### 2. Installer startup option contract (normative)

- `installer.sh` startup must use POSIX-safe shell options only.
- Bash-only `set` flags (for example `pipefail`) are forbidden in unconditional startup path.
- Baseline safety contract for startup is `set -e` plus explicit command checks where needed.

### 3. Diagnostics and fail behavior

- On shell-option incompatibility, behavior must not fail with ambiguous startup crashes.
- Regression checks must catch shell-incompatible edits before release.

### 4. Regression and parity obligations (normative)

Implementation must include deterministic coverage for:

- direct shell invocation path:
  - `sh installer.sh --target <tmp> --mode missing --create`
  - `sh installer.sh --target <tmp> --mode upgrade`
- CLI Unix path:
  - `node bin/its-magic.js --target <tmp> --mode missing --create`
- non-regression of existing install completeness checks and framework/user-data boundaries.

### 5. Scope boundary

- This decision addresses shell startup compatibility only.
- It does not redefine bug routing, resume-source precedence, or installer payload ownership contracts.

## Consequences

- Installer behavior becomes robust across `/bin/sh` variants used in containerized and distro-default environments.
- CLI contract remains simple and portable.
- Future shell-option hardening must remain POSIX-compatible unless a separate decision explicitly revises launcher assumptions.

## Risks

| Risk | Mitigation |
|------|------------|
| Future bash-only edit reintroduces startup failure | Add explicit `sh`-path regression checks in shared test harness. |
| False confidence from single-shell local testing | Keep deterministic CLI + direct `sh` smoke coverage in CI/test scripts. |
| Pressure to add bash features later | Require explicit architectural decision before changing Unix launcher contract. |

## Decision outcome

- Approved option: **3** (POSIX-safe startup semantics under existing `sh` invocation contract)
- Approval source: architecture phase (`tech-lead`), `orchestrator_run_id=auto-20260403-01`
