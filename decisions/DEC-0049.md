# DEC-0049: Deterministic release operator Run/Connect/Verify hints contract

- Date: 2026-03-16
- Status: Accepted
- Story: `US-0067`

## Context

Release outputs can pass quality gates while still lacking operator-ready startup
and connectivity instructions. Research (`R-0044`) confirms the need for a
deterministic contract that keeps sprint release notes actionable, concise, and
rerun-stable without expanding into deployment-engine orchestration scope.

## Decision

Adopt a deterministic release-operator hints contract with fail-closed
finalization checks for `US-0067`.

Decision details:

1. Canonical sprint release notes must include fixed-order sections:
   `Run -> Connect -> Verify -> Credentials (env-ref only) -> Known Issues`.
2. Required fields are mandatory for release finalization:
   - startup command(s),
   - runtime mode (`local|remote`),
   - endpoint (`url/ip:port`),
   - expected health signal,
   - known issues.
3. Credentials/auth guidance must reference env variable names and expected
   source locations only; inline secrets are prohibited.
4. Finalization fails closed on missing or ambiguous required fields with
   deterministic reason-code remediation.
5. `handoffs/release_notes.md` remains a concise latest-pointer surface linked to
   canonical per-sprint release notes, with deterministic run/connect summary
   parity.
6. Local/remote runtime context must be explicit and aligned with
   `docs/engineering/runtime-connectivity.md` when that contract exists.

Deterministic reason-code baseline:

- `RELEASE_OPERATOR_HINTS_MISSING_REQUIRED_FIELD`
- `RELEASE_OPERATOR_HINTS_AMBIGUOUS_FIELD`
- `RELEASE_OPERATOR_HINTS_RUNTIME_CONTEXT_MISSING`
- `RELEASE_OPERATOR_HINTS_CREDENTIALS_POLICY_VIOLATION`

## Alternatives considered

1. Free-form operator hints without fixed schema:
   - rejected because reruns become inconsistent and harder to audit.
2. Warning-only validation for missing fields:
   - rejected because release could complete without actionable operator guidance.
3. Inline credentials in release notes:
   - rejected due to direct secret-exposure risk.

## Consequences

- Release artifacts become operator-actionable and stable across reruns.
- Some releases will fail earlier when required run/connect details are missing.
- Scope remains strictly release-operator hints and does not alter runtime
  verification ownership (`US-0065`) or test scaffold ownership (`US-0066`).
