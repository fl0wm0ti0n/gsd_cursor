# DEC-0067: Explicit topic-scoped intake delegation with fail-closed validator semantics (US-0083)

- Date: 2026-03-31
- Status: Accepted
- Story: `US-0083`
- Research: `R-0062`
- Supersedes: none

## Context

`US-0083` requires a non-blocking path when users explicitly delegate unresolved required intake decisions, while preserving deterministic fail-closed behavior for non-delegated gaps. Current intake evidence validation (`DEC-0060`) only accepts `satisfied_by=answer_ref|assumption_confirmation_ref`, so unresolved required topics always block persistence. We need the simplest extension that preserves auditability, guided/low-touch parity, and canonical status authority (`US-0045`).

## Options considered

1. **Keep strict-only required coverage (no delegation branch)** - Rejected: safe but fails story intent (`AC-2`, `AC-3`).
2. **Global delegation toggle for missing topics** - Rejected: broad bypass risk and weaker topic-level auditability.
3. **Topic-scoped branch in existing `topic_coverage[]` rows (chosen)** - Extend `satisfied_by` with `delegation_ref` and require deterministic evidence fields.

## Decision

### 1. Delegation schema extension (normative)

- `topic_coverage[].satisfied_by` allows:
  - `answer_ref`
  - `assumption_confirmation_ref`
  - `delegation_ref`
- When `satisfied_by=delegation_ref`, the row MUST include:
  - `delegation_scope`
  - `delegation_rationale`
  - `delegation_confidence` (`low|medium|high`)
- Row MUST also retain `ref` (`ie:`), `quoted_user_text`, and run/turn metadata already required by `DEC-0060` binding rules.

### 2. Validator branch contract (normative)

- **Non-delegated unresolved required topic**: unchanged fail-closed behavior (`INTAKE_REQUIRED_TOPIC_MISSING`; optional `INTAKE_REQUIRED_PACK_INCOMPLETE`; umbrella `INTAKE_PERSISTENCE_BLOCKED`).
- **Delegated required topic with complete evidence**: treated as covered and eligible for persistence.
- **Delegated required topic with missing/malformed evidence**: fail closed under deterministic delegation-specific reason codes and `INTAKE_PERSISTENCE_BLOCKED`.

### 3. Delegation reason codes (normative)

- `INTAKE_DELEGATION_EVIDENCE_MISSING`
- `INTAKE_DELEGATION_EVIDENCE_INVALID`
- `INTAKE_PERSISTENCE_BLOCKED` (umbrella retained)

Diagnostics MUST name the topic key and missing/invalid field(s), with remediation text that requests explicit user delegation evidence (not inferred defaults).

### 4. Evidence integrity and scope

- Delegation is **topic-scoped only**; no intake-level global bypass flag is allowed.
- `ie:` validation remains deterministic over sorted-key canonical JSON and MUST include delegated branch input values, preventing opaque bypass tokens.

### 5. Mode and parity invariants

- Guided and low-touch modes use the same validation pipeline; no delegation-only mode bypass.
- Active + `template/` parity is required for command/rule/docs/test surfaces that define or validate intake evidence schema.

### 6. Status authority boundary

- This decision does not alter lifecycle status semantics.
- Story status remains canonical in `docs/product/backlog.md` (`US-0045`).

## Consequences

- Intake can proceed when users explicitly delegate bounded unresolved topics with auditable evidence.
- Existing strict behavior remains intact for non-delegated required-topic gaps.
- Sprint implementation is focused: command/rule/schema updates, validator branching, deterministic diagnostics, parity fixtures.

## Risks

| Risk | Mitigation |
|------|------------|
| Implicit delegation bypass | Require explicit `delegation_ref`, delegation fields, and `ie:`-bound quoted user text. |
| Schema divergence across active/template | Add parity checks and mirrored fixtures in sprint scope. |
| Overly complex delegation payload | Keep minimal bounded metadata (`scope`, `rationale`, `confidence`). |
| Downstream misinterpretation of delegated topics | Persist explicit delegated markers and rationale for later revisit. |

## Decision outcome

- Approved option: **3** (topic-scoped `delegation_ref` branch in existing rows)
