## Context

US-0122 is the second slice of the six-story OpenCode adapter epic (US-0121..US-0126). US-0121 shipped an empty-but-valid `template/.opencode/` pack + the `--host` installer switch. US-0122 populates that pack with eight OpenCode role agents and locks the Layer-1 permission matrix that the OpenCode host enforces. The matrix is the security control: a model that ignores its prompt still cannot let PO write production code when `edit` is `deny` on production paths (success test (c), AC-3).

R-0109 DQ1..DQ8 deepened the eight discovery questions. This DEC locks the answers as the cross-cutting permission contract that US-0124 (plugin spawn loop) and US-0126 (runbook) inherit without re-deriving. Three sovereign-critic non-blocking carry-forwards from the research phase are closed here: (1) AC-3 static-vs-runtime harness wording — lock AC-3 as the static permission-object harness, with the optional runtime permission-check call deferred to US-0124 if its plugin API exposes one; (2) publish the full eight-agent matrix + Task subagent ID contract + built-in subagent deny posture in this DEC; (3) T-008 stays a one-liner for AC-6 manual invoke — full runbook deferred to US-0126.

Research basis: **`R-0109`** US-0122 deepened findings (DQ1..DQ8 LOCKED for `/architecture`; US-0121 Q1..Q12 locks preserved, not wiped).

## Decision

### 1. Markdown agents at `template/.opencode/agents/<role>.md` (DQ1 LOCKED — AC-1)

Template form = **markdown** under `template/.opencode/agents/` (one file per role, eight files total): `po.md`, `tech-lead.md`, `dev.md`, `qa.md`, `release.md`, `curator.md`, `security.md`, `auto.md`. The filename (minus `.md`) is the OpenCode agent name. YAML frontmatter carries `description`, `mode`, `permission` (the Layer-1 table), and a short `prompt` body (Layer-2). Markdown is preferred over a repo-root `opencode.json` `agent` table because (i) it composes with the kit's existing `.cursor/agents/*.mdc` convention without coupling to it (US-0002/US-0004 do-not-port rule), (ii) it keeps each role's prompt body co-located with its permission block, (iii) it avoids a repo-root `opencode.json` that would prematurely lock US-0123 provider config (R-0109 Q6 US-0121 lock preserved). A repo-root or `.opencode/opencode.json` is **not required** for US-0122; markdown agents are self-contained.

**Rejected alternatives**: (a) JSON `agent` table at `opencode.json` / `.opencode/opencode.json` — rejected as prematurely locking US-0123 provider config and separating prompts from permissions; (b) global agents at `~/.config/opencode/agents/` — rejected as out of scope for a kit template (project-local only).

### 2. Layer-1 permission matrix for eight agents (DQ2+DQ3+DQ4+DQ5+DQ6 LOCKED — AC-2, AC-5, AC-10; **amended BUG-0016 / R-0115**)

`permission.edit` uses the **object form** with **deny-last ordering** (DQ2+DQ3). OpenCode permission glob matching is **last-match-wins**; a specific `deny` glob placed after a broad `allow` wins. Tests assert **both** the glob set and the ordering (order-sensitive). `permission.bash` uses shorthand `"allow" | "ask" | "deny"`. `permission.task` uses the object form for `auto` (7-role allow-list + `*` deny last) and shorthand `"deny"` for the seven role agents (DQ4 — role agents do not spawn sub-tasks; BUG-0006 spawn-only via the orchestrator). `mode: "primary"` for `auto`; `mode: "subagent"` for the seven role agents (DQ5 — operator can `@<role>` manually before US-0124; none `hidden: true`).

**BUG-0016 amend (R-0115 DQ1–DQ8)**: Align Layer-1 with kit phase duties without weakening success test (c). Normative delta: (1) `po` / `tech-lead` / `curator` `bash: "deny"` → `"ask"` (reject `"allow"`; bash object-form allowlist YAGNI); (2) PO edit adds `handoffs/intake_evidence/**`, `handoffs/resume_brief.md`, `docs/engineering/state.md`; (3) replace every permission-key `sprints/Sxxxx/<file>` with `sprints/S*/<file>` (OpenCode simple wildcards — no `[0-9]` classes; literal `Sxxxx` never matches `S0131`); (4) release edit adds `sprints/S*/release-findings.md`, `handoffs/verify-work-to-release.md`, `docs/engineering/state.md`, `handoffs/resume_brief.md`, `docs/engineering/runbook.md` (keep existing `verify_to_release.md`); (5) `security` / `auto` unchanged. Active ↔ template agent frontmatter must stay byte-identical after execute. Layer-1 ∩ DEC-0124 plugin write-guard remain conjunctive — do not amend DEC-0124/0125 unless execute proves double-deny.

**Ordering note (R1 / OpenCode docs divergence)**: OpenCode docs often illustrate catch-all `*` first then specific allows; this kit **preserves allow-first + `**` deny-last** so success test (c) stays static-provable. Do not flip global key order in this bug.

#### Ordering contract (DQ3 LOCKED — last-match-wins, order-sensitive)

For every object-form `permission.edit`, the broad `**` → `deny` glob MUST be the **last key** in the object. Specific allow globs precede it. Tests assert key order, not just set membership. For `auto` `permission.task`, the `*` → `deny` glob MUST be the last key. This is the success-test-(c) anchor: a prompt-ignoring PO attempting `edit` on `scripts/foo.py` matches only `**` → denied regardless of prompt content. BUG-0016 does **not** grant any non-dev role `scripts/**`, `its_magic/**`, `**/*.py`, installer, or other production/code allows.

#### Task subagent ID contract (DQ4 LOCKED — critic NB closed)

`auto` `permission.task` object lists the seven role names as `allow` keys: `po`, `tech-lead`, `dev`, `qa`, `release`, `curator`, `security`. The trailing `*` → `deny` key denies **all** non-kit subagents, including any OpenCode built-in subagents and any future US-0124 plugin-internal helpers. US-0124 may add plugin-internal helpers as additional `allow` keys **above** the `*` deny, but never remove the `*` deny last. Role agents carry `task: "deny"` shorthand — they cannot spawn sub-tasks (BUG-0006 spawn-only via the orchestrator).

#### Security findings posture (DQ6 LOCKED — YAGNI)

Default security agent posture is `edit: "deny"` (no write surface in v1). Findings return as conversation turn text or Task result back to the orchestrator. A committed `handoffs/security_findings/` directory is **not required** for v1 — YAGNI. If US-0126 (runbook) decides to persist findings, architecture may grant a narrow `handoffs/security_findings/**` → `allow` + `**` → `deny` (last) glob; the `**` deny last still blocks production/code paths, so success test (c) holds. That decision is deferred to US-0126.

### 3. Static success-test-(c) harness (DQ7 LOCKED — AC-3, AC-8 — critic NB closed)

Success test (c) MUST NOT depend on the model obeying the prompt. The minimum harness is a **static permission-object inspection** (required) plus an optional **runtime permission-check call** (deferred to US-0124):

- **Static layer (required, US-0122; amended BUG-0016)**: parse `template/.opencode/agents/po.md` frontmatter → assert `permission.edit` is an object (not shorthand) → assert `docs/product/**`, `handoffs/po_to_tl.md`, `handoffs/intake_evidence/**`, `handoffs/resume_brief.md`, and `docs/engineering/state.md` are `allow` → assert `**` is `deny` and is the **last key** (last-match-wins) → assert no production/code path (`scripts/**`, `its_magic/**`, `**/*.py`, `installer.*`, `template/scripts/**`, `template/its_magic/**`) appears as `allow`. This proves the host would deny a production-code edit regardless of prompt content.
- **Runtime layer (optional, deferred to US-0124)**: if OpenCode exposes a programmatic permission-check API (`permission.ask` hook or `tool.execute.before` hook), a test may call it with a synthetic write to `scripts/foo.py` and assert denial. This is stronger but depends on a host API that US-0124 will confirm. For US-0122, the static layer is sufficient — the permission object IS the security boundary.

AC-3 wording is locked as: "contract test proves PO cannot write a production/code path via **static permission-object inspection** (frontmatter parse + deny-last ordering assertion + no-production-allow assertion), even if the agent prompt is emptied or contradictory (host permission, not prose). Optional runtime permission-check call deferred to US-0124."

### 4. Layer-2 short prompts + clone guard (AC-4)

Agent prompt bodies state only who the role is and which artifacts they may write. They MUST NOT paste `.cursor/commands/*.md` bodies, `.cursor/agents/*.mdc` bodies, `.cursor/rules/**`, or skills content. A size/grep guard fails on oversized command clones: each `template/.opencode/agents/<role>.md` file MUST be ≤ 2 KiB total AND MUST NOT contain forbidden clone markers (`/auto`, `/intake`, `/discovery`, `/research`, `/architecture`, `/sprint-plan`, `/execute`, `/qa`, `/release`, `/closure`, `/refresh-context` command-body prose; `.cursor/commands/` path literals; `---` MDC frontmatter delimiters). The 2 KiB cap is the locked ceiling; `/architecture` may lower it per agent but cannot raise it without amending this DEC.

### 5. Manual invoke one-liner (AC-6 — T-008, critic NB closed)

T-008 ships a **one-liner** in `docs/engineering/runbook.md` under a new `## OpenCode role agents and permissions (US-0122)` h2: "With the pack installed via `--host opencode|both`, an operator can `@po` (or `@<role>` for any of the seven role agents) in the OpenCode chat to invoke that role manually, before the US-0124 plugin exists." The full OpenCode operator runbook is deferred to US-0126. T-008 does NOT author a full runbook section.

### 6. No vendor slugs in template (AC-7 — US-0102 / US-0123 compose)

`template/.opencode/agents/*.md` frontmatter MUST NOT contain a `model:` key with a real vendor slug. The `model:` key is either omitted entirely or set to a placeholder. US-0123 owns per-role `provider/slug` routing and the local catalog. `test_us0122_no_vendor_slugs_in_template` greps for known vendor slug patterns (`deepseek`, `moonshot`, `kimi`, `glm`, `claude`, `gpt`, `sonnet`, `opus`, `haiku`, `o1`, `o3`, `sk-`) in `template/.opencode/agents/*.md` and fails on any hit.
