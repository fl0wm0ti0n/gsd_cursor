## Context

The sovereignty stack (US-0092 / US-0095 / US-0103 / US-0104 / US-0105 / US-0107) ships many hard-stop reason codes that are safe to auto-repair or soft-skip in a self-driving loop, but the governance layer refuses to do so. Operators also have to flip twelve individual autonomy flags to reach zero-touch flow. US-0119 adds two orthogonal primitives:

1. **`AUTONOMY_PRESET={none|balanced|full}`** — an ergonomic single-flag switch that deterministically expands into a well-defined bundle of per-feature autonomy flags. All twelve target flags already exist individually (or are net-new in US-0119); no new consumer semantics are invented. Explicit per-flag values always win over preset expansion.
2. **`AUTONOMY_STOP_POLICY={block|auto_repair_then_block|auto_repair_then_skip}`** — classifies every fail-closed reason code as `security_hard` (never auto-resolved under any preset/policy) or `autonomy_resolvable` (bounded auto-repair with an append-only ledger before escalation).

Research basis: **`R-0107`** Q1–Q10 (10/10 closed LOCKED).

## Decision

### 1. AUTONOMY_PRESET enumeration — 3-tier `none` / `balanced` / `full` (AC-1, AC-2)

**Enumeration**: `AUTONOMY_PRESET ∈ {none, balanced, full}` returned by `scripts/autonomy_preset_lib.py:expand_autonomy_preset(preset, overrides) -> dict`.

**Preset semantics**:

| AUTONOMY_PRESET | Behaviour | Flag bundle |
|-----------------|-----------|-------------|
| **`none`** (default) | Byte-identical pre-US-0119 behaviour. No flags flipped; no expansion. | `{}` (empty) |
| **`balanced`** | Moderate autonomy — auto-refresh stale briefs, auto-accept classifier outputs, lightweight proofs, drain auto-accept (low risk only), auto-confirm publish (allowlist only). | 8 of 12 flags flipped per AC-5 mapping |
| **`full`** | Maximum autonomy — all `balanced` flags + `INTAKE_AUTONOMY_MODE=1` (auto-derive intake answers on known-stack repeat projects) + `INTAKE_MINIMAL_PACK=1` (shrunk follow-up intake) + `CROSS_MODEL_SKIP_PHASES` (skip critic for low-risk phases) + `GOAL_CONVERGENCE_INTERVAL=1` (evaluate every phase). | All 12 flags flipped per AC-5 mapping |

**Precedence (LOCKED)**: explicit per-flag value in scratchpad (or scratchpad.local) always wins over preset expansion. Expansion is deterministic: the same `(preset, overrides)` input always produces the same output dict. No LLM, no network, no `.env` reads.

**Rejected alternatives**: (a) 2-tier `none|full` — rejected as too coarse (no moderate option); (b) 4-tier `none|low|medium|high` — rejected as over-engineered (no operator demand for four levels; 3-tier mirrors `classify_touched_files` tier A/B/C precedent cleanly).

### 2. AUTONOMY_STOP_POLICY enumeration — 3-value `block` / `auto_repair_then_block` / `auto_repair_then_skip` (AC-3)

| AUTONOMY_STOP_POLICY | Behaviour |
|----------------------|-----------|
| **`block`** (default) | All fail-closed reason codes block the orchestrator; no auto-repair. Byte-identical pre-US-0119. |
| **`auto_repair_then_block`** | `autonomy_resolvable` codes get bounded auto-repair (ledger entry); if repair succeeds, continue; if repair fails or cap exhausted, block with terminal `AUTONOMY_REPAIR_CAP_EXHAUSTED`. `security_hard` codes always block immediately (no repair attempted). |
| **`auto_repair_then_skip`** | Same as `auto_repair_then_block` except cap exhaustion or repair failure results in a skip (with ledger evidence) instead of a block. `security_hard` codes always block immediately (no skip). |

**Two-tier stop classification**: every reason code in `docs/engineering/autonomy-stop-matrix.md` is classified as either:
- **`security_hard`** — never auto-resolved under any policy; block immediately; `auto_repair_kind=n/a`; cap = 0.
- **`autonomy_resolvable`** — bounded auto-repair permitted when policy != `block`; cap per (run, reason_code) taken from matrix `cap` column (default 3 per Q3 LOCKED).

**Rejected alternative**: 3-tier `security_hard|autonomy_resolvable|soft_warn` — rejected as over-engineered (operators want binary never/yes for auto-repair eligibility).

### 3. Security-hard gates never softened (AC-7)

Matrix `security_hard` rows include at minimum:

| Reason code | Rationale for `security_hard` classification |
|-------------|----------------------------------------------|
| `PHASE_CONTEXT_ISOLATION_VIOLATION` | Context isolation is a fundamental security boundary |
| `PHASE_CONTEXT_ISOLATION_MISSING` | Missing isolation evidence = untrusted context |
| `ISOLATION_EVIDENCE_STALE` | Stale evidence = untrusted context |
| `RUNTIME_PROOF_MISSING` | Proof absence = unverifiable execution |
| `RUNTIME_PROOF_REUSED` | Proof reuse = unverifiable execution |
| `RUNTIME_PROOF_STALE` | Stale proof = unverifiable execution |
| `RUNTIME_PROOF_AMBIGUOUS_LINK` | Ambiguous link = unverifiable execution |
| `PHASE_ROLE_CAPABILITY_MISSING` | Role capability is a security boundary |
| `PHASE_ROLE_MISMATCH` | Role mismatch is a security boundary |
| `PHASE_OWNERSHIP_VIOLATION` | Ownership is a security boundary |
| `PHASE_OVERRIDE_EVIDENCE_MISSING` | Override evidence is a security boundary |
| `INTAKE_BUG_ROUTING_REQUIRED` | Bug routing is a structural gate |
| `INTAKE_ANSWER_REF_NOT_TOPIC_DISTINCT` | Topic distinctness is a truthfulness boundary |
| `INTAKE_REQUIRED_TOPIC_MISSING` | Required topic absence blocks intake |
| `INTAKE_PERSISTENCE_BLOCKED` | Persistence failure = unreliable state |
| `AUTO_SCHEDULER_CONFLICT` | Scheduler conflict = unreliable sequencing |
| `RESUME_BRIEF_STALE` (when `RESUME_BRIEF_AUTO_REFRESH != 1`) | Stale brief = unreliable context (when auto-refresh not enabled) |
| Any `SECURITY_REVIEW=1` critical finding | Security review critical = security boundary |

Contract test `test_us0119_security_hard_gates_never_auto_repaired` fails on divergence.

### 4. `auto_repair_kind` taxonomy — 9 values (R-0107 Q2 LOCKED)

| auto_repair_kind | Description | Reason codes served |
|------------------|-------------|---------------------|
| `reorder_anchors` | Sort H1s by story ID | `ARTIFACT_ORDERING_ANCHOR_AMBIGUOUS` |
| `fix_timestamp` | Replace stale timestamp with `now()` | `STATE_TIMESTAMP_NON_MONOTONIC` |
| `truncate_hot_surface` | Archive rollover | `ARTIFACT_HOT_SURFACE_OVERSIZE` |
| `reset_retry_counter` | Reset to 0 | `BLOCK_RETRY_CAP_EXHAUSTED` |
| `disambiguate_state` | Pick last-known phase | `STATE_PHASE_AMBIGUOUS` |
| `auto_refresh_brief` | Regenerate from state.md | `RESUME_BRIEF_MISSING` |
| `approve_plan_deviation` | Ledger waiver | `PLAN_FIDELITY_VIOLATION` |
| `regenerate_isolation_evidence` | Re-run context-refresh | `ISOLATION_EVIDENCE_INVALID` |
| `skip_confirmation_gate` | Allowlist-gated skip | `RELEASE_PUBLISH_MODE` (when target in allowlist) |

Each reason code maps 1:1 to an `auto_repair_kind` (or `n/a` for `security_hard`).

### 5. Bounded auto-repair ledger (AC-8)

**Location**: `handoffs/autonomy_repair_ledger/<orchestrator_run_id>.jsonl` (gitignored at per-run path).

**Schema per row**: `{"reason_code": "<code>", "auto_repair_kind": "<kind>", "attempt": <int>, "outcome": "success|failure", "evidence_ref": "<path>"}`.

**Cap**: uniform `cap = 3` per `(orchestrator_run_id, reason_code)` (Q3 LOCKED). Operator can override per-run via `AUTONOMY_REPAIR_CAP_OVERRIDE=<int>` (optional).

**Cap exhaustion**: escalates with new terminal stop reason `AUTONOMY_REPAIR_CAP_EXHAUSTED` (distinct from `BLOCK_RETRY_CAP_EXHAUSTED` per Q9 LOCKED — the former is run-level, the latter is story-level).

**Ledger is append-only**: no deletions, no modifications after write. Audit surface for operator review per AC-9.

### 6. Breadcrumb in state.md (AC-9, Q10 LOCKED)

**Format**: `autonomy_relaxed: <reason_code> -> <auto_repair_kind>` emitted at phase boundary (after phase completes, before next phase starts). One-line per soft-stop, not aggregated per phase.

**Rationale**: operator audit surface per AC-9 requires per-stop visibility; aggregation loses granularity.

## Consequences

- **Positive**: Operators gain a single `AUTONOMY_PRESET=balanced|full` switch that deterministically configures twelve autonomy flags; `AUTONOMY_STOP_POLICY` provides explicit control over how softened non-security stops are handled; audit trail via ledger + breadcrumb; backward-compatible default.
- **Negative**: More scratchpad surface area (14 new keys); new code surface (`autonomy_preset_lib.py` + `validate_autonomy_stop_matrix.py` + tests); new stop-matrix authority file; 7th cumulative byte-stability sub-block in README.
- **Neutral**: Implementation lives in `/execute` (build+verify macro); this decision fixes the architecture contract only. `/sprint-plan` may merge or split the 12 task seeds within the 12-task budget.
