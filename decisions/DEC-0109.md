## Context

Post-deploy smoke probe + bounded retry loop on top of US-0054 publish chain. After `[RELEASE_PUBLISH_OK]`, a two-stage smoke probe (health HTTP GET + acceptance smoke runner) validates the deployed artifact. On probe FAIL, the publish path is re-entered idempotently up to `AUTO_SOVEREIGN_DEPLOY_RETRY_MAX`. After retry-cap exhaustion, US-0107 `append_deferral(work_item_kind=deploy)` writes a DEPLOY_DEFERRED row. Orchestrator continues per `AUTO_SOVEREIGN_DEFERRAL_POLICY`.

Research basis: `R-0097` Q1–Q11 closed.

## §2 — Post-deploy smoke probe contract (probe_contract_v1, AC-2)

Two-stage probe chain, executed **sequentially** after US-0054 `[RELEASE_PUBLISH_OK]`:

**(a) Health HTTP GET**
- Target URL resolved from `os.environ[AUTO_SOVEREIGN_DEPLOY_HEALTH_ENDPOINT]` (names-only per US-0085)
- Timeout: `AUTO_SOVEREIGN_DEPLOY_SMOKE_TIMEOUT_SEC`
- Success: HTTP 2xx
- Fail → `DEPLOY_SMOKE_PROBE_FAIL`

**(b) Acceptance smoke runner**
- Path: `SOVEREIGN_DEPLOY_ACCEPTANCE_SMOKE_PATH` (default `tests/deploy_smoke/`)
- Runner: bounded `pytest -x --timeout=30 -q`
- Success: exit 0
- Fail → `DEPLOY_SMOKE_PROBE_FAIL`

Both stages MUST pass to emit **`[DEPLOY_SMOKE_PROBE_OK]`**. When `PROBE_KIND != both`, only the named stage runs.

Output schema:
```json
{
  "probe_kind": "two_stage",
  "health_status": "pass|fail",
  "health_status_code": "200|null",
  "acceptance_status": "pass|fail|skip",
  "acceptance_tests_run": "int|null",
  "acceptance_tests_failed": "int|null",
  "overall": "pass|fail",
  "reason_code": "string"
}
```

## §3 — Bounded retry loop (retry_loop_v1, AC-3)

- Max retries: `AUTO_SOVEREIGN_DEPLOY_RETRY_MAX` (default 3)
- Retry body: re-enter publish PASS path (US-0054) idempotently — same artifact set, no execute re-entry
- Per-attempt: emit `DEPLOY_HEALING_RETRY_ATTEMPT` reason code + `retry_count` tag
- Idempotency invariant: no duplicated ledger rows (US-0103 `retry_count` field); deploy target overwrite safe
- Total bounded time: `AUTO_SOVEREIGN_DEPLOY_SMOKE_TIMEOUT_SEC` per stage × retry count

## §4 — DEPLOY_DEFERRED state transition (deploy_deferred_tuple_v1, AC-4)

After retry cap exhaustion:
```python
from sovereign_loop_lib import append_deferral

append_deferral(
    repo, scratchpad,
    reason_code="DEPLOY_DEFERRED",
    work_item_kind="deploy",
    work_item_ref="<current_story_id>",
    source_orchestrator_run_id="<runner>",
    remediation_hint="<smoke_summary truncated to 512 chars>",
    blocked_by_phase="release",
    retry_count=retry_max,
)
```

Fields emitted: `{reason_code, remediation_hint, retry_count, timestamp, proof_ref}`.

Orchestrator continues per `AUTO_SOVEREIGN_DEFERRAL_POLICY` — does NOT halt.
