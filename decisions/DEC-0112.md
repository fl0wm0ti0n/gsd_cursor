## Decision

Classify all 8 `model-catalog.local.example*.json` files as **framework files** in the installer manifest, adding them to `[install_include_paths]` in both active (`docs/engineering/context/installer-owned-paths.manifest`) and template (`template/docs/engineering/context/installer-owned-paths.manifest`) locations (16 rows total, byte-parity). The `missing` installer mode will copy these files when absent; the `upgrade` mode will refresh them when the template version differs (same semantics as `scratchpad.local.example.md` per US-0075/US-0018/US-0057). Never touch gitignored `.cursor/model-catalog.local.json` (operator-owned active catalog).

## Rationale

- **Q1–Q2**: The 8 preset filenames are confirmed (scratchpad L352–359 + glob verification), and the manifest uses line-based paths under `[install_include_paths]`.
- **Q3**: `missing` mode semantics: copy when absent, deterministic name-only log/status per file (consistent with `scratchpad.local.example.md`).
- **Q4**: `upgrade` mode classifies files as framework; refresh when template differs, skip unchanged files — reuse US-0075/US-0018/US-0057 precedence rules; no new classification mechanism.
- **Q5**: The three installers (`installer.py` / `installer.ps1` / `installer.sh`) read a single manifest as source of truth; `List-SourceFiles` / Python equivalent must cover all 8 examples.
- **Q6**: Runbook anchor — add section "Model-Catalog Example Presets" under Model Tier / Catalog in `docs/engineering/runbook.md`.
- **Q7**: 8+ `test_us0112_*` markers + `--scope=model-catalog-examples` with `MODEL_CATALOG_EXAMPLE_PAIRS` constant (16 active/template row byte-parity check).
- **Q8**: A companion DEC-0112 is required to record installer payload decisions (manifest rows, framework classification, active catalog exclusion).

## Risk Analysis

- **R1**: Template file renaming causes stale active upgrade → deterministic manifest list + idempotent upgrade copy prevents old-file deletion.
- **R2**: Operator confusion if all 8 examples land but none is selected → runbook recipe is mandatory (lists 8 names and purpose).
- **R3**: Active catalog (`model-catalog.local.json`) accidentally installed → manifest exclusion invariant + regression test protection.
- **R4**: Installer drift across Python/PS1/Bash paths → single manifest as source of truth + parity test enforcement.
- **R5**: npm `package.json` `files` field gap → already covered by `template/` glob; verify at architecture phase.
- **R6**: Precedence order vs US-0075 / US-0018 → reuse same framework-file semantics; additive only.

## Consequences

- **Positive**:
  - Operators no longer manually locate and copy `template/.cursor/model-catalog.local.example*.json`.
  - `MODEL_RESOLVE=local_catalog` / `role_catalog` users obtain all 8 examples after install and upgrade.
  - Active catalog (`model-catalog.local.json`) remains under operator full control — installer never touches it.
  - Framework classification aligns with US-0075 / US-0018 / US-0057 — no new code path required.
- **Negative**:
  - Active manifest grows by 8 rows (active + template) → minor maintenance cost.
  - 8 new fail-closed error codes required (reason_codes.md § US-0112).
  - 8+ `test_us0112_*` markers required for regression coverage.
- **Neutral**:
  - Installer behavior on existing installs unchanged — only new/missing files trigger `missing` mode; only stale template versions trigger `upgrade` refresh.

## Verification Requirements

- 8 preset filenames appear in both active and `template/` manifests under `[install_include_paths]`.
- `missing` mode: verify 8 examples are copied to target `.cursor/` when absent.
- `upgrade` mode: verify 8 examples are refreshed only when template content differs.
- Active catalog (`model-catalog.local.json`) remains untouched in all installer modes.
- 8+ `test_us0112_*` markers cover manifest, missing, upgrade, parity, and protection.
- Runbook recipe anchor: `docs/engineering/runbook.md` § Model Tier / Catalog documents example delivery and operator usage.
