# DEC-0072 — Caveman mode scratchpad contract, composition surface, and default-off invariant

## Status

Accepted — 2026-04-18

## Context

US-0089 introduces an optional **response-side** Caveman voice (terse /
imperative assistant replies) toggled from `.cursor/scratchpad.md`, aligned
conceptually with the external JuliusBrussee/caveman MIT pattern (`lite|full|
ultra` levels, "compress touches prose, not code blocks"). The feature must
ship **default off** and must not weaken any existing its-magic contract: spawn
isolation (US-0048 / DEC-0029 / BUG-0006), strict runtime proof tuple
(US-0056 / DEC-0038), `AUTO_QUIET` non-suppressible gate vocabulary (US-0088),
user-visible ID metadata (US-0071), intake evidence (US-0078 / DEC-0060), bug
evidence validators, and artifact-ordering policy (DEC-0040).

Research `R-0073` surfaced eight architecture asks across composition, key
names, toggle phrasing, literal-region preservation, test strategy, and
template parity. US-0090 will later add **input-side** file compression on top
of this story's scratchpad vocabulary; US-0089 must not implement any
file-mutating behavior.

## Decision

Adopt the following architecture-locked contract for US-0089. US-0090 is
**out of scope** here and must not be activated by anything delivered under
this DEC.

### 1. TOKEN_PROFILE × CAVEMAN precedence — Option A (orthogonal, non-substitution)

`TOKEN_PROFILE` (US-0080 / DEC-0062) and `CAVEMAN_MODE` / `CAVEMAN_LEVEL` are
**two independent axes**. Neither substitutes for the other. The following
matrix is normative (any composition is valid and deterministic):

| TOKEN_PROFILE \ CAVEMAN_MODE | 0 (off) | 1 (on) |
|------------------------------|---------|--------|
| `lean` | Pre-US-0089 behavior under lean context pack. | Lean context pack + Caveman voice applied to prose; literal regions untouched. |
| `balanced` (default) | Pre-US-0089 behavior under balanced pack. | Balanced pack + Caveman voice. |
| `full` | Pre-US-0089 behavior under full pack. | Full pack + Caveman voice. |

Rules:

- `CAVEMAN_MODE=1` **never** changes `TOKEN_PROFILE` semantics, context breadth,
  phase context packs, or archive policy (DEC-0035 / DEC-0062 unchanged).
- `TOKEN_PROFILE=lean` **never** implies Caveman voice.
- A single **non-substitution paragraph** (verbatim) is published in both
  `docs/engineering/auto-orchestration-reference.md` and
  `docs/engineering/runbook.md` (active + `template/` mirrors) stating:
  "`TOKEN_PROFILE` controls context breadth. `CAVEMAN_MODE` controls reply
  voice. Neither substitutes for the other; setting one does not change the
  other. Combine freely."

Option B (explicit enumerated matrix baked into rules/commands) and Option C
(collapse into a `TOKEN_PROFILE=lean-caveman` value) are rejected — see
"Alternatives considered".

### 2. Rule vs rule+skill composition — Option A (rule-only)

- **Authoritative file**: `.cursor/rules/caveman.mdc` (active) with
  `template/.cursor/rules/caveman.mdc` mirror. Scope: `globs: ["**/*"]`
  (always-on rule, same posture as `core.mdc` / `quality.mdc`).
- **No new skill** under `.cursor/skills/` in US-0089. The existing
  `.cursor/skills/its-magic/SKILL.md` is **not modified** by this story.
- The rule file contains:
  - `CAVEMAN_MODE` gate contract (how the agent reads the scratchpad key).
  - Literal-region invariant (9-zone list, verbatim §4 below).
  - Operator toggle phrase catalog (§5 below) with "scratchpad authoritative
    across subagent spawn" semantics.
  - Non-suppressible gate list inherited from US-0088 (`decision_gate`,
    `error`, `pause`, `loop_max`, `blocked`, `missing input`,
    `[BUG_VALIDATION_OK]`, `[INTAKE_EVIDENCE_VALIDATION_OK]`,
    `[SCRATCHPAD_PAIR_OK]`) — rule MUST assert Caveman voice cannot remove
    these.
  - Single-line attribution: "Inspired by JuliusBrussee/caveman (MIT).
    External reference only; not vendored."
- **No `npx skills add …`** instructions anywhere in the kit.

Option B (rule + focused skill under `.cursor/skills/its-magic-caveman/`) is
rejected for US-0089 to minimize surface area. A skill may be added in a
future story if discoverability evidence justifies it; the rule alone is
sufficient for AC-1..AC-8.

### 3. Scratchpad key contract

Locked key names (the exact strings contract tests may match on):

- `CAVEMAN_MODE=0|1` — **default `0`** (off). Absence of the key is equivalent
  to `0`.
- `CAVEMAN_LEVEL=lite|full|ultra` — **default empty**. Semantics:
  - When `CAVEMAN_MODE=0`: inert regardless of value.
  - When `CAVEMAN_MODE=1` and `CAVEMAN_LEVEL` is empty: rule treats level as
    `full` (the mid-tier, matching upstream reference).
  - When `CAVEMAN_MODE=1` and `CAVEMAN_LEVEL` is one of `lite|full|ultra`:
    that level applies.
  - Any other non-empty value: rule must fail closed with deterministic
    reason code `CAVEMAN_LEVEL_UNKNOWN` and fall back to pre-US-0089 voice
    (no terseness applied) while continuing the turn.
- **Reserved-for-US-0090 keys (documented no-ops in US-0089)**:
  - `CAVEMAN_COMPRESS_INPUT=0|1` — default **`0`**.
  - `CAVEMAN_FILE_SCOPE=` — default empty.
  - Both keys MUST be declared in `.cursor/scratchpad.md` (active) and the
    example file with a comment: `# reserved for US-0090; inert in US-0089;
    no behavior until compression story ships`.

Test contract strings (exact byte-for-byte — dev phase MUST NOT rename):

- Line in `.cursor/scratchpad.md`: `CAVEMAN_MODE=0`
- Line in `.cursor/scratchpad.md`: `CAVEMAN_LEVEL=`
- Line in `.cursor/scratchpad.md`: `CAVEMAN_COMPRESS_INPUT=0`
- Line in `.cursor/scratchpad.md`: `CAVEMAN_FILE_SCOPE=`
- Same four lines mirrored (with identical defaults) in
  `.cursor/scratchpad.local.example.md` and
  `template/.cursor/scratchpad.local.example.md`.

### 4. Literal-region invariant (nine-zone list, hard MUST)

When `CAVEMAN_MODE=1`, the following output regions remain **byte-literal**
(no abbreviation, no rewording, no casing change). Rule phrasing is MUST, not
SHOULD:

1. **Fenced code blocks** — both plain ``` ... ``` and CODE REFERENCE blocks
   of the form ```startLine:endLine:filepath ... ```. Content, line numbers,
   filepath, language tags, and whitespace preserved.
2. **File/path strings** — anything matching `` `[\w./-]+\.(md|py|ps1|sh|json|
   mdc|ts|tsx|js|jsx|yml|yaml|toml|ini|env|example|manifest)` `` or enclosed
   in backticks that points to a repo path. Preserve extension and case.
3. **AC checklist items** — bullets of form `- [ ]` or `- [x]` and their
   entire text (AC-1..AC-N).
4. **Reason codes** — `ALL_CAPS_WITH_UNDERSCORES` tokens such as
   `PHASE_CONTEXT_ISOLATION_VIOLATION`, `RUNTIME_PROOF_MISSING`,
   `AUTO_RESUME_ERROR`, `AUTO_SCHEDULER_CONFLICT`, `REMOTE_TARGET_UNKNOWN`,
   `CAVEMAN_LEVEL_UNKNOWN`, `INTAKE_PERSISTENCE_BLOCKED`, etc.
5. **IDs** — `US-xxxx`, `DEC-xxxx`, `R-xxxx`, `BUG-####`, `S0xxx`, `T-xxx`.
6. **Contract markers** — `[BUG_VALIDATION_OK]`,
   `[INTAKE_EVIDENCE_VALIDATION_OK]`, `[SCRATCHPAD_PAIR_OK]`,
   `[ARTIFACT_ORDERING_ANCHOR_AMBIGUOUS]`, `[CODEBASE_MAP_OK]`, and siblings.
7. **Strict-proof tuple fields** — `orchestrator_run_id`, `runtime_proof_id`,
   `proof_hash`, `proof_issued_at`, `proof_ttl_seconds`, `phase_id`, `role`
   (DEC-0038).
8. **Isolation evidence fields** — `fresh_context_marker`, `evidence_ref`,
   `timestamp` (DEC-0029).
9. **Commit / git refs** — quoted `git commit` messages, branch names, SHAs,
   `HEAD`, tag names.

Forbidden "garbling" examples (rule must list): dropping the `US-` prefix,
lowercasing a reason code, collapsing fenced code into a bullet, truncating
a path mid-filename, abbreviating a proof hash.

### 5. Operator toggle phrases — canonical set

Locked set (published verbatim in `.cursor/rules/caveman.mdc`,
`docs/engineering/runbook.md`, and template mirrors):

| Phrase | Effect |
|--------|--------|
| `caveman on` | Enable Caveman voice for the session (overlay). Effective from the next assistant turn. |
| `caveman off` | Disable Caveman voice for the session (overlay). Effective from the next assistant turn. |
| `stop caveman` | Alias for `caveman off`. |
| `normal mode` | Alias for `caveman off`. |
| `caveman: lite` / `caveman: full` / `caveman: ultra` | Set level for the session (implies `caveman on`). Effective from the next assistant turn. |

Determinism rules:

- Scratchpad `CAVEMAN_MODE` / `CAVEMAN_LEVEL` are **authoritative across
  subagent spawns**; session toggles are overlays for the current
  conversation only and DO NOT persist across a fresh subagent context.
- Within a session, the **last explicit toggle wins**.
- A mid-turn toggle applies **from the next turn onward**; current-turn
  machine-verifiable artifacts (gate messages, reason codes, tuples) remain
  literal regardless of the toggle.
- Ambiguous phrases (`be caveman-lite`, `quiet caveman`, `cave man off`, etc.)
  are **not recognized** — rule must list exact literal matches only.

### 8. Non-goals / boundaries

Explicitly **out of scope** for US-0089. Any attempt to do these must be
rejected by `/sprint-plan`, `/execute`, or `/qa`:

- **No input-side file compression.** US-0090 owns `CAVEMAN_COMPRESS_INPUT` /
  `CAVEMAN_FILE_SCOPE` behavior; US-0089 only documents the reserved keys as
  no-ops. No script under `scripts/`, no installer change, no file mutator.
- **No change to `TOKEN_PROFILE` semantics** (DEC-0035 / DEC-0062). No new
  profile value, no renames, no change to context pack computation, archive
  policy, or phase-context slimming contracts.
- **No rewrite of canonical artifacts.** `docs/product/backlog.md`,
  `docs/product/acceptance.md`, `docs/engineering/state.md` schema,
  `handoffs/intake_evidence/*.json`, `docs/engineering/decisions.md`
  canonical records, and DEC files remain unchanged in structure.
- **No new npm dependencies.** No `package.json` change. No runtime dep, no
  devDep, no `npx`.
- **No vendor plugin install.** The JuliusBrussee/caveman `npx skills add`
  path is not surfaced as a recommended action anywhere in the kit.
- **No change to spawn-only orchestration** (US-0048 / DEC-0029 /
  DEC-0051 / BUG-0006). No change to strict runtime proof (DEC-0038). No
  change to `AUTO_QUIET` non-suppressible list (US-0088). No change to
  US-0071 user-visible metadata sanitization.
- **No unit test of voice quality** under `CAVEMAN_MODE=1` (qualitative,
  operator-verified).

## Consequences

- Operators gain a documented, reversible, scratchpad-driven terse voice mode
  with predictable literal-region preservation. Default-off operators see
  zero behavior change.
- One new rule file (active + template) and one new architecture section are
  added; everything else is additive edits to existing files.
- Contract tests gain 8 new subtests (all file-presence / token-presence /
  literal-equality). No voice-quality assertion enters CI.
- US-0090 can proceed with its own discovery/research without being blocked on
  further scratchpad vocabulary negotiation; the four key names are
  already reserved here.
- TOKEN_PROFILE / `AUTO_QUIET` ecosystems remain independent and
  non-interacting with Caveman — no regression risk for US-0080 / US-0088
  tooling.

## Alternatives considered

- **Option B — TOKEN_PROFILE × CAVEMAN precedence matrix (§1 alternative).**
  Publishing an explicit enumerated matrix in commands/rules. Rejected:
  adds doc surface and invites misreadings ("lean+caveman is the canonical
  cheapest combo" — no evidence). Option A is simpler and still correct for
  every cell.
- **Option C — Collapse into TOKEN_PROFILE (`TOKEN_PROFILE=lean-caveman`).**
  Rejected: breaks US-0080 semantics, forces every TOKEN_PROFILE consumer
  to care about voice, and couples two independent concerns.
- **Rule + focused skill (§2 alternative Option B).** Rejected for US-0089
  to minimize surface; can be reconsidered in a future story if
  discoverability evidence emerges. Literal-region invariants must remain in
  the rule (rules are always-on; skills are contextual), so moving anything
  out of the rule is unsafe.
- **Skill-only composition (§2 alternative Option C).** Rejected: rules are
  always-on agent context; skills are contextually invoked. Hard invariants
  (literal regions, gate preservation) cannot live outside rules.
- **Single-key `CAVEMAN=off|lite|full|ultra`.** Rejected: collides with the
  repo convention that mode flags use `0|1` (`AUTO_QUIET`,
  `AUTO_BACKLOG_DRAIN`, `CAVEMAN_COMPRESS_INPUT`) and couples the enable
  flag with level selection.
- **Renaming `CAVEMAN_MODE` to `CAVEMAN_VOICE`.** Rejected: chosen name
  matches verb-pattern of `TOKEN_PROFILE`, `AUTO_FLOW_MODE`. Cosmetic
  difference only; not worth the churn.
- **New focused test module `tests/caveman_defaults_test.py`.** Rejected for
  US-0089: keeping assertions in `tests/auto_command_contract_test.py`
  preserves the existing contract-test authority. A separate module may be
  introduced if the subtest count grows past ~15 in a future story.
