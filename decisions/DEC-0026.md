# DEC-0026: Configurable Guided Intake Behavior

- Date: 2026-03-01
- Status: Accepted
- Related story: US-0033
- Research refs: R-0015

## Context

Teams want high-quality intake by default, but some prefer low-touch intake
without proactive follow-up overhead. Existing intake behavior does not provide
a single dedicated mode switch for this tradeoff.

## Decision

1. Introduce one switch: `INTAKE_GUIDED_MODE=1|0` in `.cursor/scratchpad.md`
   (default `1`).
2. Guided mode (`1`) requires:
   - targeted follow-up only when ambiguity blocks concrete acceptance
   - at least one viable option/alternative before recommendation
   - explicit user authority (`PO recommends, user decides`)
   - intake-time web research persisted in `docs/engineering/research.md`
3. Low-touch mode (`0`) removes proactive follow-up/options/research overhead
   unless user explicitly asks for depth.
4. Duplicate/overlap backlog check remains mandatory in both modes.
5. Active/template parity is required for intake command, PO agent, switch
   declaration, and operator docs.

## Consequences

- Intake behavior becomes explicit and configurable with a single control.
- Teams can optimize for either guidance depth or speed without losing baseline
  safety.
- New installs inherit consistent intake behavior through template parity.
