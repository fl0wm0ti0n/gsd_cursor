# DEC-0036: Configurable Multi-Target Publish with Confirmation and SSH Support

- Date: 2026-03-13
- Status: Accepted
- Related story: US-0054
- Research refs: R-0029, R-0030

## Context

Different repositories need different post-release publish targets (registry,
git, docker, cloud, custom servers). Existing release finalization is workflow
safe, but destination execution must be configurable and guarded to avoid
accidental publish actions or provider lock-in.

## Decision

1. Introduce a configurable publish-target contract with deterministic schema
   validation and ordered execution semantics.
2. Support built-in target taxonomy (`npm`, `choco`, `brew`, `git`, `docker`,
   `cloud`) plus generic `custom` and first-class `ssh` targets.
3. Add default confirmation publish mode (`confirm`) so operator approval is
   required before target execution.
4. Require env-reference-only handling for sensitive values; no inline secret
   literals in committed config.
5. Keep mandatory `/release` gate chain unchanged; publish targets are a
   post-release optional layer.

## Consequences

- Repositories can adapt publish behavior without changing framework code.
- A clear confirmation boundary reduces accidental irreversible publishes.
- Additional schema validation and regression coverage are required to preserve
  deterministic and safe behavior across target types.
