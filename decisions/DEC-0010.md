# DEC-0010: Traceability Index Location

## Status: Accepted

## Context

US-0025 requires "at least one maintained artifact provides a project-wide
cross-reference index spanning all active/completed sprints" (AC-2). The index
must map story ID → sprint ID → task IDs → status/evidence so that any
OPEN/DONE story can be traced to its execution artifacts.

The question is where this index should live.

## Options

### Option A: New dedicated file (`docs/engineering/traceability.md`)

A standalone cross-reference index file.

- Pros: clean separation, unlimited growth room.
- Cons: one more file to create and maintain, another artifact for the curator
  to manage, no natural "home" in existing workflow.

### Option B: Section in `docs/engineering/state.md`

Add a "Traceability Index" table section to the existing state file.

- Pros: `state.md` is already the project-wide status artifact. The curator
  already maintains it via `/refresh-context`. No new file. Natural fit for
  "where is everything in this project."
- Cons: `state.md` grows slightly. For very large projects with dozens of
  sprints, the table could become long (mitigated by curator compaction and
  the fact that completed/archived sprints can be summarized).

### Option C: Table appended to `docs/product/backlog.md`

Add sprint-mapping columns directly to the backlog.

- Pros: stories and their execution live together.
- Cons: backlog is a PO artifact focused on story definition and priority, not
  execution tracking. Mixing concerns. Backlog is already 250+ lines.

## Decision

**Option B is accepted.** The traceability index lives as a dedicated section
in `docs/engineering/state.md`.

### Index format

```markdown
## Traceability Index

| Story | Sprint | Tasks | Status | Evidence |
|-------|--------|-------|--------|----------|
| US-0018 | S0001 | T-001..T-011 | DONE | S0001/uat.json, S0001/summary.md |
| US-0020 | S0002 | T-001..T-002 | DONE | S0002/summary.md |
```

### Maintenance rules

- **`/sprint-plan`** (Tech Lead): creates new rows when assigning stories to a
  sprint. Status = `PLANNED`. Evidence = empty.
- **`/verify-work`** (QA): updates status to `PASS` or `FAIL` and fills
  evidence column with artifact references.
- **`/refresh-context`** (Curator): compacts completed entries and ensures
  index stays current with actual sprint artifacts.
- **Pre-handoff check**: any role running `/verify-work` or `/release` should
  confirm no story lacks a traceability entry (AC-3, AC-5).

## Consequences

- No new file introduced — the index piggybacks on the existing state artifact.
- `/sprint-plan` and `/verify-work` gain a lightweight step (add/update a table
  row) rather than a heavy new artifact workflow.
- For very large projects, the curator can archive completed-sprint rows into a
  collapsed section to keep state.md compact.
