# DEC-0059: Documentation audience/depth profiles and dual README developer shard (US-0077)

- **Date**: 2026-03-28
- **Status**: Accepted
- **Story**: `US-0077`
- **Research refs**: `R-0054`
- **Related**: **`DEC-0055`** (merged scratchpad inputs for profile flags), **`US-0030`**
  (README/runbook/template parity), **`US-0031`** / **`US-0032`** (optional modes —
  orthogonal), **`US-0071`** (user-visible string hygiene), **`US-0038`** / reason-code
  discipline (deterministic failures)

## Context

**`R-0054`** defines a **9-cell** matrix (`DOC_AUDIENCE_PROFILE` × `DOC_DETAIL_LEVEL`),
semantic section keys, artifact ownership sketch, H2 budgets, and a tiered validation
strategy. Execute phase must lock **literal paths**, **heading text**, **default/migration
rules**, and **validator placement** so generation and CI stay deterministic.

## Decision

### 1. Profile semantics (scratchpad)

- **`DOC_AUDIENCE_PROFILE`**: `user` \| `developer` \| `both` (required for validator
  participation once story ships; until then execute phase may treat absence as default
  per §6).
- **`DOC_DETAIL_LEVEL`**: `concise` \| `balanced` \| `technical-deep` (same rule).
- **Invalid enum** → **`DOC_PROFILE_INVALID`** with allowed-value remediation (**`US-0077`**
  **AC-1**).
- **Merge/parse failure** when reading profile inputs → **`DOC_PROFILE_MERGE_ERROR`**;
  no doc mutation (**`R-0054`** gate 3).

### 2. Artifact ownership (non-overlapping intents)

| Surface | Owns | Notes |
|--------|------|--------|
| Root **`README.md`** | All **`USER_*`** semantic keys required for the resolved cell when audience is **`user`** or **`both`** | Operator/user how-to entry |
| **`docs/developer/README.md`** | All **`DEV_*`** semantic keys required for the resolved cell when audience is **`developer`** or **`both`** | Developer shard; **new** path introduced by this story |
| **`docs/engineering/runbook.md`** | Command keys (**`US-0030`**) | Profile may add **cross-links** from README only; runbook body not profile-templated |
| **`docs/user-guides/US-xxxx.md`** | **`US-0032`** when `USER_GUIDE_MODE=1` | Profile adjusts depth/examples pointers, not file existence when mode off |
| Spec-pack outputs | **`US-0031`** when `SPEC_PACK_MODE=1` | Profile does not redefine spec-pack semantics |

### 3. README split strategy

- **Single vs split**: **Dual-file** is canonical — root README = user channel; developer
  channel = **`docs/developer/README.md`**.
- **`both` × `concise`**: **Split enforced** — user keys in root README, developer keys in
  developer shard (**`R-0054`**).
- **`both` × `balanced`**: **Split required** (README H2 budget otherwise exceeded).
- **`both` × `technical-deep`**: **Split required**; root README keeps **user** keys only
  (≤ **6** H2s per **`R-0054`** budget); **no** inlined **`DEV_*`** bodies in root beyond
  short pointers to the developer shard.
- **`developer` × \***: **`DEV_*`** keys live **only** in **`docs/developer/README.md`**;
  root README contains at most a **single** short pointer H2 (e.g. “For contributors”)
  linking to the shard — pointer is not a substitute for missing shard sections.
- **Alternative considered**: labeled regions in one README — **rejected** for
  `both`×`balanced`/`technical-deep` due to bloat and **`US-0071`** scan ambiguity; may be
  used only for **`user`**-only cells if execute phase needs a transitional fixture (not
  default layout).

### 4. Semantic key → H2 literal mapping (validator normative)

Architecture **`docs/engineering/architecture.md`** (**`# US-0077`**) lists the canonical
H2 titles. Validator resolves **semantic key → one or more H2 headings** (exact match after
strip); missing mapping for a required key → **`DOC_SECTION_MISSING:<key>`**.

### 5. Section budgets

Soft caps for **H2 count in root `README.md` body** (user keys + non-body pointers only)
match **`R-0054`** table; exceed → **`DOC_SECTION_BUDGET_EXCEEDED`** unless a future DEC
documents an explicit waiver (**execute** may add manifest allowlist later — out of scope
for this decision).

### 6. Migration and defaults

- **Template/example scratchpad** ships explicit **`DOC_AUDIENCE_PROFILE`** and
  **`DOC_DETAIL_LEVEL`** (framework default recommendation: **`both`** + **`balanced`**).
- **Merged scratchpad** (**`DEC-0055`**) with **both keys absent** during transition:
  treat as **`both`** × **`balanced`** for resolver/tests **only** until **`US-0077`**
  execute marks keys mandatory in CI — document cutover in sprint/release notes.
- **Non-destructive upgrade**: existing single-README repos add **`docs/developer/README.md`**
  when adopting **`developer`** or **`both`**; no automatic deletion of legacy sections
  (generator may relocate content in a separate guided step).
- **Active + `template/`** parity: same paths and headings (**`US-0030`**, **`AC-7`**);
  mismatch → **`DOC_TEMPLATE_PARITY_FAIL`**.

### 7. Validator and test strategy

- **Validator implementation**: canonical entrypoint **`scripts/validate_doc_profile.py`**
  (execute phase) — reads **merged** scratchpad via **`installer.py`** merge helpers (same
  pattern as **`DEC-0058`** — no duplicate precedence).
- **Invocation**: **`tests/run-tests.ps1`** / **`tests/run-tests.sh`** call the validator
  against fixture trees (not production free-form glob in first increment unless sprint
  scopes it).
- **Tiered regression** (**`R-0054`**, **`AC-8`**):
  - **Tier A**: snapshot fixtures for `user×concise`, `developer×balanced`,
    `both×technical-deep` (split layout).
  - **Tier B**: table-driven fixtures for remaining six cells (resolver-only).
  - **Tier C**: wiring smoke — one path per `DOC_AUDIENCE_PROFILE` at **`balanced`**
    depth for enum/merge wiring.

### 8. User-visible outputs

- **`US-0071`**: all generator/validator stdout and user-facing markdown bodies on scanned
  surfaces remain free of forbidden planning-token patterns; extend allowlists only for
  tooling diagnostics if needed (**execute**).

## Alternatives (not chosen)

- **Monolithic README with labeled regions for all cells** — lower file count but fails
  **`both`×`technical-deep`** bloat and complicates **`US-0030`** parity checks.
- **Profile stored outside scratchpad** (e.g. only CI env) — duplicates source of truth and
  breaks **`DEC-0055`** alignment with local overrides.

## Risks

- **Drift** between semantic keys and headings if editors rename H2s without updating the
  resolver table — mitigated by CI validator and template parity.
- **New path** `docs/developer/README.md` — must be added to installer/template sync lists
  if framework owns it (**execute** verifies against **`docs/engineering/context/installer-owned-paths.manifest`**).
- **Optional modes** — incorrect ordering of checks could block repos with modes off;
  validators must gate **`US-0031`/`US-0032`** artifacts only when respective flags are **1**
  (**`R-0054`** §6).
