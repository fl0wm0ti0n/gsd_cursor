# DEC-0041: Intake Capability Fail-Fast and Single-Writer Drift Safety

- Date: 2026-03-14
- Status: Accepted
- Related story: US-0059
- Research refs: R-0035

## Context

An intake run in a fresh repository reported two unsafe behaviors:
- role-specific `po` subagent capability was unavailable and execution silently
  degraded to in-band behavior,
- the run then detected its own writes as mid-run external drift and blocked.

This created ambiguity and operator confusion for first-run intake reliability.

## Decision

1. Require `/intake` capability preflight for role-specific `po` subagent before
   any mutation.
2. If capability is unavailable, fail fast with deterministic reason code
   `SUBAGENT_CAPABILITY_UNAVAILABLE`.
3. Default fallback policy is deny (`INTAKE_SUBAGENT_FALLBACK=deny`); allow
   fallback only with explicit opt-in (`INTAKE_SUBAGENT_FALLBACK=allow`).
4. Add deterministic single-writer identity per intake run:
   - `writer_id`
   - `intake_run_id`
5. Drift detection must treat same-writer/same-run changes as valid self-writes.
6. Conflicting external mutation during active run must fail safe with
   `INTAKE_CONCURRENT_WRITER_DETECTED` and no partial overwrite.

## Consequences

- Operators get deterministic diagnostics instead of silent degradation.
- Intake drift guards stop blocking on self-write false positives.
- Existing ordering and canonical ownership contracts remain preserved.
- Active/template parity and regression coverage are mandatory to prevent
  behavior drift.
