## Pattern identified

**Cross-story byte-stability contract — when a new story touches a README (or any shared artifact) section that a prior story already released, use net-new keys + cross-link pointers; never edit the prior story's released block.**

This generalizes US-0113's AC-5 parity lockstep (one-way copy + `fc /b`) from a within-story pattern (its_magic/README.md ↔ template/its_magic/README.md) to the cross-story case (US-0113's released `### Sovereign-loop era keys` block ↔ US-0114's new `### Release & distribution keys` block). The contract has three parts:

1. **Net-new content only**: the new story's section adds only keys/content that did not exist in the prior story's released block (US-0062's `PROJECT_README_ENFORCE` / `FRAMEWORK_KIT_REPO`).
2. **Cross-link pointers for overlap**: for keys/content that already appear in the prior story's released block (US-0111's `RELEASE_TRIGGER_*`, US-0112's `DELIVERY_MODE` / `TOKEN_PROFILE` / `ID_NAMESPACE_BOOTSTRAP` / `MODEL_TIER`), the new story's section adds a cross-link pointer ("see US-0113 `### Sovereign-loop era keys` for the sovereign-loop angle on these keys") rather than re-documenting the key.
3. **No edits to the prior story's released block**: the prior story's released section remains byte-stable; git diff on the shared artifact should show only additions from the new story, not modifications to the prior story's lines.

This contract preserves the byte-stability guarantee that released content remains reproducible — a downstream consumer reading US-0113's block sees the same bytes regardless of US-0114's release, and a consumer reading US-0114's block gets the new angle without redundancy.
