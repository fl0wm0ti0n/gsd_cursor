# US-0108: Parallel Instance Arbitrage

## Overview

Parallel instance arbitration enables spawning N independent dev instances in isolated git worktrees, running parallel execute→QA flows, and deterministically selecting a winner based on QA verdict and anti-slop score.

**Default:** `SOVEREIGN_PARALLEL_DEV=0` (off, sequential path)

## When to Enable

Enable parallel dev when:
- Multiple independent implementation approaches exist
- You want parallel exploration before selecting the best result
- You need redundancy against instance failures
- Anti-slop quality filtering is required

**Do NOT enable** when:
- Single sequential path is sufficient
- Resource constraints (memory, disk, CPU) are tight
- Story scope is simple or well-defined

## Enablement

Add to `.cursor/scratchpad.local.md`:

```markdown
SOVEREIGN_PARALLEL_DEV=1
AUTO_SOVEREIGN_PARALLEL_N=3
AUTO_SOVEREIGN_PARALLEL_MAX_TOTAL=6
```

Scratchpad keys:
- `SOVEREIGN_PARALLEL_DEV` (0|1, default 0) — global enable
- `AUTO_SOVEREIGN_PARALLEL_N` (int, default 3) — instances per execute cycle
- `AUTO_SOVEREIGN_PARALLEL_MAX_TOTAL` (int, default 6) — system-wide cap
- `AUTO_SOVEREIGN_MERGE_RESOLVE` (enum, default `first_pass_wins`) — merge strategy
- `AUTO_SOVEREIGN_WORKTREE_KEEP` (0|1, default 0) — retain loser worktrees for debugging
- `AUTO_SOVEREIGN_PARALLEL_ANTI_SLOP_THRESHOLD` (int 0-10, default 6) — anti-slop floor
- `AUTO_SOVEREIGN_PARALLEL_QA_ARBITER` (enum, default `critic_first_pass`) — QA selection strategy

## Parallel Workflow

### Phase 1: Spawn Worktrees

`/execute` step 25 spawns N worktrees:
- `.git/worktrees/us0108-<story_id>-<instance_idx>/`
- Branch: `us0108-<story_id>-<instance_idx>`
- Each worktree has isolated GIT_DIR + GIT_WORK_TREE env
- Deterministic naming prevents collisions

### Phase 2: Parallel Execute+QA

Steps 26-27: each worktree runs independent `/execute` → `/qa`:
- Dev agents work in isolated worktrees
- QA agents run in fresh subagent contexts (US-0048 isolation)
- Anti-slop scores computed per instance

### Phase 3: Selection

Step 28: `select_winner(qa_results[])`:
1. Filter `qa_verdict=pass`
2. Sort `anti_slop_score` descending
3. Tie-break: earliest `proof_issued_at`
4. Return winner or `None`

**Selection predicate guarantees:**
- Deterministic: same inputs → same winner
- Anti-slop quality: winner meets aggregate threshold
- Fail-closed: no winner → `PARALLEL_DEV_SELECTION_NO_PASS`

### Phase 4: Merge

Merge policy:
- Default: `first_pass_wins` (merge winner's branch to main)
- Conflict retry: ≤2 attempts with `-X theirs` strategy option
- After 2 failures: `PARALLEL_DEV_MERGE_CONFLICT` halt
- Write-once artifact: `handoffs/parallel_dev_pick.json`

### Phase 5: Cleanup

Post-merge cleanup:
- Winner: branch promoted, worktree removed
- Losers: worktrees removed (unless `AUTO_SOVEREIGN_WORKTREE_KEEP=1`)
- Lockfile released
- If cleanup fails: `PARALLEL_DEV_WORKTREE_CLEANUP_FAILED` (fail-open)

## Resource Guard

**Lockfile:** `.git/us0108_parallel_dev.lock`
- Atomic create via `pathlib.Path.open('x')`
- Contains JSON with active slot IDs
- System-wide cap: `AUTO_SOVEREIGN_PARALLEL_MAX_TOTAL` (default 6)

**Acquire:**
```python
ok, msg = acquire_parallel_slot(slot_id, repo_root, max_total=6)
if not ok:
    # PARALLEL_DEV_RESOURCE_CAP_EXHAUSTED
```

**Release:**
```python
release_parallel_slot(slot_id, repo_root)
```

**Fail-fast:** `PARALLEL_DEV_RESOURCE_CAP_EXHAUSTED` when cap reached

## Integration Points

**Execute steps 25-28** (AC-6):
- Step 25: `spawn_parallel_worktrees(story_id, n)`
- Step 26: `/execute` per worktree (parallel instances)
- Step 27: `/qa` per worktree (parallel instances)
- Step 28: `select_winner()`, `merge_winner()`, `cleanup_worktrees()`

**After US-0047 step 22** (bulk execute guard):
- Parallel path executes after bulk orchestration
- Resource caps are independent (parallel ≠ bulk)

**Before US-0092 step 25** (full autonomy outer driver):
- Parallel dev is internal to execute phase
- Outer driver sees single merged result

## Backwards Compatibility

**Zero overhead when off** (AC-7):
- `SOVEREIGN_PARALLEL_DEV=0` (default):
  - No worktree creation
  - No parallel QA
  - No pick JSON
  - No resource guard
  - US-0047/US-0092 semantics unchanged

**No behavior change** when key absent:
- Scratches without `SOVEREIGN_PARALLEL_DEV` = sequential path
- Existing workflows unaffected

## Example: Parallel Sprint Execution

```markdown
# .cursor/scratchpad.local.md
SOVEREIGN_PARALLEL_DEV=1
AUTO_SOVEREIGN_PARALLEL_N=3
AUTO_SOVEREIGN_PARALLEL_ANTI_SLOP_THRESHOLD=7
```

**Flow:**
1. `/sprint-plan` → creates sprint with 3 tasks
2. `/execute` → spawns 3 worktrees
3. Each worktree: `/execute` (dev) → `/qa` (QA)
4. Anti-slop scores: [8, 9, 7]
5. Winner: instance 2 (score 9)
6. Merge: instance 2 branch → main
7. Cleanup: remove all 3 worktrees
8. Output: `handoffs/parallel_dev_pick.json`

**Pick JSON:**
```json
{
  "story": "US-0108",
  "winner_instance_id": "us0108-US-0108-1",
  "worktree_path": ".git/worktrees/us0108-US-0108-1",
  "qa_verdict": "pass",
  "anti_slop_score": 9,
  "proof_issued_at": "2026-06-29T22:50:00Z",
  "merge_policy": "first_pass_wins",
  "merge_commit_hash": "abc123...",
  "loser_instance_ids": ["us0108-US-0108-0", "us0108-US-0108-2"]
}
```

## Resources Removed

**Always cleaned up:**
- Winner worktree (after merge)
- Loser worktrees (unless `AUTO_SOVEREIGN_WORKTREE_KEEP=1`)
- Lockfile `.git/us0108_parallel_dev.lock`

**Optional retention (debugging):**
- Loser worktrees when `AUTO_SOVEREIGN_WORKTREE_KEEP=1`
- Manual cleanup: `git worktree remove <path>`

## Troubleshooting

**"All instances failed QA"**
- Check anti-slop threshold (lower if too strict)
- Verify each instance has valid `proof_issued_at`
- Check QA logs in `sprints/<sprint_id>/qa_findings.md`

**"Merge conflict after 2 retries"**
- Inspect conflict files manually
- Consider `AUTO_SOVEREIGN_MERGE_RESOLVE=theirs_ours_mixed`
- Verify base branch is up-to-date

**"Resource cap exhausted"**
- Reduce `AUTO_SOVEREIGN_PARALLEL_MAX_TOTAL`
- Release stale locks: `rm .git/us0108_parallel_dev.lock`
- Check for orphaned worktrees: `git worktree list`

**"Worktree cleanup failed"**
- Manual cleanup: `git worktree remove --force <path>`
- Check git version (worktree support requires git 2.5+)
- Verify no process holds lock on worktree
